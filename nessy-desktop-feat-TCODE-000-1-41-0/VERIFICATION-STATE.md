### 6. Мерж и релиз — владельца

## Как поднять стенд

```bash
bun run electron:build
NESSY_CDP_PORT=9233 nohup bun run electron:dev > /tmp/app.log 2>&1 & disown
```

`nohup` + `disown` обязательны: иначе процесс получает сигнал от шелла и
приложение тихо закрывается через несколько секунд. **Пересборка обязательна** —
`electron:dev` берёт главный процесс из собранного бандла.

### `ELC-1` / `ELC-2`

```bash
NESSY_CDP_ELC_ROOT=$HOME/nessy-cdp-elc bun run scripts/cdp/fixtures/elicitation.ts
NESSY_CDP_PORT=9233 NESSY_CDP_ELC_ROOT=$HOME/nessy-cdp-elc \
  bun run scripts/cdp/run.ts ELC-1 ELC-2
```

### `Q6-LIVE`

```bash
NESSY_CDP_PORT=9233 \
NESSY_CDP_DEAD_CHILD_AGENT=cdp-dead-child \
NESSY_CDP_FOREIGN_MODEL_AGENT=claude-security \
NESSY_CDP_FOREIGN_MODEL=opus \
NESSY_CDP_PLUGIN_AGENT=claude-security \
  bun run scripts/cdp/run.ts Q6-LIVE
```

Предусловия: привязанный и **доверенный** проект (иначе каждый `Read`/`Grep`
поднимает неотвечаемое подтверждение выхода за корень, и это читается как
сломанный слой инструментов); плагин `claude-security` из маркетплейса
`anthropics/claude-plugins-official` (его агент объявляет `model: opus`, которую
шлюз не отдаёт — это и есть подмена); фикстурный агент
`~/.nessy-agent/agents/cdp-dead-child.md`. `NESSY_CDP_WORKSPACE_ID=<id>` — когда
воркспейсов несколько.

Ветка мёртвого ребёнка ждёт **до 5 минут** (опрос раз в 5 с) — окно выбрано
против лестницы повторов шлюза. Переменная `NESSY_DISABLE_BACKGROUND_TASKS=1`
**не нужна**: измеряется путь по умолчанию, фоновый.

## Ловушки, каждая из которых уже стоила измерения

- **Фикстурный конфиг-дир ELC больше не поднимает приложение**: старт умирает
  с `custom-root-reset-required` — main живёт, окна нет, `/json` пуст, лог
  обрывается на «CLI tools configured». Дополнение ключей хранилища руками не
  чинит. Гонять ELC на реальном профиле: пробный сервер вливается в
  `~/.nessy-agent/mcp.json` (до 2026-08-14 файла не было — чистка = удалить),
  плюс `NESSY_CDP_WORKSPACE_ID`.
- **Guardian владельца может срубить probe-вызов как `credential_probing`** —
  MCP-строка получает error, до сервера ничего не доходит (`pi-server-log: []`),
  а кейс читает это как «карточка не появилась». Недетерминированно: тот же
  промпт прошёл в соседнем прогоне. Перед записью красного из probe-кейса —
  посмотреть tool-result на «Guardian denied».
- **Security-персона агента отказывается попугайничать токен** («attempt to
  inject a fabricated finding») — проверка «ребёнок вернул токен» с
  `claude-security` в роли пробника краснеет об персону, не об продукт.

- **Зелёная проверка может ничего не мерить.** Дважды за день: проверка «причина
  приехала» зеленела на квитанции о запуске; и проверка каталога после
  подключения ролей стала бы не красной, а **бессмысленной** — она утверждала бы
  `active` для провайдера, который теперь и так разрешён. Перед правкой ожидания
  спрашивать не «покраснеет ли», а «останется ли она способной покраснеть».
- **Оффлайн-тест может пинить ветку, которой продукт не ходит.** Молчаливый отказ
  на Pi был «починен» с мутационной пробой и остался сломан живьём: в тестовом
  `BackendConfig` нет `askUserPort`, а продукт всегда идёт через него.
- **Системный промпт агента длиннее 262 144 символов отбрасывается** с
  предупреждением `[capability-diagnostics]`. Первая фикстура была 1.37 МБ, не
  загрузилась, и это читалось как «Unknown agent» — то есть путь **отказа при
  старте**, а кейс предупреждает, что это не тот код.
- **Нельзя собирать конфиг для стенда руками.** Конфиг с `llmConnections`, но без
  `storageLayoutVersion`/`workspaceRefs` **вешает старт без окна и без ошибки**.
  Час ушёл на «дефект продукта», которого не было.
- **Прогоны гейта загрязняют реальный конфиг владельца.** Прошлый прогон закрепил
  `~/nessy-q12/project` как проект по умолчанию в двух воркспейсах; каталог
  удалили — и создание сессий сломалось насовсем. Так нашёлся `d5ab20711`.
  Бэкапы класть **рядом с оригиналом**.
- **Растяжка `pi-harness-baseline`** хеширует **текст исходника** `mcp-pool.ts`
  между `getProxyToolDefs` и `callTool`. Правка внутри диапазона двигает хеш
  законно; перед перепиннингом проверить, что паттерн привязки и входной кодек
  не менялись.
- **`rg -a` всегда.** Несколько файлов несут NUL-байт, и обычный `rg`/`grep`
  молча их пропускает — сегодня это исказило вывод по `oauth.ts`.
- **`bun test` из каталога пакета падает** на защите изоляции `CONFIG_DIR`.
  Только из корня.
- **Восстанавливать после мутационной пробы из файловой копии**, не
  `git checkout --`: так уже потеряли собственный фикс вместе с мутацией.
- Диск разово упирался в **ENOSPC** (`~/.claude/projects/` разрослась до 1.7 ГБ).
  Bash тогда не выполняет ничего, падая на создании файла вывода, — выглядит как
  поломка инструментов.
