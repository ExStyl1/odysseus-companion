# Nessy Desktop 1.39.0

September 17, 2026

The second and third phases of the Developer Platform sign-in plan, plus the MCP work that
sat behind them. The sign-in ladder now finds the `dp` tool the same way on every machine
and never replaces your own `dp` session with a private one; a chat that hits a gateway
credential failure re-mints once and re-sends the message by itself; and the app now says,
under the model list, when your MCP tool schemas are being sent to an external model
vendor. Underneath, an MCP server started by the app no longer leaves helper processes
behind when the app closes it, and a chain of test-isolation holes that let suites read a
developer's real credentials is closed.

## NEW

- **The `dp` tool is resolved by one ladder on every machine.** `NESSY_DP` if you set it,
  then the system `dp`, then Nessy's own managed copy, then the copy nessy-cli keeps in
  `~/.nessy/dp_latest` — first runnable wins, and an outdated copy is skipped while a
  newer one is available. Your `~/.dp` session is shared on every rung: Nessy never
  replaces it with an isolated workdir, so signing in once in the terminal signs Nessy in
  too. All three `dp` invocations (login, print-token, version) run with the same home
  and the same workdir.
- **A gateway credential failure heals itself in one round trip.** When a turn fails on
  the corporate gateway with an expired or missing token, Nessy re-mints the token once
  and re-sends your message; only if that fails does the sign-in card appear, carrying
  the reason and one `dp auth login` button. The card also disposes the failed session
  before it shows, so a stale process cannot answer a message you re-send.
- **The sign-in card names the environment variable you actually set.** If nessy-cli's
  `NESSY_CLI_DP_AUTH_TOKEN` is exported while Nessy's own variable is not, a "dp not
  found", "sign in needed" or "login failed" failure says so instead of "dp token
  rejected" — the three failures that variable would have avoided; every other failure
  keeps its own reason, and the variable's presence alone changes nothing else.
- **The app says when an external model receives your MCP tool schemas.** A mark on the
  connection rows and one line under the model list name the host that will receive the
  session's tool definitions when the target is an external vendor. Nothing is withheld —
  the line is the disclosure the policy asks for, and it is computed per session rather
  than emitted once per process.
- **The model picker says when the gateway catalogue was last refreshed.** A gateway
  card now carries the moment its model list was last read from the live catalogue,
  separately from the enrolment marker a BYO endpoint uses.
- **`nessy-general-agent doctor` reports the gateway credential's state.** Reason codes,
  lengths and booleans only — whether the stored credential decodes, whether it has
  expired and by how many minutes, and which re-mint reason a session would meet — never
  the token itself. The section is a reading and does not move the exit code.
- **A new `lint:chain` step keeps the sign-in-codes table honest.** The gate parses the
  `DpAuthError` members out of the source and asserts one row per member in both locale
  copies of the documentation table, so a new failure code cannot ship undocumented.
- **MCP connection isolation gains a per-transport spelling.** `NESSY_MCP_CONNECTION_ISOLATION=by-transport`
  shares stdio and websocket connections and isolates http and sse per session. The
  default stays `shared` — see KNOWN.

## IMPROVED

- **The credentials store honours `NESSY_HOME` in every reader, and the documentation says
  so.** One `### NESSY_HOME` section on the environment-variables page (absolute values
  only; relative or `~` values are ignored), a cross-link from the credentials remedy, and
  the sign-in codes table's `NeedsLogin` row now names the one case where the chat does
  not keep working. A `### NESSY_DP` section documents the `dp` lookup ladder in order,
  and the "dp not found" row names the four places that were searched.
- **The app says when your MCP tool schemas go to an external model, on a reference page
  of its own.** The new "External models and MCP tools" page carries the owner-approved
  scope statement verbatim, in both locales.
- **A stored credential that cannot be decoded is no longer treated as a usable one.**
  The warm path of the sign-in facade re-mints instead of handing the gateway a value it
  will refuse.
- **The four copies of "is this a gateway-backed connection" are one.** The renderer, the
  main process, the session manager and the model fetchers all read the same exported
  predicate, which is deliberately strict: a connection with no base URL is not the
  gateway. A BYO endpoint that merely lives on the gateway host no longer spends the
  shared corporate token on the gateway's catalogue, no longer has the gateway's model
  list written over its own, and no longer receives the corporate token on its requests.
- **The gateway preset stops prefilling a live token into a visible text field.** The
  one-click card is the only door; the field stays blank.
- **The renderer's gateway URL is derived, not hand-written.** The onboarding step's
  read-only endpoint field shows the "gateway host, not the gateway URL" notice when it
  applies.
- **The auth-retry classifier is credential-shaped, not status-shaped.** A `403` counts as
  a credential failure only when the text names the token; the llm-proxy guardrail's
  refusal, which carries the word "auth", no longer trips it. A "credentials not found"
  failure on the gateway now reaches the retry and the card instead of dying as a raw
  error row.
- **A startup sweep clears a credential the gateway card must not hold.** One site, both
  hosts, a count logged and nothing else.
- **The headless daemon's authentication posture is written down, item by item,** in the
  server's own module docblock, with the absences named and their controls.
- **The loopback MCP pool server's bearer, and the Origin/Host decision, are documented**
  where the server is defined, including why the SDK's own DNS-rebinding option cannot
  simply be enabled on the transport this server uses.
- **Pool connection keys differ on every credential-bearing field** (headers, bearer env
  var, stdio env and envVars), pinned by a table test.

## FIXED

- **A BYO endpoint under the gateway's chat base is no longer offered the gateway quota
  command, nor told it spends the Nessy Gateway budget.** The quota gate now reads the
  same whole-URL rule the credential side uses on all three runtimes.
- **The gateway credential-gate error names the file it actually read.** With
  `NESSY_HOME` set, the "credentials not found" and "token is expired" sentences name
  that directory instead of `~/.nessy`.
- **An MCP server started over stdio no longer leaves its helper processes behind.** The
  app now spawns such servers in their own process group and signals the group on
  teardown, after the child's `exit` rather than after its pipes close — a wrapper that
  forked a descendant used to keep the app waiting for the whole grace period and then
  leave the descendant running. On Windows the app delegates to the SDK's own transport
  and the sweep is graceful only.
- **Three model-fetcher suites and the adapter's expiry-gate suite could read a
  developer's real credentials.** They faked `HOME` but never cleared `NESSY_HOME`, which
  outranks it; the repo-wide test preload now deletes every relocation name that is read
  live from the environment.
- **A commit's quoted pass count hid a red** in a dp credentials test; the arm read a
  fixture from a directory the setup recreates. Fixed with the next row.
- **The doctor's gateway section reported a missing credential on a machine with no
  gateway card** and moved the exit code; it now prints a reading and moves nothing. A
  record with no numeric expiry read as healthy while the store refused it on every turn;
  it now reads `credentials_unreadable`.
- **The loopback stub used by the BYO sitting sent the wrong argument name to Codex's
  shell tool**, so the Codex arm died inside Codex and looked like the credential failure
  the stub exists to remove. It now reads the tool's own schema.
- **A CDP case could take a checklist id another row already claimed;** the harness now
  refuses it.
- **Nine Codex agent suites stubbed a credential reader the agent no longer imports and
  left the one it does import un-stubbed.** Both are stubbed now.

## KNOWN

- **`NESSY_MCP_CONNECTION_ISOLATION=per-leaser` and `=by-transport` select a posture that
  does not work end to end.** An isolated connection is created under its own key and is
  then unreachable through tool calls, elicitations, resource reads and the sign-in
  bookkeeping (measured on a real Streamable HTTP server: 10/0 shared, 2/8 per-leaser).
  The default `shared` is unaffected; do not set either spelling until the tracked fix
  lands.
- **The lazy managed-`dp` provisioner (the ladder's download rung) is not built.** The
  upstream publishes an MD5 only, so the pinned digest must be computed at release time;
  the ladder already reserves the rung.
- **On a BYO Claude connection the child process can read the name `ANTHROPIC_API_KEY`
  but not the key;** on Pi and Codex neither is reachable. The direct `anthropic` card
  takes a different path and was not measured this release.
- **The external-model disclosure line is shown only in the compact (narrow-window)
  model picker.** In a desktop-width window the connection row carries the badge and the
  sentence naming the host appears only as the badge's hover text; the line under the
  model list, and the "this list comes from …" provenance line, are not rendered there.
  Measured on the packaged build (RS-44).
- **The quota pointer on the Claude Code and Codex gateway cards is unreachable.** The
  command palette offers no quota row on those two cards by design, and a typed `/quota`
  is sent as an ordinary message, so the sentence naming the Nessy Gateway budget is never
  printed. The Pi gateway card's quota row works (RS-39).
- **The app's `networkProxy` setting does not reach the `dp` tool.** A proxy configured in
  the setting is not applied to the `dp` re-mint; a proxy in the environment is. Measured
  on the packaged build under a refusing proxy (RS-43).
