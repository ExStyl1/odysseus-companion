# Nessy Desktop 1.20.0

August 7, 2026

## NEW

- Skills can run shell commands in their instructions. A `!`-prefixed command in a skill's body now executes and its output is substituted before the model reads it — including on the forked-subagent route, where these placeholders never ran at all.
- Plugins show when an update is available, and you can update one from its page. Updating tells you to refresh the plugin runtime, because a session that is already running keeps using the previous version's hooks and servers until you do.
- `/loop` self-paced scheduling, the `/clear`, `/btw` and `/recap` session commands, and a per-session web-search budget with a notice when you reach it.
- Two more output styles, Proactive and Learning, and output styles can now live in a project directory.
- Per-agent memory directories, and two instruction-file locations that were previously ignored: the working directory's `.claude/CLAUDE.md` and the system-wide tier.
- Scheduled tasks catch up after a missed run, and each can run in its own worktree.

## IMPROVED

- Skill precedence follows the documented order: a skill below your working directory is offered as `/dir:skill`, a project skill outranks a bundled one, and a skill outranks a command of the same name — as one row, not two.
- Custom slash commands support positional arguments (`$1`, `$2`). An argument you never supplied now behaves as documented: an indexed placeholder stays as written, a named one expands to nothing.
- Subagent nesting is capped at 3 by default with an override, subagent concurrency has a ceiling, and oversized output from a child spills to disk instead of filling the turn.
- MCP servers gained the roots capability and channel notifications, with stricter rules for what a server config may declare and what environment it is started with.
- Memory files are capped at 25 KB, the cap now applies on the path the app actually uses, and a write reports what it measured.
- Worktrees are created from an up-to-date default branch and cleaned up after removal.
- Hook payloads carry the documented fields under their documented names, and every documented hook event is covered.
- A `Setup` hook is now refused with an explanation instead of being accepted and never running. Use `SessionStart` for per-session initialization.

## FIXED

- **Two hooks on the same event no longer erase each other's output.** This was happening: two hooks that each returned a worktree path produced no path at all, and an MCP prompt accepted with values lost both the acceptance and the values, so the dialog opened anyway.
- A hook can now name the session and ask for a skills reload, and both actually happen. A name set that way — or by you — is no longer overwritten by the automatically generated title.
- A skill's shell command could never match an `allowed-tools: Bash(gh *)` rule, because backticks reached the shell as command substitution. They are stripped before execution now.
- The home directory no longer receives a stored trust grant.
- Deep links no longer perform an action without a step from you.
- Informational messages from the Claude runtime are no longer dropped, and warnings survive a reload instead of vanishing.
- Completing a goal clears it and records it as achieved.
- Proxy bypass lists parse correctly, and the gateway's own requests are hardened against redirects.
