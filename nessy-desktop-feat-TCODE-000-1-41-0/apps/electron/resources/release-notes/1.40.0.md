# Nessy Desktop 1.40.0

September 18, 2026

The first four waves of the integrations-and-authorization work, plus the tail of the
Developer Platform sign-in plan. The slash commands the docs promised now exist on every
runtime (`/tasks`, `/workflows`, `/workflows stop`), the background-task panel lists this
chat's scheduled work and watches, an expired credential reaches you as one card with one
sign-in button whichever runtime you are on, a model that answers from outside the
corporate boundary now loses the MCP servers policy withholds instead of only telling you
about them, a plugin can live for a single chat, and the Pi agent panel is no longer dark
after the first turn — which is what 1.39.0 shipped with. Three known issues published
with 1.39.0 are closed here, and the release also carries the readings from six live
sittings on the packaged 1.39.0 and 1.40.0 builds — the last of which found, and this
release fixes, a Stop that stopped nothing when a message was queued behind it and a side
question (`/btw`) that opened as a panel you could not type into.

## NEW

- **`/tasks` and `/workflows` are real commands.** `/tasks` answers with this chat's
  background-task list and leaves the answer in the transcript; `/workflows` shows the
  workflow progress view and `/workflows stop` stops every background agent of the chat.
  Both are recognised by the app rather than by the model, so they behave the same on Pi,
  Claude Code and Codex — until now both reached the model as ordinary prose.
- **Scheduled work and watches in the background-task panel.** One request carries this
  chat's scheduled automations and its monitor watches, and the panel lists them beside
  the work already running. Beside work that is already on screen, a chat with nothing
  else queued now says so — and "nothing is scheduled", "it could not be read" and "we
  have not asked yet" stay three different answers rather than one blank space.
- **One sign-in button for an expired credential, on every runtime.** A subscription or
  BYO credential that expires now reaches you as the same card the corporate credential
  already raises — one reason, one button — instead of a settings hint on Claude Code and
  a transcript line on Pi. The button opens Settings → AI with the connection that failed
  already open, because a settings link can now name a connection.
- **A model outside the corporate boundary loses your MCP servers, not just your
  trust.** When the chat's model answers from a vendor — a BYO endpoint, a vendor
  namespace such as `anthropic/…`, or any model id this app cannot place — the session
  keeps only a short allowed list of corporate servers and loses every other one,
  including your own, your project's and your plugins'. The model picker says what is
  held back beside what is sent, and the documentation page says exactly which servers
  survive and why.
- **A plugin can live for one chat.** A plugin from a local directory or a URL archive
  can be attached to a single session instead of installed for the workspace; it is
  released when the session is deleted and at shutdown, so a plugin you wanted to try
  once no longer has to be uninstalled afterwards.
- **Claude Code honours and announces an administrator's restricted mode**, a host
  `hooks.json` SessionStart / SessionEnd hook now runs on Claude Code too, a SessionStart
  hook's `systemMessage` reaches you and its `additionalContext` reaches the model on
  Claude Code and Pi, and a resumed session's `context_tokens` rides SessionStart on all
  three runtimes.
- **The Claude runtime's own postures reach a surface you can open.** The chat's Memory
  menu now carries a *Runtime notes* section: whether the runtime keeps notes of its own
  for this chat and where they are written, whether an administrator's restricted mode is
  in force, that deny-rule filtering of search results is done by the app itself, and
  that the runtime may enter a git worktree without the recorded working directory
  changing. The settings-tiers notice says when automatic memory was forced on or off.
- **The per-server MCP tool timeout you configure reaches the Claude SDK's own
  per-server setting**, one second looser than the app's own abort so that the app's
  message is the one you see.
- **The model picker's provenance label is per entry, in both pickers.** A model the
  gateway catalogue does not list is marked as such rather than guessed at from the list
  it sits in.
- **`run --url` attaches to a server that is already running** instead of spawning one,
  and refuses the four flags it could not honour against a server it did not start
  (`--safe-mode`, `--fallback-model`, `--settings` and `--setting-sources`), naming the
  environment variable that would work instead.
- **An administrator can refuse the one sideload flag this product ships.** The documented
  managed key `disableSideloadFlags` now rejects `--agents` at startup, naming the flag and
  the key.
- **A WebSocket upgrade that does not name the headless server is refused.** On a loopback
  bind the server accepts only its own authority in the `Host` header — the standard
  defence against a web page in your browser being pointed at it — and
  `NESSY_RPC_ALLOWED_UPGRADE_HOSTS` is the escape for a reverse proxy that forwards a
  public name. A deployment that serves the web UI seeds that list from its own address.
- **The session and the doctor say which credential authorized them.** A Claude session
  can report the credential source the runtime itself reports, said out loud when it
  disagrees with the connection's own, and `nessy-general-agent doctor` now answers which
  `dp` binary is actually running of the four places it looks.
- **Codex: the managed application egress destinations are disclosed by value** rather
  than by field name, codex's `in_app_local_automation` reaches both halves of the
  automations, and the one model switch this app makes on its own now fires the
  model-switch hook.
- **The reasoning effort you pick is remembered per model.** Choose a level once for a
  model and the next chat on that model starts there, on Pi, Claude Code and Codex
  alike; a gateway model that publishes its own reasoning effort starts at that level
  when you have neither picked one for it nor set an app-wide default (previously that
  default came from a registry that has never held a gateway model id).
- **Seven new checks joined the repository's lint chain** (measured against 1.39.0's
  `package.json`), among them fixed-size source-text windows in tests, stray writes to the
  headless server's handshake stream, workspace-dependency shadowing and a native-binary
  install check that a dependency bump can silently drop.

- **Bypass permissions is in the mode picker and the Shift+Tab rotation.** The mode was
  reachable only through a configuration file; it is offered by default now, and the first
  activation on an install still asks you to confirm what it means.
- **Read-before-write reaches Claude Code and Codex.** An existing file the session has not
  read is refused with the same sentence Pi already used; on Codex the runtime raises the
  approval instead. One host ledger serves all three runtimes.
- Codex's approval posture reaches the operator queue once per configuration write, and the
  notice now says what the permission profile bounds — the workspace, `$TMPDIR`, `/tmp` and
  the operator's added roots, with an out-of-workspace change asking — instead of claiming
  there is no sandbox at all.
- The session read now carries the runtime's own advertised tools, commands, skills and
  agents, so a diagnostic can be taken against what the child actually offers.
- The `coder` model is marked as supporting thinking, per the gateway catalogue; `fast` is
  not, because the catalogue says nothing about it and a silence is not a measurement.
## IMPROVED

- An endpoint-less BYO connection is now fail-closed with one measured exception, and the
  model picker sees the same verdict the backend does instead of under-disclosing.
- `CONNECTION_IN_USE` names the chats and tasks that hold a connection, in your own
  language, end to end through the wire and the desktop bridge.
- The connection row's description wraps rather than truncating.
- A retired session model is no longer shown as the live one; a stale default is not
  rewritten when a catalogue fetch fails, and one bounded re-fetch follows a transient
  failure.
- A session command's answer stays beside the question that asked it, and the retry chip
  clears on any content, not on text alone.
- Compaction on Pi retries under the same ladder as an ordinary turn and narrates its
  retries; a compaction that failed once no longer ends the summary.
- A housekeeping task the runtime does not consider your work stops announcing itself in
  the transcript as if it were, and the orchestration panel says which child a turn is
  waiting on, whether it is backgrounded, and how deeply it is nested.
- Codex operator diagnostics are classified: the user-facing ones are translated, the
  configuration-file ones stay English by design. A safety judge that cleared a command
  says so on the card that asks anyway, and a worktree the runtime refuses now says
  something to you beside the runtime's own line.
- The headless server's own log reaches the operator on stderr and never on the stream the
  CLI reads its token from, a second stop waits for the first instead of racing it, and a
  headless run whose server dies mid-turn names the cause promptly.

- Codex's own command classification rides the host's tool frame, so a command the runtime
  classified is reported the way the host reports every other one.
- Every host-raised permission card — a hook, a watch, a worktree, a cross-session ask, an
  archive, a skill's `!` line, the composer's `!` — now counts toward the chat's
  awaiting-approval badge, so the badge stops disagreeing with the screen.
- **What's new shows every version, not the ten most recent.** The panel listed only the ten newest release notes, so a user on 1.31.0 could read back to 1.22 and no further; every bundled note now loads, newest first.
## FIXED

- **Stop now stops the turn even when a message is queued behind it.** Queuing a follow-up
  made the app believe the turn had ended: the Stop button turned back into a send button,
  Esc-Esc stopped working and the host was never asked to interrupt anything. And a Stop
  the app could not deliver is now reported to you instead of being dropped in silence.
- **A side question (`/btw`) opens with a composer you can type into.** It used to open as
  a small read-only panel, so the feature could be started and not used. Three things that
  came with it are fixed too: the panel greeted you with *"What would you like to change?"*,
  copy written for the edit popover, and now says what a side question is; a `/btw` typed
  inside the panel was swallowed in silence and is now simply the next question; and opening
  the panel no longer logs a failed lookup for a chat the app itself invented. And the panel
  now opens in the same compact card as the agent-driven add popover, with its own
  placeholder — it used to be a wider box with a title bar and a key-hint footer, and its
  input advertised the sidebar shortcut. Two more, found by the owner the same day: a side
  question on a chat that had not run a turn yet came back as an error (first as the token
  `agent-not-started`, then — after that was fixed — still as an error, because the chat's
  agent was started and immediately lost the permissions it had just been given, one step
  before the question was asked); it is now answered, and when a side question does fail
  the panel says why in a sentence in your own language instead of an internal code, with
  the provider's own message beside it; and the panel is now a thread — every question and answer stays in it in
  order, newest at the bottom, like an ordinary chat, where earlier questions used to pile
  up as a dimmed list at the top of the card.
- **Turning memory off now also stops Codex sessions from saving memories.** The app-wide
  switch never reached the Codex session tools — a privacy control that had quietly stopped
  controlling. Codex sessions can also save to your user memory index again; the request
  used to fail with an internal message about a missing path while the same request worked
  on the other two runtimes.
- **The project-trust prompt for a folder that has been moved or deleted no longer traps
  you.** The dialog closes and says what happened, nothing is trusted, and the next project
  you open in the same chat is asked about again.
- **A sign-in whose browser you cannot see now says what to do.** Instead of waiting five
  minutes and timing out silently, the card names the loopback address the sign-in has to
  reach on this machine and the port-forward that makes it reachable.
- A `UserPromptSubmit` command hook that needed a permission card no longer wedges the turn
  forever: the wait is bounded by the hook's own budget and says what stopped it. A command
  hook from your own configuration, or from a project you have trusted, runs without a
  card; a plugin's hook still asks.
- The `/hooks` run history records what a host-dispatched command hook did — the field had
  one producer and the production merge dropped it, so that half of the history was blank.
- `dontAsk` permission mode can be entered again: the composer's picker wrote `default`
  back over it.
- Pressing Stop now records what it asked the Claude runtime for — the capability read and
  the runtime's own interrupt receipt go to this chat's diagnostic file in debug mode, so a
  Stop that behaved oddly can be read off a packaged build instead of guessed at.
- A background record that was running when the app was closed is reported again after a
  restart, a record whose process is provably gone no longer pins the chat busy, and a
  just-recorded row survives a cold save.
- The settings-provenance view no longer publishes a Claude settings file the child never
  opens, and the gateway's cached-token accounting reaches the Claude Code and Codex cards.
- **One Always Allow on a `git push` no longer opens the door to every git command.**
  Approving a dangerous two-word command (`git push`, `git reset`, `git rebase`,
  `git checkout`, `sudo …`) used to store a rule for its first word — the harmless
  `git status` had written that same rule — and after one such approval both the ask
  and the auto permission mode ran `git push` and `git reset --hard` without asking, and
  the sandbox exemption ran them outside the sandbox. The stored rule and the session
  grant now name the two-word command, and the whole command line is tested against the
  dangerous list on every runtime.
- **Always Allow on a file write or an API call now does what it says.** The session grant
  a file-write or API-mutation card stored was written under a key no check ever looked up,
  so the next identical write or call asked again; the grant is now stored the way the check
  reads it — that one path for a file write, the method and path for an API call — while a
  runtime's own broad session rule keeps its meaning.
- **"Yes, don't ask again" no longer approves whatever is chained onto the command you
  approved.** Once you had allowed `npm test`, the app also ran `npm test && curl … -o
  /tmp/file`, `npm test && git push origin main` and `npm test ; rm -rf ./build` with no
  card at all — in Default, Accept Edits and Auto alike — although each of those second
  commands always asks on its own. A remembered approval now covers only the command you
  were shown; anything joined onto it with `&&`, `||`, `;`, a pipe or a newline is asked
  about again. One cost that comes with it: a pipeline such as `npm test | tee out.txt` now
  asks unless you have allowed `tee` as well.
- **A command written with its full path, or with a variable in front of it, is no longer
  treated as a different command.** `/bin/rm -rf …`, `/usr/bin/sudo …`, `/usr/bin/git push`
  and `NODE_ENV=production rm -rf …` all slipped past the list of commands this app never
  remembers, so one "Yes, don't ask again" on such a line both stopped asking for the rest
  of the session and wrote a permanent rule for that repository — where the same command
  spelled plainly is refused both. They are now recognised however they are written.
- **"Yes, don't ask again" on a `bash -c "…"` command no longer hands over the shell.** The
  app remembered it as plain `bash` and wrote a permanent `bash` rule for the repository,
  which then matched `bash -c` with any script at all. Shell and wrapper commands (`bash`,
  `sh`, `zsh`, `env`, `xargs`, `eval` and their kin) can still be allowed once; they are
  simply never remembered, because the app cannot honestly say what it would be remembering.
- **A remembered command is now saved as the command you saw, not as its first word.**
  Approving `npm test` used to write a permanent rule covering every `npm` subcommand —
  `npm publish` and `npm install <anything>` included — while the same click inside the
  session remembered only `npm test`. The two now agree: `npm test` saves `npm test`,
  `docker compose up -d` saves `docker compose up`. Rules saved by earlier versions are left
  exactly as they are, so if you have used "Yes, don't ask again" before, it is worth
  looking at `.claude/settings.local.json` in those repositories.
- **A removal typed inside a `fish` shell command is caught again.** The protection that
  refuses to delete your home directory or the root of the disk could read `bash -c …`,
  `zsh -lc …` and `sh -c …` but not `fish -c …`, so on a machine whose login shell is fish it
  could be walked past — and Codex runs every one of its commands through your login shell,
  so that was every Codex command there.
- **A Codex deployment that turns off local automations really turns them off.** An
  administrator's `in_app_local_automation = false` requirement was reported as honoured
  while this app's scheduled automations kept running — the policy arrived after the
  schedulers had started and nothing listened for it. They now stop, including ones
  already running when the policy lands, and the log says why.
- **Approving a message held for another chat now delivers it.** Approvals were reported
  back to the sending chat as declines, and a request that timed out was reported as a
  decline as well instead of as an expiry.
- **The Pi runtime snapshot a live chat produces was rejected by its own parser after the
  first turn.** That is what left the agent panel dark on the packaged 1.39.0 and made
  every child-listing view report no children.
- A Pi `PostToolUse` block reason wrote an unfenced hook band into the tool result the
  model reads. It is fenced again.
- Two messages arriving close together built two Pi sessions for one chat.
- A rule such as `allow: Bash(npm test*)` approved arbitrary input typed into a running
  Codex terminal with no card at all; the rule check now reads what kind of approval it is
  being asked about.
- Three runtime error codes (`oauth_org_not_allowed`, `model_not_found`, `overloaded`) and
  a suspended account stopped being reported as network trouble.
- The expired-subscription error code existed on the wire and nothing produced it.
- **A dialog you were still reading counted as a failure.** An answer that took longer
  than 30 seconds — a file picker, a delete confirmation — was discarded by a timeout
  nobody had accounted for, and `sessions:command` was reported as failed while it
  succeeded.
- One failed hardware-identity read at a busy launch keyed the credential store to a
  fallback identity and made a perfectly good store unopenable. The answer is now
  remembered and retried once.
- The folder-trust prompt no longer asks about a folder with nothing to trust, and the
  report it previews now covers the whole `.nessy-agent` tier rather than part of it.
- `PreCompact`'s `custom_instructions` is `null` on both triggers, as the runtime's own
  page says.
- A batch unit that was created but not started is named in the reply, and a session
  plugin's staging directory left behind by a crash is swept at the next start.
- The telemetry disclosure stopped saying your account is exported when only the session
  id is — corrected in all five places that sentence is produced, the operator doctor
  included.
- **The app's network-proxy setting, and its extra CA with it, now reach the `dp`
  sign-in** (a 1.39.0 known issue: a proxy set in the app was not applied to the `dp`
  re-mint, only a proxy set in the environment was).
- **The disclosure, provenance and translated-wire lines now render in the desktop-width
  model picker too** (a 1.39.0 known issue: only the narrow picker showed them).
- **Both isolating spellings of `NESSY_MCP_CONNECTION_ISOLATION` work end to end** (a
  1.39.0 known issue): an isolated MCP connection was created under its own key and was
  then unreachable by every surface that routes by tool name. One dropped argument, in the
  pool itself.
- A stopped child agent's card no longer reads "Running" forever after you interrupt the
  parent.
- The packaged app stops pointing at a command-line tool it does not ship, its
  documentation path points where the documentation actually ships, the connection
  handler's log lines reach the packaged log at all, the exact gateway URL is refused when
  a connection is saved rather than only in a form that is not rendered, and that refusal
  reaches you as a sentence instead of an error token.
- The headless platform logger no longer writes INFO and DEBUG lines onto the handshake
  stream the CLI reads the server token from.

- **Switching the model in the middle of a chat now re-applies the external-model MCP rules
  straight away.** Servers that are withheld from an external model are no longer left
  attached to it after a switch, and switching back to an in-perimeter model gives them back
  without starting a new chat. Before this fix the decision was taken once, when the chat
  started, and a later model change never revisited it.

- **An automation the assistant created in your workspace could run a shell command without
  asking you first.** Commands from automations stored in a workspace now raise the usual
  approval card; hooks you wrote in your own settings file are unchanged.
- **The assistant could create or edit an automation that runs in Bypass permissions mode,
  which you were never asked to approve.** Automations the assistant creates are now limited
  to Accept edits or narrower; you can still set any mode yourself on the Automations page.

- **"Remember from this chat" is a switch again.** Turning memory off for one chat now stops
  the model writing memories from it on Pi, Claude Code and Codex. Until now the setting was
  recorded, shown as off in the chat menu and survived a restart while memories kept being
  written. On Pi and Claude Code the change applies immediately, mid-chat; on Codex it also
  closes Codex's own memory for that thread, and a change made after the chat has already
  started reaches its memory tool when the runtime next starts.

- **The assistant could change this workspace's automation file through a notebook edit, a
  multi-file edit or a background command** — three routes that skipped the refusal it already
  gets for an ordinary edit. All of them now get the same refusal, which points at the
  automation tools; automations you create yourself are unaffected.

- **The assistant could rewrite this workspace's permission rules directly,** which would have
  widened what it is allowed to do without ever asking you. It now gets a refusal that points
  it back to you; your own changes in Settings › Permissions are unaffected.

- **"Always Allow" on a Claude session no longer saves a permanent rule for the whole
  repository.** The approval card on a Claude connection says it remembers the command for
  this session, and it now does exactly that. Before, the app also wrote the command into the
  repository's `.claude/settings.local.json` — which did not stop Claude asking you again, but
  did mean a later Pi chat in the same project ran that command with no approval card at all.
  Pi and Codex are unchanged: there the card says repository, the rule is saved, and it is
  what stops the next prompt.

## KNOWN

- **In Manual mode a never-granted read-only command still runs without asking.** The
  read-only allowlist is what the mode trusts, on every runtime; an edit still asks.
  Asking about every single command is what Plan mode is for. This is the documented
  posture, not a defect (D1.263).
- The quota pointer on the Claude Code and Codex gateway cards was measured unreachable on
  the packaged 1.39.0. The dispatch itself is proven to work, so the cause is somewhere
  before it and the case now carries the positive control that will say where (DA2.26).
- The rewind menu offers **Rewind and restore files** the first time you open it in a chat
  and not the second: the button is shown while the answer about tracked changes is still
  being fetched. Pressing it in that first moment does nothing (D1.378).
- `/hooks` says this session publishes no hook listing and that no hook has run, while
  hooks are loaded and running normally — the listing, not the hooks, is what is missing
  (D1.386).
- Adding a plugin marketplace registry reports success even when the catalogue behind it
  cannot be fetched from your machine; the listing simply stays as it was, with nothing
  said about why (D1.387).
- A subagent definition's `maxTurns` does not bound a Pi child — it costs extra turns, not
  correctness (D1.389).
- Windows and Linux rows stay parked until those release channels reopen.
