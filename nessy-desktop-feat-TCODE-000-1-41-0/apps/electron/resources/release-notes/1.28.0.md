# Nessy Desktop 1.28.0

August 16, 2026

## NEW

- **Tools from your connected sources are now fetched on demand instead of being described upfront.** Every tool a source offers used to be spelled out in full at the start of every single message — on one measured setup that was about 20 000 tokens of tool descriptions before you had typed anything. The agent now receives a searchable index and pulls in the full description of a tool at the moment it decides to use one. **Nothing becomes unavailable**: every tool is still reachable, and one that is needed arrives before it is called. This was already possible behind an environment variable; it is now simply how the app works.

- **This applies even if you have no sources connected at all.** The mechanism now switches on for every profile rather than only for setups with enough connected tools to be worth it, so the saving is not reserved for heavy configurations.

## IMPROVED

- **A source you have pinned still arrives upfront, and that promise is unchanged** — pinning is how you say "this one must always be present", and it still means exactly that. One detail is worth stating plainly because it changed: pinning every tool of a source no longer switches the whole on-demand mechanism off. If you want it fully off, that is its own setting, not a side effect of pinning enough things.

- **Groundwork for fetching the app's own built-in tools on demand too.** The internal name-handling this will require is now checked by tests rather than being true by coincidence. This changes nothing you can see today — the feature it prepares for is not shipped — but it means the assumption cannot quietly break underneath it later.

## FIXED

- **A broken table in an internal document could hide most of its contents.** A single blank line in the wrong place ends a table in Markdown, so every row after it rendered as loose text. This was found in a document where it was hiding fifteen of seventeen rows, and the check written for it immediately found a second document with the same problem that nobody had reported. Both are fixed and the format is now verified automatically.

- **A test that stopped testing instead of failing.** One internal check was written so that if its subject ever moved, it would quietly skip rather than report a problem — a silent all-clear. It now fails loudly, which is the only useful behaviour for a check.

## KNOWN OPEN

- **Fetching the app's own built-in tools on demand is not shipped.** The work is written and set aside: it is held up by a test that counts sessions in a way that an extra internal reload disturbs, and that reload is long-standing behaviour rather than anything new. It is parked deliberately, with the diagnosis recorded, rather than rushed.

- **Codex support for on-demand tools is still being investigated.** We have confirmed that the setting exists and that we are able to write it. Whether the Codex version we ship actually acts on it has not yet been tested, and until it has, nothing is claimed either way.
