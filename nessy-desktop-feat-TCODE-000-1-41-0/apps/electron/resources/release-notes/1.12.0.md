# Nessy Desktop 1.12.0

July 20, 2026

## NEW

- One shared MCP connection per workspace. An MCP server used by several chats now runs as a single process and a single connection — no matter how many conversations use it — spawned lazily the first time something needs it and kept alive afterwards. Previously every chat spun up its own copy of every enabled server, so two chats with the same database server meant two database processes.

## IMPROVED

- Each chat still sees only its own tools. The connection layer is shared, but the view is not: a chat's tool list contains only the servers it has enabled, another chat's servers never leak into it, and a chat can never call a tool it hasn't enabled — the shared pool refuses the call outright.
- Tool responses stay with their chat. Large and binary MCP tool responses are saved into the session that made the call and summarized with that session's own settings, even when many sessions share one server connection.
- Closing a chat is now polite to its neighbors. Ending or deleting a conversation releases only that chat's claim on the shared pool; a server still used by another chat — or by the Sources browser — keeps running untouched. Only a server nobody wants anymore is shut down.

## FIXED

- Disposing a chat that used the Claude or Nessy Cloud backend could tear down the workspace's entire MCP pool, killing server connections that other chats and the Sources tab were still using and leaving the Sources tab showing no tools until an unrelated refresh. Session teardown now releases only the session's own lease.
