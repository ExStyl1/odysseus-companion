# Nessy Desktop 1.30.1

August 20, 2026

## IMPROVED

- **A banner now names an outdated dp as the reason your built-in servers won't connect.** When Nessy's built-in dp-backed MCP servers (Jira, GitLab, Sage, Wiki, and the rest of `dp ai mcp`) fail to connect and an out-of-date dp is why, the failed-servers notice now says so and points you at updating dp — instead of listing every failed server with no explanation of the actual cause.

## FIXED

- **Signing in to the Nessy Gateway now recovers on its own from a broken saved token.** A `~/.nessy/dp_auth_creds.json` holding something that is not actually a JWT — left behind by an interrupted login, a foreign edit, or a different tool sharing the file — used to be sent to the gateway as if it were valid, which produced an endless "token is malformed" 401 loop with no way out short of finding and deleting the file by hand. Every place that reads that file now checks the token is genuinely JWT-shaped first; anything else now reads as signed out, and you get the sign-in flow instead of the loop.

- **A rejected gateway token is no longer retried as-is.** After a 401 from the Nessy Gateway, the app used to retry with the exact same cached token, which fails again for the same reason and simply repeats. It now asks dp to mint a fresh one first, on the Claude, Pi, and Codex gateway connections alike. Clicking Sign in on a gateway card does the same — it always fetches a new token rather than replaying whatever was cached.

- **Already signed in through nessy-cli? The desktop now picks that up automatically.** Before minting a new session of its own, the desktop looks for a valid token in nessy-cli's own credentials file and signs you in with it — read-only, nothing in that file is changed — instead of sending you through dp's browser login again.

- **Signing in no longer fails just because dp printed an update notice.** `dp auth print-token` and `dp auth login` now run with dp's own warnings suppressed, and the desktop no longer treats routine stderr output as a failed command.

- **The error card on the Claude Code (Nessy Gateway) connection now points at Sign in, not an API key you don't have.** A 401 on that connection used to suggest fixing an API key, which does not apply to a one-click gateway sign-in — it now names Sign in in Settings → AI instead.
