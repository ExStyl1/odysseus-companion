# Nessy Desktop 1.21.2

August 8, 2026

## FIXED

- A stalled provider now fails in minutes instead of leaving the session on "Responding…". A hard-stalled upstream used to be retried ten times with growing pauses, so a turn could sit unsettled for a quarter of an hour before you were told anything had gone wrong. Sessions you are watching now give up sooner and show the error. Unattended runs are unaffected: if you set `CLAUDE_CODE_RETRY_WATCHDOG` to wait out long outages, that still wins, and an explicit `CLAUDE_CODE_MAX_RETRIES` of your own is never overridden.
- An MCP server whose token was revoked or expired now offers you sign-in instead of looking broken. Until now the only thing that could ask you to sign in was an empty credential slot, so a credential the provider rejected left the server sitting there as a failure with no way to fix it.
- Being genuinely broken and needing sign-in are told apart. A server error, a missing endpoint or a dropped connection stays reported as a broken server rather than sending you to a sign-in screen that would not help.
- A server that connects and then rejects the first request is no longer reported as an unexplained failure — that rejection now reaches the app with its cause intact.
