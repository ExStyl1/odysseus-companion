# Nessy Desktop 1.32.0

August 22, 2026

## NEW

- **The Nessy Cloud agent now speaks the gateway's current protocol.** The remote code agent moved from the legacy A2A 0.3 endpoint to A2A 1.0 on `/api/v2/code-agent/a2a` — the wire the backend actually develops against: the streaming and cancel methods, the message and part shapes, the task states, and the agent card are all read the way the server writes them today, and an unfamiliar stream frame is now logged and skipped instead of failing the turn. One consequence is intended and worth knowing: a conversation that was running against the old endpoint starts a fresh cloud context on its next prompt, because the old conversation handle is not a valid handle on the new one. Your local transcript is untouched.

- **Skills now work on the Nessy Cloud agent.** The session's skills are advertised to the remote agent, and it can activate one by name mid-turn — the skill's instructions and its resource paths are delivered as written (author restrictions such as disallowed tools are shown to the remote agent rather than enforced on it), and a skill you marked as not model-invocable stays off limits.

- **`/quota` tells you how much of your daily budget is left.** Run it in a Nessy Cloud session to see each limit the gateway applies: what remains as a percentage, the gateway's own message about the limit's state, and when it resets — read from the server rather than guessed from your own usage. The command appears in the slash menu only on connections that have a quota to report.

## IMPROVED

- **Hitting the daily token limit no longer ends the turn.** A rate-limited request now waits and retries with a growing delay — up to ten times, from five seconds out to a minute — and re-sends exactly what it sent before, so nothing is lost or duplicated. When the retries genuinely run out, the message you see is the gateway's own text about your limit, not a generic failure.

- **A question from the remote agent now reaches you, and your reply answers it.** When the cloud agent asks a follow-up question or responds in Plan mode, the question is shown to you — with its suggested answers numbered — and the turn parks. Your next message is delivered as the answer to that exact question instead of starting a new one. Previously the question was answered by the model itself and you never saw it.

- **Large prompts are trimmed to fit the gateway's request limit instead of being rejected.** The request is now measured in bytes as it will actually be sent — Cyrillic and escaping included — and, when it is over the limit, the project instructions are shortened first, then the MCP tool schemas are emptied while every tool name is kept, then the skill list, stopping at the first step that fits.

- **Remote work and support triage are visible.** Tools the cloud agent runs on its own side now appear in the transcript as activity, with their results, and the gateway's request id is attached to error messages — so a report about a failed turn carries the one identifier the backend can trace.

## FIXED

- **The remote agent's tools now match what it actually sends — every search and every edit used to fail.** Project-wide search was executed as a literal-text search with the file filter dropped, so a regular expression from the agent matched nothing; in-place edits were sent in a format nothing on our side could read; and MCP tools were advertised under names the backend's reply could not be mapped back to. Search now runs as the regex it is, edits are applied from the agent's own SEARCH/REPLACE blocks through the normal permission and checkpoint path, and MCP tool names round-trip. The builtin tool schemas are pinned to a committed snapshot of the backend's own definitions, so a mismatch between our schemas and that snapshot is caught by a test rather than by a broken turn (the snapshot itself refreshes from a pinned backend checkout on developer machines).

- **`/clear` now clears the cloud conversation too.** It used to clear only the local transcript while the next prompt silently continued the same remote conversation. The remote context is now reset first — before session-end hooks run, so a failing hook cannot leave the old conversation attached.

- **A stale cloud task no longer bricks the session.** If the backend rejects a resumed task as already finished — or has lost it entirely — the request is retried once without the dead task handle instead of failing every prompt from then on, and the server's own explanation of the failure survives to the message you read.

- **Stopping a turn now actually stops the remote agent.** Cancel used to be sent on the connection that had just been aborted, so it never left the app and the cloud agent kept working; it now goes out on its own bounded request, and closing a session or restarting the runtime cancels the running task as well.

- **Text the agent had already written is no longer lost when a stream drops.** A connection that breaks mid-reply now delivers what had arrived before the break instead of discarding it.
