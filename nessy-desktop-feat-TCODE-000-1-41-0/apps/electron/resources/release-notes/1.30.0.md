# Nessy Desktop 1.30.0

August 17, 2026

## NEW

- **A Claude session now stays alive between your messages.** Until now the app started a fresh Claude process for every message you sent and it died with the answer — which is why nothing on that runtime could outlive a turn. One session now holds one process for its whole life. This is the shape Claude's own SDK calls its preferred one, and most of what follows is built on it.

- **Background tasks are finally visible, and stopping one actually stops it.** The list existed, the row existed, the menu existed — and none of it was ever put on screen, so a running background command or agent left no trace you could see or act on. The rows now sit in the composer beside your other session badges, they scroll rather than crowd the input, and the Stop in their menu reaches the task for real. A row disappears when something actually stopped; when a task cannot be stopped from there, you are told so instead of watching the row vanish and the work continue.

- **You can read a background task's output.** "View Output" on a background command opens the same output panel the app already uses for tool results. If the command is still running the header says so, so a command that has printed nothing yet no longer reads as one that produced nothing.

- **A correction typed mid-answer reaches the model on Codex.** You send a task, it starts working, you notice it is going the wrong way and type "stop, use the other API" — that message used to wait for the whole answer to finish. On Codex it now goes into the turn that is already running, through the runtime's own mechanism rather than an imitation of one. Turns that cannot take one (a review or a compaction) queue the message instead of dropping it.

- **Changing the model, the permission mode or your connected tools mid-conversation no longer restarts a Claude session.** The change is applied to the running session and takes effect on your next message. Your conversation was already kept across a model switch; what you no longer pay is the restart — a new process, the whole conversation replayed to it, and a cold cache. Switching between Claude models is live; leaving the Claude family, or moving to a model with a different thinking shape, still restarts, and so does turning on the permission bypass, because that one is decided when the process starts.

## IMPROVED

- **Stop now leaves a session that answers your next message.** It used to end the process outright. It now interrupts the turn, which is the difference between "that turn is cancelled" and "start over". If the session stops answering that request, the app still ends it after five seconds rather than leaving you with a chat that never replies.

- **An open chat you have not used in a while gives its process back.** Half an hour of no activity and the runtime is released; your next message starts it again with the conversation intact. Nothing is released while it is holding work — a running turn, a background task, a background command, a child agent, a permission card or a question waiting for your answer all keep it. A session that would go deaf if released, because it is listening for something, is never released on idle at all.

- **The app no longer takes a running session's work away to make room for a new one.** When too many sessions are open at once it used to shut down the least recently used one, which was harmless when nothing outlived a turn and is not any more. It now refuses to start the new one and tells you which sessions are still busy, rather than silently killing a background task, dropping a detached child agent's result or cancelling a permission card you were about to answer.

- **A message the app could not deliver mid-answer is sent, not lost.** When a correction cannot reach the turn in flight, it goes back into the queue and is sent as your next message. It used to be re-queued in a form that could not be replayed, so it was dropped with an error instead — after the composer had already shown it as delivered.

## FIXED

- **Stop on a Codex session now actually interrupts it.** It never did. The app was asking the Codex runtime to stop in a form that runtime does not accept — and in one of the two paths, in a form it does not even read — so every Stop you pressed on a Codex session was ignored while the app behaved as though it had worked. Measured directly against the shipped runtime rather than inferred.

- **Pressing Stop and then Enter no longer sends the same prompt twice.** After a Stop, the app puts your prompt back in the composer so you can adjust and resend — deliberately. But the button under your cursor turned back into a send button while the stop was still travelling, so a second press re-sent the prompt into the answer that was still winding down.

- **A finished background command no longer looks like it is still running.** Nothing removed a command's entry when it simply exited, so it stayed in the list and the session that started it could never release its process again — one command that ended an hour ago pinned it for the rest of the day. Entries are now retired when the record proves the command ended. Anything less than proof — still running, an unknown handle, an unreadable record — deliberately leaves the entry alone.

- **An MCP call or a workflow left running in the background can be stopped.** Neither could be before: the app was reaching for a mechanism that only knows about child agents, so an MCP task could not be stopped at all and a workflow had its current step killed while the rest of it carried on — and the app reported success.

- **Background tasks on Claude are no longer reported wrongly after the session restarts its process.** A task the app had told you started could silently disappear from its own bookkeeping, and a session that had never run one could announce "Background tasks finished." You are now told plainly when a restart lost a background task, instead of either.

- **A session running a Claude background task is no longer treated as idle.** It was invisible to everything that decides whether a session is busy, so after half an hour the app could release its runtime and take the running task with it, without a word. Claude's own Agent tool runs in the background by default, which made this easy to hit.

- **A Stop pressed between two turns no longer poisons the next one.** The next message came back marked as interrupted, with a stop banner on an answer nobody had stopped. The same wrong mark could also appear on a runtime that had not interrupted anything at all.

- **Bring-your-own Claude connections no longer fail every turn on an endpoint that has not implemented one optional Anthropic beta.** The app was forwarding a field that beta authorizes while dropping the header that declares it — a request no endpoint could correctly accept. The header now travels with the field, and an endpoint that refuses the field by name gets one retry without it, remembered for the rest of the session. Nothing is removed from your request until the endpoint has actually objected to it.

- **Streaming turns through the gateway no longer go out with a malformed header.** The proxy that separates a model's reasoning from its answer was copying the upstream's own transfer framing on top of the framing it adds itself, so every streaming turn carried the value twice — and once more for each additional hop. The Bun version the app ships tolerates it at one hop, which is why nothing looked broken; a second hop refuses the response outright and the turn produces nothing at all. Found because that second hop is exactly what one test sets up, and it failed only where the shipped Bun version runs.

- **One session can no longer read — or delete — another session's background output.** The lookup was keyed by task id alone and cleared the record as it read, so a session asking about an id belonging elsewhere both saw output it should not have and destroyed the only copy.

## KNOWN OPEN

- **Mid-answer corrections still wait on existing Codex connections.** The new behaviour is the default for connections you add from now on. A connection you already have keeps the setting stored when it was created, deliberately — the app cannot tell that stored value apart from one you chose yourself, and overwriting it would undo a real choice. Turn it on per connection in Settings → AI → Mid-stream sends → "Steer immediately".

- **Bring-your-own connections carrying Anthropic models may still be refused by the proxy's own security guardrail.** It answers with a policy error listing the app's own session tools. This release removes a different blocker on the same connections; the guardrail is untouched and is a platform-policy question rather than an app fix.

- **Claude background tasks do not yet appear in the Background Tasks list.** They are announced in the conversation instead. The app keeps such a session alive while its work runs, so nothing is lost — but the list does not show it.

- **A session opened from the inline edit popover shows no background-task row.** That surface renders the composer in its compact form, where the whole badge row is hidden.
