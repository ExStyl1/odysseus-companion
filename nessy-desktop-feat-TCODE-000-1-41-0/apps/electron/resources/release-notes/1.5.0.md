# Nessy Desktop 1.5.0

July 17, 2026

## NEW

- Plugin connectors now work end to end. A Codex or Claude bundle that declares a connector — an id, the MCP servers it exposes, and an optional sign-in policy — is no longer just imported and set aside. Enabling a connector-bearing plugin in a workspace materializes each declared server as a real MCP-backed source through the same source machinery you already use, and disabling it removes exactly those sources. An app declared by a plugin routes only to its connector's declared MCP servers, never anywhere else.
- Interactive sign-in for connectors. A connector that needs authentication signs in through the existing source OAuth flow — the same browser-based, server-side exchange Nessy already uses for any MCP source. Connector credentials live only in the server-owned credential store; a plugin bundle never carries or stores a secret of its own.

## IMPROVED

- Sign-in timing is honored as timing, not trust. A connector can ask to authenticate right after install or on first use; either way the choice only decides when Nessy offers the sign-in, never whether the connector is trusted. Declining a sign-in leaves no trace — the connector simply stays unauthenticated and unavailable.
- The source detail page now shows a connector's provenance: which plugin connector provided it and when it prompts for sign-in. This is presentation only — it never changes how a source is trusted, activated, or authenticated.
- Codex apps and connectors are reported as supported in the compatibility report instead of deferred, and a connector or app declaration whose entries are all malformed is surfaced as a dropped-declaration diagnostic rather than vanishing silently.

## FIXED

- Materializing a connector source no longer triggers an outbound request to the plugin-declared host before you consent. A connector source shows a neutral icon until you complete its interactive sign-in, so an untrusted plugin URL is never contacted just by enabling the connector.
