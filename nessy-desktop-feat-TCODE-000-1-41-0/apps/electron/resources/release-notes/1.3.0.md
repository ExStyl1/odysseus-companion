# Nessy Desktop 1.3.0

July 17, 2026

## NEW

- Unified plugin adapters. Nessy now installs Codex and Claude plugin bundles alongside its own native bundles and internal-marketplace items, all normalized to one lossless Nessy manifest and one runtime. A supported bundle needs no manual repackaging: skills, MCP servers (stdio/http/sse), command hooks, Markdown slash commands, and Markdown agents are recognized across every format.
- Format and source badges. Plugin, source, and skill surfaces show the package format (Nessy, Codex, or Claude) next to where it was acquired from (marketplace, repository, local, or URL), using the icons already in the app. The badge is display-only and never affects execution, trust, or permissions.
- Agent-driven plugin management. The assistant can plan an install, install it, report installed status, and enable/disable/update/repair/uninstall plugins through dedicated session tools — without ever running a shell command or handling credentials.
- Executable trust review. A new panel lists plugin command hooks and stdio MCP servers that need review, and lets you grant or revoke trust for the exact capability. Installing or enabling a plugin never auto-grants trust, and an update or changed bundle returns to review-required.

## IMPROVED

- One immutable, content-addressed plugin cache serves global, Workspace, and Project activation. A plugin is installed once; enabling it in one scope never copies its bundle, data, or credentials into another.
- Every plugin's declarations are imported losslessly. Components Nessy does not yet run — non-command Claude hook types, LSP, Codex apps and connectors, and peripheral Claude surfaces — are reported as deferred rather than silently dropped.
- Each format's compatibility is surfaced when you install: a fully supported package activates, a partial package installs but waits for your explicit confirmation, and a blocked package is refused with the reason shown.

## FIXED

- Plugin- and project-provided command hooks now run under the workspace process-isolation profile with the existing trust gate, instead of a bare inherited-environment spawn.
- Markdown slash commands from plugins are treated as prompt templates, never executed or hashed as shell commands; only the literal `$ARGUMENTS` token is substituted and the visible arguments are preserved.
- Runtime behavior no longer depends on a plugin's format or acquisition source; a normalized compatibility profile — not the origin — selects the environment a bundle sees, and an unrecognized profile fails closed.
