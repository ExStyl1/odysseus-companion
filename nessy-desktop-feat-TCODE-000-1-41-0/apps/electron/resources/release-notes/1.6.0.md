# Nessy Desktop 1.6.0

July 18, 2026

## NEW

- Agent memory now cleans up after itself. Notes the agent writes are tagged as agent-written and, on a daily background pass, quietly deduplicated and aged out past a threshold. Anything you wrote by hand is never touched — human notes are always left byte-for-byte as they are.
- Top-level subagents now run in the background by default. When the agent hands off a sizeable piece of work to a helper, that work runs as a task you can watch and steer, and its result arrives when it is ready instead of blocking the turn. Helpers spawned inside another helper still run inline as before.
- Subagents start with a workspace context seed. A stable summary of where they are working — the workspace root and project overview — is supplied up front, so a helper does not have to rediscover the basics before it can begin.
- Plugin language servers can now do more. Beyond definitions, references, hover, and symbols, a trusted plugin's language server can now format a document, format a selected range, and offer code actions, and it can stream diagnostics as they are published — all under the same trusted-project isolation as before.

## IMPROVED

- Enabling, updating, or disabling a plugin now pre-warms idle sessions. New tools and capabilities become available right away instead of waiting for the next turn, while a session that is mid-turn still defers the refresh so nothing in flight is disturbed.
- The subagent tool guidance is clearer about how background results arrive and how to retrieve them, so the agent picks the right hand-off shape more reliably.

## FIXED

- A hook that keeps denying the same tool no longer hangs a turn. After a few repeats the agent gets one final warning and then the turn stops with a visible diagnostic, instead of looping silently.
- The language-server client no longer leaves a server hanging when the server sends its own request; such requests are answered so the connection stays healthy.
- Streamed diagnostics are held in a bounded per-file buffer, so a chatty language server cannot flood memory.
