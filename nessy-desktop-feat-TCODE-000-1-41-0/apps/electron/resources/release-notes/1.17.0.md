# Nessy Desktop 1.17.0

August 1, 2026

## NEW

- **A built-in set of MCP servers, with no sign-in at all.** Every tool server the `dp` CLI provides — 28 of them — is now listed in **Sources → MCPs** alongside your own and your plugins'. They reuse the `dp` session you already have, so there is no OAuth, no token to paste and nothing to install. Every one ships switched off; you turn on what you want, one switch per server, and the choice persists. A machine without `dp` says so instead of offering a switch that cannot work.
- **Three more plugin marketplaces reachable from the app**: Anthropic's official catalogue (276 plugins), its community catalogue (2 307), and Anthropic's demo set — added the same way as any other registry, from **Plugins → Create → Add marketplace**. Installing by a direct URL works too.
- **A plugin's page says what it contains before you install it.** A listing that declares its components now shows which kinds it ships, and a plugin's own manifest is read on demand when you open its page — for both the Claude and the Codex format. Where neither says anything, the page says exactly that instead of claiming the plugin is empty: names and counts are only knowable after install, and it no longer pretends otherwise.
- **Filter the skills catalogue.** The marketplace's own filter vocabulary — tenants, tags and professions — now reaches the browse list, so 6 084 skills can be narrowed instead of scrolled.
- **A plugin's `bin/` executables are on the Bash tool's PATH** while the plugin is enabled, matching Claude Code, so a skill that shells out to its own bundled tool works. A plugin cannot shadow a system binary of the same name.

## IMPROVED

- **The internal marketplace installs what it lists.** It offered 118 extensions and could install 12 of them; it now installs **116**. The other two were never published. A listing that publishes no install command has its npm coordinates derived from the listing itself — never silently: the install source records that they were derived, and a diagnostic names the exact package.
- **An advertised version resolves to the build that exists.** The catalogue advertises `1.0.9` while the registry publishes `1.0.9-source.<timestamp>.<sha>`; that now resolves, by widening within the requested version and never across it. The rule that matched is recorded on the result.
- **Sign-in sits where the server is, and only there.** A server that needs authorising states it in its row — a marker beside its badge — and carries the Connect on its own page. A list item says, a detail page acts. The notice at the start of a chat is now a card in the conversation rather than a strip above every view, and a sign-in offered from the chat reaches the right server instead of failing.
- **The model can say what is missing.** A plugin MCP server that is declared but not signed in is now visible to the model mid-turn, and that plugin's skills are marked in the skills listing — so a skill that tells the model to call a Figma tool no longer produces a silent failure the user reads as "the plugin is broken".
- **Claude plugins import completely.** `hooks` and `mcpServers` declared as a path or written inline are read, not only the two default files — the shape Claude's own schema example uses. An imported agent keeps the description the model dispatches on, LSP servers keep their `env` and `workspaceFolder`, and a marketplace's `renames` map is honoured so an upstream rename does not orphan what you installed.
- **Codex plugins browse with names.** The official 180-plugin catalogue showed bare directory slugs with no description or version; each plugin's own manifest is now read. Prompt and agent hooks are parsed and skipped exactly as Codex does, `SessionEnd` hooks get Codex's own 3-second ceiling instead of Claude's 1.5, and a bundle whose listing metadata we cannot carry says so.
- **A failed marketplace refresh no longer empties the catalogue.** Refreshing kept serving the last good catalogue while it worked; a failed fetch is no longer cached as though it were an empty one; and an upgrade that did not happen reports the failure instead of a success toast.
- **One MCP failure stops taking the others down.** A server that cannot materialise is reported unavailable and the rest of the batch proceeds, and a reload keeps the live connection of a server nothing changed about.
- Marketplace installs are reported to the marketplace's own counter, a skill's install records the immutable snapshot it took, and a skill arrives in one digest-checked archive request instead of one request per file.

## FIXED

- **Installing a plugin no longer breaks every message in that workspace.** An un-authorised plugin MCP server reported "credential not ready" using the same code as a revoked capability snapshot, which killed the turn — and took down the sign-in notice that was the only way to authorise it. A not-ready credential now has its own code, and a credential the store has rotated past resolves instead of failing the turn.
- **The app would not start.** A renderer import of a package subpath missing from the exports map left the window blank; type-checking, the unit suites and the linter were all green, because none of them resolves the way the bundler does.
- **The startup screen could stay up forever.** Its only way off was the fade-out animation reporting that it had finished — and a window that is not being drawn, because it is hidden, minimized or still opening, never advances that animation by a single frame. The app was fully loaded underneath the whole time, just unreachable. It now leaves on a deadline as well.
- **The post-install checklist stayed silent about the one connector that most needed naming.** A connector whose catalogue asks for sign-in at install time was filtered out of the list on the assumption that its sign-in had already run. Nothing ever ran it. Both timings are now listed, and the sign-in is offered from the chat notice, the plugin page or the MCP list.
- **A built-in MCP server no longer appears twice** when you have configured a server of the same name yourself and given it a different display name. Only one of the two was ever going to start; now only one is listed.
- A downloaded artifact whose integrity digest this app cannot evaluate is refused rather than silently accepted, and `dist.shasum` is consulted when no stronger digest is published.
- A GitLab archive is fetched from the documented API route, so a sign-in page can no longer reach the archive extractor.
- An unsupported git host is refused when the entry is resolved, naming the host, instead of after a download attempt.
- A Claude bundle's `bin/` folder no longer costs the plugin its activation grants, and what a bundle genuinely cannot run is named.
- The open plugin's row is highlighted in the plugins list, the way every other Sources list already marked its selection.
- The install checklist stopped telling you a connector needs no sign-in when it does.
- The browse list no longer shows rows a user cannot tell apart, and its count describes the rows on screen.
