# Nessy Desktop 1.26.0

August 15, 2026

## NEW

- **Connecting your own key is now one form, and it asks you for a key and a runtime — not for a URL.** Setting up a personal key used to mean choosing between several look-alike cards ("API key", "Custom runtime endpoint" …) that differed in ways nothing on screen explained, and then typing an endpoint address by hand. There is now a single **Custom runtime endpoint** entrance. You pick which harness runs your key — **Pi agent**, **Claude Code** or **Codex** — and paste the key; the address is the internal LLM proxy and is filled in for you. If you already have a connection pointing somewhere else, it keeps working and its address is shown, read-only, so a re-save cannot silently move it.

- **The form shows you which models your key can actually reach, one at a time as it finds out.** Press **Fetch models** and the endpoint's published catalog appears immediately — hundreds of rows, searchable, grouped by provider family — and then every row is checked in the background and marked with what came back. A catalog is not an entitlement list: a shared proxy commonly publishes far more models than any single key can use, so the list is always labelled as what the endpoint *publishes*, and the marks are what answer the other question. Four things a row can say: your key reaches this model; it is published but your key has no quota for it; it does not answer on this protocol at all; or the check itself failed. Models your key cannot use are collapsed into one **Unavailable** group and cannot be picked by accident. The models you do pick appear as chips, and clicking a chip makes that model the default for new chats — the chip that sits first is the default, so what you see and what gets saved cannot drift apart.

- **Models that speak Anthropic's protocol now work on the Claude Code runtime, and are marked as such everywhere else.** Some models on the proxy answer only on Anthropic's own `/v1/messages` wire rather than the OpenAI-style one. Those models are now recognised, routed to the right wire per request, and shown on the Pi and Codex runtimes with the reason they are greyed out — *only available on the Claude Code runtime* — instead of appearing to be broken. Which wire a model speaks is **measured**, never guessed: if a model refuses the first protocol, the second one is actually asked before anything is claimed about it. One honest caveat: on the corporate proxy a Claude Code turn is currently refused by the proxy's own security guardrail, which rejects agentic tool names — that is a platform-side policy conversation, and it does not affect Pi or Codex connections to the same proxy.

- **Model details keep themselves up to date, without a switch to remember.** Once a day at startup, Nessy re-reads the context window and description for the models on a connection and updates them. Your selection is never touched: a model you chose is not removed because the catalog stopped listing it, and a model you did not choose is never added. This used to be an opt-in toggle in the form; it is not a decision worth handing you, so it now simply happens and the form says so.

- **An agent can now turn a source off, or remove it, instead of editing files behind your back.** Asked to disconnect something, an agent used to have no tool for it and could only rewrite configuration files by hand — which skipped the cleanup the Sources screen does and left traces behind. There is now a single tool with two actions: *disable*, which turns the source off but keeps its configuration and credentials so you can turn it back on; and *remove*, which does the same three things the Sources screen does — deletes the source, drops it from the workspace's default list, and revokes it from sessions already running. In Safe mode it is refused outright, and elsewhere it asks before it acts like any other tool that changes your setup.

- **The Guardian's second-opinion model can be chosen per integration.** Guardian asks a separate, cheaper model to judge whether a risky action should be allowed. That judge used to be one global setting, which does not survive contact with several connections: an id that exists on one provider is meaningless on another, and picking a wrong one quietly weakened the check. You can now choose the judge per integration, from that integration's own model list; a stale or unavailable choice falls back to a working model rather than failing, because a model restriction must never become a reduction in safety.

## IMPROVED

- **Context sizes and compaction are now correct on all three runtimes, which mostly means long conversations stop dying.** Three separate things were wrong and each is fixed. Claude Code sessions now tell the runtime how much context the model actually has, instead of letting it assume a size that had nothing to do with your model. Codex sessions do the same, and additionally get a point at which to compact — previously they had none, so a Codex conversation kept filling its window with nothing set to stop it — measured at 91% and still climbing. And Claude Code sessions now compact automatically as well; before this release only the manual `/compact` worked there, and a long session would carry on past 94% of its window with no compaction at all. All of it was verified by driving real conversations to the limit and watching the context come back down.

- **The context meter no longer invents a threshold it cannot know.** The percentage above the message box used to be drawn against a fixed guess on every runtime. It now shows the real number where there is one, the runtime's own formula where that is what applies, and nothing at all where the runtime publishes no threshold — rather than a confident figure that meant nothing.

- **Runtime logos now say which runtime you are looking at.** The gateway cards were all wearing the same Nessy mark, so the Codex agent and the Claude Code agent were indistinguishable from the Pi agent at a glance. Each card now wears the mark of the harness it actually runs: the OpenAI mark for the Codex agent and the ChatGPT connection, the Claude mark for the Claude Code agent and the Claude Pro/Max connection, and the Nessy mark on exactly two — the default Pi agent and the cloud agent. The same mapping now applies everywhere a connection is shown, including the connection list, the model selector and plugin badges.

- **Those logos are drawn rather than pasted, so they work in dark mode.** They used to be fixed-colour image files, which is why some of them rendered as a black shape on a dark background. They now take the colour of the text around them, in both themes.

- **The cards above the message box line up with the message box.** The sign-in notice, the task checklist and the running-agents panel each carried their own margin, which did not match the composer beneath them — so their left edges sat a few pixels off, and the three of them could drift apart from each other as well. All three now share the composer's own margin, and a test fails if that ever stops being true.

- **Guardian says what it covers, and says so when its judge failed.** The Guardian settings section described the protection unconditionally while it is in fact wired for Pi sessions only — it now states that. And when the judge cannot answer at all — it failed to start, timed out, or returned nonsense — the question you are asked now tells you so, instead of looking exactly like a judge that considered the action and was unsure. You are still asked either way; you now know which of the two happened.

## FIXED

- **A session could die permanently, mid-conversation, and the only way out was to start a new one.** If the set of agents available to a session changed while it was running — installing a plugin that provides one is enough — the session's runtime could be handed a definition it no longer recognised and refuse the whole session from that point on. Not the turn: every turn, forever, with no way to recover from the app. A definition it cannot use is now skipped and named in the log, and refreshed definitions are handed to a running session properly, so the situation that caused it no longer arises either.

- **Claude Code sessions reported that they had used no context at all.** After a completed turn the session recorded zero tokens used, on every Claude Code session, while the runtime's own record for that same turn showed tens of thousands — so the meter had a correct denominator over a permanently empty numerator. The reading is now taken from the point in the exchange where the real figures exist rather than from the opening frame, where they are always zero.

- **The usage panel's Context row read `0` on Claude Code and Codex.** Two different counters were being read through a fallback that could never trigger, because the one it fell back from is initialised to zero rather than left empty. The row now reads the counter that was actually observed, and shows `?` rather than a confident `0 / 240,000 (0%)` when neither counter has observed anything.

- **Reasoning no longer leaks into the answer when your own connection runs a Qwen model.** Some models emit their internal reasoning inline, wrapped in a marker, and Nessy has always split that out so the answer reads cleanly. That splitting was switched on by the *address* you were connected to rather than by the *model* you were running — so the same model reached through your own endpoint produced answers that began with a wall of thinking. It is now decided by the model, wherever it runs, and a connection can additionally be marked as speaking that dialect for a model we do not recognise. Connections to the built-in gateway behave exactly as before.

- **Signing in to an integration could fail silently, and for some servers it always failed.** Two problems, one behind the other. A failed sign-in was indistinguishable from a successful one — nothing was reported anywhere, so the browser half looked perfect and the credential slot stayed empty. With that fixed, the actual cause appeared in four seconds: servers that hand out a confidential client — Figma is one — require the app to authenticate when it redeems the login, and Nessy had no way to send that. It does now, on both the initial sign-in and the silent renewal an hour later, which would have failed the same way.

- **An error from your provider now says what the provider said.** A refusal from the endpoint was being reported as "your API key may be invalid or expired" — including when the key was perfectly valid and the request had been refused for an entirely different reason. The upstream reason is now carried through to you.

- **A plugin that depends on another plugin now installs both when an agent installs it.** When you install from the Plugins screen, declared dependencies are fetched too. An agent installing the same plugin entered one layer lower and skipped that step, so the plugin arrived, sat disabled with a dependency error, and stayed that way until someone installed the missing piece by hand. Both paths now go through the same install, so the dependency comes with it.

- **An agent can install from your own plugin registry again.** Asking an agent to install a listing from a registry you added yourself failed with a not-found error, because the request went to the built-in marketplace, which had never heard of it. Listings from your own registries now resolve against your own catalog, the way the Plugins screen already did — and when an id really is wrong, the error says which half of it is wrong instead of reporting a lookup failure somewhere else.

- The Nessy mark and the runtime marks now carry a name for screen readers where they stand in for a label; previously the label was silently dropped and the mark was announced as nothing at all.
