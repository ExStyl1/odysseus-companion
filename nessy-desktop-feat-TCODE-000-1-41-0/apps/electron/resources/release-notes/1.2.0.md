# Nessy Desktop 1.2.0

July 17, 2026

## NEW

- A Workspace is now a logical container for projects, capabilities and sessions, while the project you select becomes the agent's real filesystem workspace. The agent can read, edit and run commands inside your project without the old "outside the workspace" error.
- Added project-local configuration in `<project>/.nessy-agent/`: a trusted project can contribute `config.toml` new-session defaults (model, thinking level, permission mode), skills, agents, commands, rules, MCP servers, hooks, permissions and `MEMORY.md`. Portable `AGENTS.md`, `.agents/*`, root `MEMORY.md` and `.mcp.json` continue to load beside it.
- Added structured approval for paths outside the project root: the agent asks with the exact target and read/write access, defaulting to the narrower "Allow once"; "Allow for this session" grants a revocable session root shown in the Agent Runtime panel.
- Added an external-project watcher so edits to a trusted project's supported config and resources take effect on the next turn; losing project identity or trust revokes access automatically.

## IMPROVED

- The Agent Runtime panel now shows the project root, additional approved roots with one-click revoke, project config diagnostics, and an explanation of how the Workspace and project relate.
- System temporary folders (`$TMPDIR`, `/tmp`) are writable without a prompt, matching common agent tooling.
- Project trust is required before any repository-owned capability loads; global and Workspace capabilities always remain available. A project configuration can narrow but never weaken your permission floor, and can never grant credentials, provider auth, environment injection or extra filesystem roots.

## FIXED

- Git metadata (`.git`) and a project's own agent configuration (`.nessy-agent`, `.agents`) are read-only to the agent's file tools, so an agent cannot rewrite its own hooks, config or a commit hook. Git itself, run through the shell, remains the only writer.
- Managed Nessy storage under `~/.nessy-agent` stays off-limits to generic file tools even when a broader parent folder has been approved.
- Fixed shell commands, session restore and the runtime panel for sessions bound to an external project, and stopped honoring an on-disk legacy `.nessy` directory entirely.
