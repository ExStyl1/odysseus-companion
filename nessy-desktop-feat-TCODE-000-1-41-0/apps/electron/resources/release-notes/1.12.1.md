# Nessy Desktop 1.12.1

July 20, 2026

## NEW

- Skill pages now show the real skill. Opening a skill in the marketplace — or an installed one under Sources — renders the actual SKILL.md instructions instead of repeating the one-line description.
- MCP tools appear instantly when the server is already running. Opening an MCP source's page peeks at the live shared pool: if a chat already spun the server up, its tools list loads with no clicks and no reconnect. A cold server keeps the explicit "Load tools" button — nothing starts without your intent.
- Browse marketplaces at scale: filter chips per marketplace (All / Skills Market / each added registry), a lightweight virtualized list for hundreds of entries, and reachable Upgrade/Remove for every added registry.
- External plugin marketplaces in the OpenAI/Codex directory layout (a repository of `plugins/<name>` folders, like github.com/openai/plugins) can now be added and browsed alongside Claude-format catalogs, and registries get sensible names instead of a git ref.
- The Create menu follows the tab you're on: the Skills tab offers "Create skill" and the Plugins tab "Create plugin" — each opens a chat pre-seeded with the right creator guide.
- "Install from URL" moved into the Create menu as a dialog, replacing the block that used to sit under the plugin list.

## IMPROVED

- The marketplace page keeps the two-column layout with a resizable sidebar; the invisible drag zone that resized a hidden panel is gone.
- The Trust review section only appears when something actually needs review.
- The composer's sources button shows its normal empty state instead of "0 sources" when a session's old selections no longer match any pickable source.

## FIXED

- Starting a chat in a trusted project no longer fails with "Unknown H2 Pi tool binding: format" — the formatter tool now has a proper harness binding.
- Workspace MCP servers configured as sources can be activated again: they are governed by their config (like Codex/Claude), not by the per-chat folder/API selection that could never include them.
- Installing a skill from the built-in market works again — catalog entries now carry a proper install source derived from the registry's locator.
- Switching between Explore/Execute or rebinding the working folder mid-session no longer kills the next turn with "Pi execution manifest orchestrator mismatch".
- Desktop notifications after a failed retry no longer show the previous successful answer — they now surface the actual error.
- The first message in a new chat no longer flashes a "Pi execution manifest registration requires initialized identity" error — title generation no longer races the agent's startup.
- The Plugins tab no longer hangs on skeletons while an external marketplace repository is being cloned: the list loads immediately from cache and registries fetch in the background with a hard timeout.
- Adding a large external marketplace no longer slows the app down or fills the disk: browse only fetches the catalog (parsed once, cached on disk, staged clones cleaned up), and only the plugins you install are stored locally.
- The agent can once again follow its own documented flows for creating sources and skills: reading the bundled docs, writing a source config into the current workspace, and authoring a skill folder are allowed through the storage guard — while credentials, other workspaces, and the rest of managed storage stay blocked.
