# Nessy Desktop 1.24.0

August 10, 2026

## IMPROVED

- A plugin's MCP server can no longer take over, move, or break the name of a built-in or your own server. Installing a plugin that happened to bundle a server with the same name as one you already had running — a built-in like an issue tracker, or a server you configured yourself — used to rename both of them, breaking the one you already relied on. A plugin's servers now always appear under their own plugin-specific name, so nothing you already have can be renamed by installing something new.
- A plugin MCP server that duplicates one you already run stands down instead of starting a second copy. If a plugin bundles a copy of a built-in server you've enabled, it is not started, and Sources says "Duplicates a built-in server; the built-in is used." If two plugins declare a server at the same address with the same credentials, only one of them runs, and the other says "Duplicates another server's endpoint; only one copy runs" — instead of both quietly launching redundant processes. Two plugins pointing at the same address under different credentials are kept as separate servers, since they are not actually duplicates.
- Permission rules are not migrated when a plugin's MCP server moves to its new stable name. If you have a rule — allow, ask, or deny — that names a plugin's MCP server by its old short name, rewrite it against the server's current `plugin_<pluginId>_<serverName>` name (check Settings -> Permissions, any subagent file with `disallowedTools`, and any skill file with `allowed-tools` or `disallowed-tools`). An allow or ask rule still naming the old short name simply stops granting anything; a deny rule still naming the old short name stops blocking anything, so the tool it used to block now runs unchallenged — check your deny rules first.
- A scoped or user-configured MCP server whose name is longer than 40 characters now has its tool names shortened, matching a length limit every plugin server's name was already held to. If you have a permission rule naming that server, rewrite it against the shortened name Sources now shows.

## FIXED

- A chat no longer ends because one tool's server name couldn't be matched. Previously, if a server name had become ambiguous or had shifted since the chat started, the whole turn failed with an internal error; now only that one tool is skipped, and the conversation continues normally.
