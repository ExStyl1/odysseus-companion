# Nessy Desktop 1.37.0

September 12, 2026

The coverage-95 parity plan's build waves, and then a day on the rig driving the packaged
build instead of reading it. Sessions can be addressed by name on every runtime, the
primary attached folder became a choice you can make, plugins install from two more git
hosts, and the small places where one runtime quietly did less than the other two were
closed one at a time. The rig day itself produced one shipped fix, a documentation
correction measured against a live child, and thirty-two rows for the follow-up plan.

## NEW

- **Address a session by name, on all three runtimes.** Type `@` in the composer and live
  sessions appear beside the other mentions with their runtime named; the inserted text is
  the plain `@name` the model reads, quoted when the name needs it. `send_agent_message`
  now takes a name where it took an id: one unambiguous live match is delivered straight
  away with no roster call, an ambiguous name refuses **by name** and lists every
  candidate, and a dead name refuses by name too. And a rename that collides leaves the
  name with the session that already has it, renames yours to a two-word variant such as
  `auth-refactor-graceful-unicorn`, and tells you — the runtime's own rule, applied to
  explicit namings only, never to generated titles.
- **The primary attached folder is a choice, not a derivation.** A select in the
  Permissions page picks it from the folders already attached, stored as `primaryDirectory`
  in `config.json`. It is a display and ordering choice and nothing else: the resolver can
  only ever answer with a folder already attached, discovery stays on the project root, and
  widening what the agent may read or write remains `additionalDirectories` or the
  outside-root approval.
- **Plugins install from Bitbucket Cloud and Azure DevOps Services**, beside GitHub and
  GitLab. Bitbucket was measured live; Azure was built from the documented routes — its
  items route publishes zip only, so the pipeline gained a second archive format. A
  self-hosted GitLab installs too: this fork's own git host by name, and any other an
  operator declares in `NESSY_PLUGIN_GITLAB_HOSTS`, which a managed `env` block can mandate
  fleet-wide. The old `gitlab` substring test became a DNS-label test, so a hostname can no
  longer pass by accident, and the refusal a look-alike now meets names the way in. AWS
  CodeCommit is recorded as structurally unroutable — it publishes no archive route at all
  — rather than left looking like a to-do.
- **Codex takes file checkpoints.** Every edit is recorded, so `/rewind` restores files and
  `/diff` shows the turn's edits the way Pi already did, under the same host setting.
- **Codex's own detached `/code-review`**, on the runtime's native `review/start`, and
  **delegation has an off-switch in the app** (Settings → AI) instead of a file to hand-edit
  — with the conditionality stated rather than a plain promise, because codex's own enabled
  `features.multi_agent_v2` takes precedence over it.
- **Claude Code: the card's "always allow" answer produces a real grant.** A mid-turn
  directory approval becomes a session-scoped grant, and a grant the runtime refuses becomes
  a line you can read instead of silence.
- **A never-persist claude session leaves no vendor transcript behind.** A caller's own
  `ephemeral` reaches the child as the SDK's `persistSession: false`, deleting a session runs
  the SDK's own `deleteSession` so the vendor transcript goes with it, and the runtime-switch
  rebuild is confirmed by asking the runtime to read back what was written rather than by
  assuming the write worked.
- **Async hooks get both deliveries the page describes**: `asyncRewake` wakes an idle
  session, a plain `async` hook waits for the next turn. Every host hook run says which
  prompt it belongs to, and a claude `SessionStart` hook's session directives are consumed.
- **The document you wrote is answered back to you, in the chat, on all three runtimes.**
  Hook and automation config notes, the refusal of a project or local
  `permissions.defaultMode` widening, and the shell-command settings refusals — user scope as
  well as project — stop being debug-log entries.
- **Worktrees say which state they came back in.** The documented reopen-reset runs as a
  table over the five reuse states, `.worktreeinclude` is applied again after a reset, and one
  sentence in the chat names what happened to the worktree you reused.
- **`/batch` stops at the branch.** It fans out over worktree leases and opens no merge
  request — now a tested property of the fan-out rather than a promise in prose.
- **The Shortcuts page can be asked a question, in both directions.** Filter by the command
  name in your own language, or press a combination and see every command bound to it —
  including the honest "nothing is bound to this", which the rebind path never had a reason
  to say. The component-specific sections are searched rather than hidden.
- **A per-session `ultracode` toggle** sits beside the effort control, bound to the vendored
  runtime's own settings key rather than to anything of ours.
- **A Pi plan-phase turn reasons at the operator's plan-mode level**, and execution returns
  to the session's own.
- **A per-session runtime diagnostic file for Pi as well as claude**, at a path this product
  owns, with its path named in the chat in debug mode.
- **Codex carries more of the administrator's intent**: the `serviceTier` in the new-thread
  verdict (saying which of the three fields moved), the added folders' skills through
  `skills/extraRoots/set`, `$CLAUDE_EFFORT` / `$NESSY_EFFORT` for shell children, and session
  identity on the OTLP resource, default off.
- **`/quota` on codex carries a measured usage window** instead of an estimate.
- **A user-scope agent file added mid-session is picked up without a restart.**

## IMPROVED

- The switch report prices more of what a switch costs: a project `.claude/commands` file and
  the command-roster difference, the auto-memory folder scope on claude, a rule naming an MCP
  tool or a network host before the switch to codex, the skills an added folder loses on Pi,
  the builtins leaving claude loses (the way leaving codex already reported), the
  security-plugin env switches, the subagent attribution header, and the tool-memory
  companion. The read fence and the `cache_ttl` warmth window are fillable fields now, not
  blanks.
- Telemetry: the span stream exports on its own documented interval instead of borrowing the
  metrics one, `prompt.id` rides on events and is refused on metrics by the page's own
  sentence, one line says which telemetry dialect this session exports, and
  `OTEL_TRACES_EXPORT_INTERVAL` joins its metrics sibling in the managed-env allowlist.
- Claude's six prompt-caching off switches are declared and honoured, and the loopback
  passthrough relay runs under the host's own idle abort.
- A permission rule codex cannot judge is **named** instead of silently matching nothing, and
  four of codex's own matchers were measured — two of them became claims.
- `[claude-code:unrecognized_model]` is explained in the words it means instead of printed as
  a fault; the background tier says which model it was asked for and which one it really runs
  on; a plugin that ships `channels` says so at install instead of losing the component
  quietly.
- The settings diagnosis says plainly that it never repairs anything; a `CLAUDE_CONFIG_DIR`
  overwrite is disclosed rather than merely authoritative; a managed policy root that is not
  an object refuses on the tolerant tier too.
- The release sitting gained six new live cases (`rs-32` … `rs-37`), every one driven on a
  packaged build: the one-click gateway card a new user gets, every runtime against a proxy
  that refuses everything, the four dialogs the chat pane opens, the two sentences an
  administrator writes, what a branch inherits at the moment it is created, and a real
  detached codex review — each with a named detector and a discriminating control.
- **The connection reference now says what a gateway card really does with thinking.** It
  used to promise that the budget saturates at High and the levels above map onto the same
  request; measured live on the packaged build, a model whose id is not a Claude model is
  sent thinking **off**, so the thinking-level control and the `ultrathink` keyword both
  change nothing on that card. The reasoning block you still see is the gateway model's own,
  translated into an Anthropic thinking block by the loopback adapter — which is why it sits
  beside a thinking-token count of zero.

## FIXED

- **One portable hook entry with no local producer switched every automation in the workspace
  off on reload.** A hook this fork cannot emit no longer makes a config reload apply nothing.
- **On codex, a write into `.git` landed with no permission card** where Pi and Claude Code raise
  one — codex protects `.git`, `.agents` and `.codex` itself, but only at the top of each writable
  root, and `/tmp` is a root of its own. The app now projects its protected directories into
  codex's own permissions table as read-only entries, so the shipped binary refuses the write
  in a plain workspace and in one under the temp directory alike.
- **An agent could write a repository's `.codex/rules/` through the shell and codex then
  enforced it.** A shell command whose write target resolves under a project agent-config
  directory now raises the same protected-path floor the file tools raise, on all three runtimes;
  reads are untouched.
- **The compaction reopen card's three answers reached nothing** — the card left the screen, the
  approval stayed counted, no compaction ran and "don't ask me again" was never remembered. The
  card is raised before the reopened session has an agent, and the answer path required one.
- **`ReviewDiff` was advertised to no bridged session**, so the background review codex can
  already run could not be requested by any model — 52 tools offered against 53. Found by
  driving the packaged build on the rig; the review-diff port is now derived from the bridge
  like its two siblings.
- **Codex reached chatgpt.com on every boot.** The plugin-startup egress is closed with
  `[features] plugins = false`.
- **`uv` behind a corporate proxy failed every PyPI resolve** with `UnknownIssuer`. Every `uv`
  the app launches now verifies TLS against the platform certificate store
  (`UV_NATIVE_TLS=1`).
- **The claude API-error scraper read a file the child never writes** — it reads the debug file
  the child actually produces, with the page re-quoted beside it.
- **The "not everything loaded" notice could grow without bound**; it gets one bounded,
  scrollable region with a collapsed roster. **The chat pane's dialogs opened against the
  window** instead of the pane. **`SystemCard`'s sticky band was 95 % transparent** and takes
  an opaque tint, with both stylesheet readings pinned.
- **A `/batch` reply blamed the bound for a unit that never started**, and the batch guard's
  own first catch was the prose describing it: a region may name a forge command only in words.
- `worktreeMove`'s claude cell said `false` after claude earned it; the CLI's no-checkpoint
  control named codex a non-producer after codex became one; the primary-folder sentinel moved
  to module scope; the documented reopen-state table is typed by the module's own union rather
  than by `string`.
- A doc-anchor guard read `…-ctrl+r` as `…-ctrl` and reported its own truncation as a dead
  anchor — `+` survives in a rendered heading id, so the slug rule keeps it and the snapshot's
  one dropped anchor is restored.
