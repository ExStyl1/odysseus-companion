# Nessy Desktop 1.31.0

August 21, 2026

## NEW

- **Switching the integration now hands over the conversation, not a summary of it.** Until now, a switch onto a different agent carried only the last 24 messages, trimmed to 1 200 characters each — and every tool call and result was dropped, so the new agent could not answer about a file it read or a command it ran before the switch. Now, when the history fits the new model's context window, the full conversation — tool calls and results included — crosses as the new agent's own native history: into Codex over its `thread/inject_items` channel, into Claude Code by rebuilding the SDK's own on-disk session transcript, and into Pi by seeding the runtime's own session file for it to fork from. When it does not fit, or the window is unknown, today's text summary crosses instead — and nothing is ever sent blind.

- **The switch confirmation now says what will cross before you agree.** The dialog names which of the three you are getting — the full history with tool calls, a resume of the agent's own earlier record plus what it missed, or a text summary of the recent messages — instead of leaving you to find out after. The decision is made against the target model's real context window, measured before anything is torn down.

- **The post-switch notice names what actually crossed.** The transcript line after a switch now says whether the conversation arrived as native history, as the agent's own resumed record, or as a text summary — and a native attempt that failed reports the text fallback it actually delivered, never the promise.

- **The collapsed turn header now says what the turn did.** A settled turn used to collapse to "Steps Completed"; it now reads like "Edited 3 files, ran 2 commands" — categorized per tool with proper Russian plurals, and Codex's `cat`/`ls` shell reads are counted as reads and listings, not as shell commands.

## IMPROVED

- **A signed-out gateway connection can be reconnected from its own row.** When the gateway sign-in expires, the connection's row menu in AI settings now offers Reconnect — the same one-click flow the notification banner leads to, without walking through adding the connection again.

- **The Russian interface stops echoing English.** A sweep of the locale found 77 strings showing English text in the Russian UI; 40 of them — the send/stop/queue controls, the message-queue tooltips, proxy and server-key settings, provider card titles — are now properly translated (the rest are brands, placeholders and keyboard labels, kept deliberately).

- **Your model now survives an integration switch when the target offers it.** Picking "Qwen Fast" on Pi and switching to Claude Code or Codex used to silently reset you to the target's default model; now the model is carried whenever the target's catalog serves it, and when it genuinely cannot be, a toast names both ends of the reset.

- **A switch onto an integration that cannot start is refused up front.** If the target runtime is not in this build, its binary is missing, or the connection has no usable credentials, the switch is refused before anything is torn down — instead of stripping the session first and failing at the first turn.

- **All three agent runtimes moved to their latest versions.** Claude Agent SDK 0.3.218 → 0.3.223 (CLI 2.1.223, which closes two Bash permission-check bypasses and a custom-endpoint stream-stall class), Codex app-server 0.147.0 → 0.148.0 (model-change forks stop carrying the previous model's instruction template), and the Pi runtime 0.80.3 → 0.84.0 (an auth/model-runtime rewrite, with the runtime's new self-discovery paths explicitly kept offline).

- **Old Claude session transcripts are now cleaned up.** The per-workspace `claude-config/projects` tree — which nothing swept before, and which had already accumulated 37 orphaned session directories — now falls under the same age-based retention policy as the rest of the session data.

## FIXED

- **Tool cards now show paths relative to the session's own directory.** Stored tool inputs and results were rewritten against the directory the app was launched from (often `/` when started from Finder), which produced broken `./Users/…` paths in Read/Write cards; they are now rewritten against the session's working directory, and the raw, unrewritten values are persisted alongside for the history carry.

- **A crash mid-switch can no longer double or lose the conversation.** After an interrupted switch, the next start either completes the native handover or falls back to the text summary — never both, never neither — and a transcript is written atomically so a half-written file can never be resumed from.

- **A background agent's result is no longer lost when its parent finished first.** An agent left working in the background used to complete silently: the session was never told, so its answer simply never appeared. Completion now reaches the conversation whichever way the agent went to the background — asked explicitly or decided by the runtime itself.

- **Switching away from a session with a large history no longer fails with "too many open files".** Listing the session's process records opened every record at once; on long-lived profiles that exceeded the file limit and killed the switch. The listing is now bounded, and old records fall under the same retention policy as the rest of the session data.

- **A failed switch now says which runtime did not shut down — and that nothing was lost.** When the old runtime fails to stop, the switch is refused and the conversation stays whole; the message now names the runtime and says exactly that, instead of a generic failure (which, worse, always blamed the wrong runtime in the logs).

- **A custom endpoint's "access denied" no longer masquerades as a gateway sign-in problem.** A 403 from your own endpoint on a Claude-runtime connection used to show "Your Nessy Gateway sign-in is missing or expired" — a sign-in that connection doesn't have. The message now matches the credential the connection actually uses.

- **The model is no longer told a freshly loaded MCP tool is callable right away.** On Pi, a tool loaded mid-reply becomes available from your next message — but the loader's message promised it immediately, so the model would call it, fail twice, and report a perfectly healthy tool as broken. The message now says when the tool actually arrives, and the model finishes its reply instead of chasing it.

- **Changing the model or invoking a plugin skill on the very first Codex turn no longer fails the turn.** Codex refuses to fork a thread that has not produced any history yet; that refusal is now recognized and answered with a fresh thread carrying the same configuration — lossless, because such a thread provably holds nothing.
