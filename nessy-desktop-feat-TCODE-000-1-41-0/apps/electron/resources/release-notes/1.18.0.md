# Nessy Desktop 1.18.0

August 5, 2026

## NEW

- **The Claude Code harness now runs on the Nessy Gateway.** A new provider card, **Nessy · Claude Code agent**, signs you in with one click — the same corporate `dp` flow the gateway card already uses, no form, no key to paste — and creates a `Claude Code (Nessy Gateway)` connection with the endpoint and models preconfigured. Sessions on it run the bundled Claude Agent SDK, so the tool set, MCP wiring, skills, and permission behaviour are the ones Claude Code users expect, while the models come from the internal gateway. A local translation adapter sits between the two: the SDK talks Anthropic Messages to it, and it talks the gateway's own API upstream. No model traffic leaves for `api.anthropic.com`, and the `Nestor-Token` header is sent only to the verified gateway URL — any other endpoint keeps standard bearer semantics. _(Corrected 2026-08-28. This line originally read "Nothing leaves for `api.anthropic.com`", and that is not true of one path: before fetching a URL, the SDK's WebFetch tool sends the requested hostname — only the hostname, not the URL, path or page — to `api.anthropic.com` to check it against Anthropic's safety blocklist. Anthropic's own documentation says that check "runs regardless of which model provider you use and is not affected by `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`" (`data-usage.md`, WebFetch domain safety check), which is the variable this build sets on the gateway path. The documented opt-out is a different setting, `skipWebFetchPreflight`, which this build does not set; turning it on also stops the blocklist from being consulted, so it is a posture decision rather than a fix.)_
- The card is gated behind the build-time flag `NESSY_FEATURE_CLAUDE_RUNTIME` and is **off** in the default build, alongside the existing Codex runtime flag. Enabling either flag also bundles the Claude SDK native binary; the SDK's JavaScript core ships in every build as before.

## IMPROVED

- **The local model adapter can no longer lose the end of an answer in silence.** Stream termination is now fail-closed: a response that stops arriving without a terminal frame is reported as failed, a partial frame left in the buffer is still parsed, and every open block is closed before the failure is emitted. This is the adapter both runtime cards share, so the Codex runtime gets the same treatment.
- **An upstream error arrives as an error, with its own identity.** Failures are classified instead of collapsing into one generic message — the upstream HTTP status and any `Retry-After` it sent are carried through, so the app can tell a rate limit from an outage from a bad request rather than showing the same red band for all three.
- **A quiet upstream is no longer mistaken for a dead one.** The adapter emits heartbeat frames while it waits, and a stream that genuinely stops producing anything is cut by a stall watchdog and reported, instead of being held open indefinitely.
- Claude sessions run on a newer Claude Agent SDK (0.3.215), matched across every packaged platform.

## FIXED

- **A turn that died mid-stream used to finish as though it had succeeded.** A truncated upstream response ended the turn with a completion frame, so a half-written answer read as a complete one — no error, no retry offered. It now ends as a failure on both adapter routes.
- A tool call carrying no arguments is serialized as `{}` instead of an empty string, which some upstreams rejected outright.
- The Linux build no longer stages the Claude SDK native binary into a build whose feature flags disable it — a ~247 MB payload the app was never going to load.
