# Nessy Desktop 1.8.0

July 19, 2026

## NEW

- Added the Guardian — an AI safety judge for the autonomous modes. In Auto mode, borderline shell, network, and MCP actions that used to always ask can now be cleared or blocked by a read-only judge: approvals you would have clicked through are handled for you with a full audit trail, and anything the judge is unsure about still asks you as before. In Execute mode the Guardian becomes a safety net that can only block or ask on high-risk actions — secret exfiltration, credential probing, destructive operations, and git actions on protected branches — and never widens what a mode would already allow.
- Added Guardian settings under **Settings → AI**: turn the judge on or off and pick the model it runs on. It defaults to the Nessy Gateway "fast" model, so a cheap, quick model does the vetting.

## IMPROVED

- Every Guardian decision is recorded in the permission audit trail with its category and reason, so a cleared action is distinguishable from a plain rule allow.
- Approving a blocked action once stops the Guardian from re-checking that exact action for the rest of the session.
- Identical commands are no longer re-judged — a per-session verdict cache reuses the earlier decision, keeping latency and cost down.

## FIXED

- Untrusted tool output can no longer forge trusted framing in what the judge reads, so a poisoned command result cannot talk the Guardian into clearing an unsafe action.
- A Guardian that times out, errors, or cannot decide always falls back to asking you — it never resolves an action to auto-run on failure.
