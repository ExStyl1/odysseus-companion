# Nessy Desktop 1.4.0

July 17, 2026

## NEW

- Plugin hook types beyond command hooks now run. A supported Codex or Claude bundle can bind four more lifecycle hook types: a `prompt` hook injects a one-shot instruction as hidden context on its event, an `agent` hook spawns a declared sub-agent, an `mcp_tool` hook calls a specific MCP tool, and an `http` hook fires a bounded outbound request. Each runs through the machinery Nessy already had — the same hook path, sub-agent service, MCP pool, and request executor — never a new one.
- Plugin-declared language servers. A trusted plugin can bring its own LSP server; Nessy provisions it through the existing trusted-project language-server owner, under the same supervised process isolation as every other spawned process. It activates only for a trusted project and tears down when trust or scope is lost.

## IMPROVED

- Plugin settings map into your preferences safely. A plugin's declared setting defaults now flow into the preferences overlay under the same forbidden-key guard as project config: any key that could grant trust, credentials, environment injection, or filesystem roots — and any credential-referencing setting — is rejected with a diagnostic and never applied.
- Peripheral plugin surfaces are triaged with a recorded rationale. Output styles, themes, monitors, and channels stay visible in the compatibility report as deferred rather than silently dropped, each with a clear reason for why it does not yet run.
- Every non-command hook type is trust-gated exactly like command hooks: installing or enabling a plugin never auto-grants trust, and changing a hook's prompt, target agent, tool, or request returns it to review-required.

## FIXED

- Outbound plugin HTTP hooks are fail-closed. An `http` hook fires only under an explicit network permission grant; when that grant is absent the request is never sent and has no side effect.
- `mcp_tool` hooks resolve strictly by the fully-qualified `mcp__<server>__<tool>` name, with no short-alias fallback, so a hook can never reach a tool it did not name.

Codex apps and connectors, and connector OAuth, remain deferred and are tracked as a dedicated follow-on: they span the source store, the credential resolver, and an interactive OAuth flow, and are imported losslessly into the compatibility report until that work ships.
