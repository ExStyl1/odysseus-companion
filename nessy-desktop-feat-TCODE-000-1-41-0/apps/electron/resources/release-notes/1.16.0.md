# Nessy Desktop 1.16.0

July 31, 2026

## NEW

- A new **Don't Ask** permission mode for unattended runs: it never prompts, executes only rule-approved and read-only actions, and denies everything else outright — including tools that require a human answer.
- Conversation forks: the **/subtask** command splits the current conversation into a child agent that inherits the full history, tool pool, and permission scope. Running forks are visible and steerable from the agent panel, can request their own isolated worktree, and their permission requests appear in your session.
- A **task checklist** for the session: the agent tracks its plan with dedicated task tools, the checklist survives restart and context compaction, and hooks can veto a task being created or marked complete.
- **Monitors and background work**: a Monitor tool watches a command or WebSocket source into the session's background-task registry, long-running shell and MCP calls move to the background automatically past a threshold, and non-interactive runs wait for background work to finish before exiting. A settings switch disables background tasks entirely.
- **Scheduled session work**: CronCreate, CronList, and CronDelete session tools maintain per-session schedules with deterministic jitter, a seven-day expiry, and no catch-up runs.
- **Session worktrees and retention**: EnterWorktree/ExitWorktree tools with an approval floor, a worktree-aware working directory that survives resume, reference-counted checkpoint cleanup that always keeps the first snapshot, and an age-based retention sweep across sessions and orphaned worktrees with a configurable window and an off switch.
- **Plugin install now ends in setup, not silence**: the install result reports every outstanding sign-in and configuration requirement, and a skippable checklist renders it — the Developer Platform sign-in is one click that unblocks every DP-backed server at once, a plugin needing configuration opens its prompt right there, and OAuth servers are listed with a pointer to the session notice. Servers still awaiting sign-in surface at session start in a non-blocking notice, and signing in from it never interrupts the conversation.
- One **MCP servers panel** lists every server — plugin-owned and user-created together — with each row's origin, transport, and auth state, and a per-server enable switch, so one server out of a plugin's ten can be turned off without losing the rest. A plugin's page shows the same rows filtered to that plugin.
- **MCP resource mentions and prompts**: mention a server resource as `@slug:uri` in the composer, run server-published prompts as `/mcp__slug__prompt` slash commands, and answer server-defined elicitation forms in a consent dialog that warns about deceptive URLs.
- **Skills grew up**: the model can invoke a listed skill on its own, every user-invocable skill gets its own slash command, and skills support named/indexed arguments, effort and paths frontmatter, `allowed-tools`/`disallowed-tools` enforcement, and skill-directory variables in bodies and rules.
- **Structured output**: a JSON Schema can be attached to a run (CLI `--json-schema`, headless surface) and the final answer is validated against it, with bounded automatic retries.
- **Workflows**: multi-step workflow recipes load from the filesystem and from plugins, run as `/name` slash commands with declared inputs, and ask for per-run launch consent with a per-project "remember" option.
- **Safe mode**: start the app, CLI, or server with `--safe-mode` / `NESSY_SAFE_MODE=1` to run a session with no CLAUDE.md, skills, plugins, hooks, MCP servers, commands, or agents — for diagnosing a broken configuration. Managed policy still applies.
- New CLI verbs: `doctor` (read-only configuration checkup that lists rejected settings layers and invalid managed entries, no server needed), `plugin validate` (check a bundle without installing it, `--strict` treats warnings as errors), `plugin list`, and `plugin details` (component inventory with projected token cost).
- **Administrators**: managed policy can now be delivered from a server (opt-in, fail-closed on forced refresh), composed from `managed-settings.d` drop-in fragments, and can enforce a model allowlist, a minimum app version, a plugin marketplace and fleet-wide plugin activation, managed MCP server entries matched by URL and command, Claude-format permission rules, sandbox and network keys, and shell-classification for Auto mode. The CLI `doctor` report shows exactly which managed source is in effect and what was dropped.
- **Network**: mutual-TLS client certificates for corporate gateways, and the OS certificate store is now trusted alongside the bundled set — an enterprise TLS-inspection root installed in the system store works with no configuration. Proxy and TLS settings now also reach agent subprocesses, the auto-updater, and the headless server.
- Optional usage telemetry: per-model token and cost counters with periodic export — strictly opt-in, off until you set the telemetry variable, and carrying counts and identifiers only, never prompts, paths, or file contents.

## IMPROVED

- **Permission modes speak Claude Code's vocabulary**: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, and `bypassPermissions`, plus **Explore** as Nessy's own read-only mode — so a mode name you know from Claude means the same thing here, and every surface (composer, settings, agent guidance) uses the same names. Old spellings like `safe`, `ask`, and `allow-all` stay readable forever, so existing sessions, workspaces, and automations keep working. Bypass permissions now sits behind a first-activation responsibility dialog and outside the default SHIFT+TAB rotation; Auto never auto-approves a file write outside the session's own roots, and Nessy's own safety judge pauses Auto back to Manual when it keeps objecting — that pause is Nessy's addition on the Pi and Codex runtimes, not part of the Claude vocabulary this bullet adopts, and the Claude runtime's Auto uses Claude Code's own classifier with its own limits instead.
- **A plugin's MCP servers belong to the plugin now**, not to each workspace: a server that needs OAuth or a bearer token signs in once, and that one credential covers every workspace. Bundled stdio servers run too — supervised, resolved inside the verified bundle, without inheriting your environment. Enabled servers connect when a session starts so their tools are ready before the first message; a settings switch (`sources.connectOnStartup`) and a managed-policy key restore connect-on-first-use.
- **Sources list only what you created.** Plugin servers no longer appear as per-workspace source duplicates — installing a plugin with fourteen servers creates zero sources — and the migration carries every existing sign-in over, so nobody re-authenticates.
- **Plan mode** now routes shell commands through the safe-command classifier, so read-only investigation runs without leaving the plan — while the write guarantees stay hard-blocked.
- Permission rules understand much more: project `.claude/settings.json` rules, Claude-format rule strings, path globs with gitignore semantics, PowerShell and `cd` rules, parameter matchers — and deny rules now match through `sudo`, `env`, and `exec` wrappers. "Yes, don't ask again" now persists exactly what the button says, and approved permission updates apply to the scope they name.
- Pending permission approvals survive an app restart and re-fire when the session opens, and an unattended approval expires instead of outliving its question.
- The **sandbox** is configurable: a settings schema with a deny floor, per-profile read allowlists, an explicit off switch for the filesystem layer, network rules that bind the sandboxed shell, credential paths denied to sandboxed commands, and an approval card that says when a command would escape the sandbox.
- **Hooks** follow the documented contract end to end: five hook types (command, prompt, agent, mcp_tool, http) with a per-event decision contract, new events (PermissionRequest, PermissionDenied, TaskCreated/TaskCompleted, WorktreeCreate, InstructionsLoaded, SessionStart after compaction), `async`/`once`/`if` fields, a `shell` picker for bash or PowerShell, per-hook status messages in the spinner, matched hooks running in parallel, and a `disableAllHooks` master switch.
- **Plugins**: install dependencies resolve automatically and guard removal, a plugin that needs configuration asks for it at enable, declared user config reaches its MCP, LSP, and skill surfaces, plugin output styles appear in the style picker, a plugin can ship WebSocket MCP servers, and marketplaces can declare authority over or supplement the built-in catalog. The Codex plugin adapter now follows the published contract, and Claude plugins' `lspServers` and default component paths are read correctly.
- **MCP connections** are faster and steadier: server connect moved off the turn critical path, per-server connection status is visible, failing connects retry with bounded backoff, per-server call timeouts with idle-progress reset are configurable, `${VAR}` and `${VAR:-default}` expand in server config, and `alwaysLoad` pins a server's tools out of deferred loading.
- The **/context** overlay shows a per-category breakdown with over-limit warnings and optimization suggestions, and auto-compaction gained threshold and disable knobs plus a bounded budget for re-attaching skill content after compaction.
- Instruction files are discovered up to the project root, subdirectory instruction files load on demand when the agent enters that area, and path-scoped rule files activate on the file being read rather than on the working directory.
- Batched agent questions arrive as one card with a structured answer envelope, and an optional timeout auto-continues an unattended question instead of erroring.
- Subagents accept `color`, `memory`, `background`, `mcpServers`, `skills`, and `isolation: worktree` frontmatter; effort levels inherit correctly through mid-session changes; and orchestration budgets are enforced on every backend, with the reason named when a turn is stopped.

## FIXED

- The pinned capability context (instructions, memory, skills listing) is now composed once per generation and sent once — not re-read and re-sent on every turn. On instruction-heavy projects this removes a large per-turn token cost.
- New guardrails stop destructive removal commands aimed at the filesystem root or your home directory in every permission mode, including Bypass permissions — the removal circuit breaker outranks every mode and covers every destructive spelling shipped.
- Session storage keeps a mirror copy and falls back to it on load, so a damaged session file no longer loses the conversation.
- A malformed agent definition file no longer breaks every send: it is skipped with the file named in the warning, the other agents keep loading, and the CLI `doctor` report points at the exact file. A named subagent in a workspace without a project now runs in the shared scope instead of being refused, and a selected output style no longer leaks into a named subagent's context.
- The fork panel is reliable under real use: steering a running fork reaches it, stopping a child updates the panel immediately, and a dismissed fork row stays dismissed instead of reappearing on the next refresh.
- Permission gates now read the exact tool input the runtime sends (file-path spellings, parameter values, unparseable shell commands prompt instead of denying), a settings-anchored path rule reaches its enforcement layer, and a bare-name deny removes the tool from the manifest entirely.
- A managed policy tightened while a session is running reaches that session, a managed-denied MCP server can no longer arm a push channel, and drop-in fragments cannot flip a policy lock through the prototype chain.
- Proxy and TLS fixes: saving proxy settings preserves the TLS client identity, a literal IP address is treated as a host so deny rules and allowlists apply, a managed extra CA outranks a user CA path, and the headless server's trust-chain watcher survives settings saves.
- Sandboxed commands can no longer reach arbitrary macOS mach services, and the credential deny roots cover the files an agent could exfiltrate.
- An opened repository cannot substitute the selected output style, plugin exec-form hooks spawn their argument vector without shell interpretation, and Codex hook ids cannot collide across sources.
- UI: an answered permission card is removed instead of lingering, the agent and checklist panels match the chat width, a running fork's output is readable while it runs, the session Info popover shows the Pi runtime diagnostics again, and loaded-file labels in the /context overlay are human-readable.
- OAuth failures during provider sign-in are terminal instead of retrying forever, and the desktop's gateway auth runtime is kept out of the renderer process.
