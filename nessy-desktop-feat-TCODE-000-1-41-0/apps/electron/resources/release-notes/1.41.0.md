# Nessy Desktop 1.41.0

September 25, 2026

The integrations follow-up release: what 1.40.0 deliberately left for later, and a
close-out safety pass. Codex now follows your permission rules and modes the way Pi and
Claude Code do. A message you send while the agent is working reaches it in order and with
its files, an approval card closes itself when nobody is waiting on it any more, and
`/hooks` shows what your hooks really did, on every runtime. `/quota` works on all three
gateway cards, the Developer Platform sign-in shows you its link when the browser tab does
not appear, and an administrator can give every user a set of MCP servers. All three
runtimes move to newer versions (Claude Code 2.1.274, Codex 0.159.3 and Pi 0.85.1), Claude
Fable 5.1 works on Claude Code and Pi, and Codex now runs with its own sandbox defaults:
its threads open in about a second, and its commands can read your credential files, as
Codex itself allows. A long list of safety fixes tightens what runs without asking, and
the last of them keep the agent away from its own permission rules, automations and hooks
and from Nessy's data folder, whatever the project folder is. A project you keep
restricted now stays restricted on Codex and Claude Code too. The permission modes are now
Claude Code's own: Explore is gone and Plan takes its place, and Plan can write and submit
its plan on Pi and Claude Code. Five issues listed as known in 1.40.0 are fixed: the
rewind menu, `/hooks`, marketplace errors, a Pi subagent's `maxTurns`, and `/quota` on the
Claude Code and Codex gateway cards.

## NEW

- **`/quota` on the Claude Code and Codex gateway cards.** The command is offered in the
  menu on all three Nessy Gateway cards and shows the same per-user budget the Pi card
  shows, instead of pointing you to a Pi session. Stop cancels the read. A card pointed at
  your own endpoint is unchanged.
- **Developer Platform sign-in: a link you can copy, and a fallback when `dp` cannot
  run.** While the sign-in waits, onboarding, the sign-in banner and the in-chat card show
  the link with a **Copy** button, and the tab still opens as before; the sign-in has to
  finish in a browser on the same computer. When the `dp` command cannot be run for a
  reason other than a sign-in, the app signs you in to the gateway once with the `dp`
  session already stored on this computer, without changing it, and tells you it did so.
- **Codex follows your permission rules and modes for MCP and session tools.** An allow or
  deny rule for a source's tool (`mcp__<source>__<tool>`), a whole server or a pattern
  (`mcp__server`, `mcp__*__delete*`), or a session tool approves or refuses the call with
  no card, as on Pi and Claude Code, and a rule in Pi's spelling for a session tool
  applies too. A deny rule removes the tool from Codex itself, and an ask rule makes Codex
  ask even about a tool its server marks read-only, with auto-review on or off. **Always
  Allow** on a Codex MCP card lasts for the rest of the session. Plan refuses a source's
  write tool and a session-configuration tool (such as editing an automation) instead of
  asking you, and the agent is told the mode refused it, not you. The MCP card names the
  tool and shows its arguments, and Codex is told the tool names its model is actually
  given.
- **A capped Pi subagent stops at its limit, says so, and can be resumed.** A subagent's
  `maxTurns` now limits its model round trips on Pi (a 1.40.0 known issue), and an
  automatic retry no longer counts against it. When it stops at the limit, the parent is
  told the output is partial and how to resume the subagent.
- **An administrator can give every user a set of MCP servers.** The managed-policy key
  `managedMcpServers` (remote `http` and `sse` servers) reaches every session on Pi,
  Claude Code and Codex alike. Users keep their own servers, and `deniedMcpServers` still
  applies.
- **A plugin enabled for a repository's project loads in each of its git worktrees**, and
  a session already open in a worktree takes a project-scope plugin change made in the
  main checkout. Trust is still asked for each folder.
- **ChatGPT (Codex), behind a build flag.** A card that runs the Codex agent on your own
  ChatGPT subscription: you sign in with your ChatGPT account in the browser, through the
  same sign-in the ChatGPT card uses, and turns spend the subscription through Codex's own
  provider. `/quota` shows the subscription's usage windows, the model list starts as
  Codex's own, with GPT-6.1-Sol as the default, and is refreshed from your account after
  sign-in, a model Codex lists as text-only does not offer image
  attachments, and Codex's own web search is the one search tool, narrowed by
  `NESSY_WEB_SEARCH_ALLOWED_DOMAINS` (the chat says once that
  `NESSY_MAX_WEB_SEARCHES_PER_SESSION` does not limit it); each of its searches shows in
  the chat as a Web Search step with the query. A turn stopped by the usage
  limit says when the limit resets and that Codex will not resume the turn by itself.
  Title prompts and one-shot completions are refused on this card rather than sent to the
  Nessy Gateway, so the session keeps its default title. The Pi card is now called
  **ChatGPT Plus (Pi)**, so the two cannot be mistaken, and the tool-sharing notice under
  the model list names chatgpt.com for both ChatGPT cards and api.anthropic.com for Claude
  Pro / Max. The ChatGPT cards appear only in builds made with
  `NESSY_FEATURE_PROVIDER_CHATGPT=1`, which is off by default.

## IMPROVED

- **All three runtimes moved to newer versions:** Claude Code 2.1.274 (Claude Agent SDK
  0.3.274), Codex 0.159.3 and Pi 0.85.1. A cloud-provider credential failure on Claude
  Code now gets its own message instead of "check your network", and so does a provider
  that asks your organisation to complete a verification step first; Codex warns about a
  configuration name it does not recognise instead of ignoring it.
- **New models.** Claude Fable 5.1 works now, on Claude Code and on Pi. Claude Opus 5.5
  and Sonnet 5.5 arrive with a later runtime update: on your own Anthropic connections they
  need a newer Claude Code (2.1.280 for Opus 5.5, 2.1.284 for Sonnet 5.5) and a newer Pi
  than this release carries, and the corporate mirror serves a new version about 14 days
  after its release. The app already knows their 1M-token context window and their medium
  default effort. Until then, a Claude Code chat on a model that needs a newer Claude Code
  says so, naming the version the model needs and the bundled one, instead of showing a
  generic error with a Retry that cannot help; the same message names the bundled version
  when your organisation requires a newer Claude Code. The Nessy Gateway cards get their
  models from the gateway and need no update. The **Extended Context (1M)** switch is gone
  from Settings → AI: every model now runs with its own context window, so on an Anthropic
  connection Fable 5.1, Opus 4.7 and later and Sonnet 4.6 and later get their full 1M tokens
  instead of 200K (Sonnet 4.6 on a Claude subscription needs usage credits for that, and
  Claude Code says so). Opus 5.5 and Sonnet 5.5 still arrive with the runtime update above.
  An administrator who must cap the window sets `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. An
  Anthropic API connection also takes each model's context window from Anthropic's model
  list, so a model newer than the app is no longer shown at 200K. Codex sessions on OpenAI's newest models (GPT-6.1, GPT-6 and GPT-5.6) can
  now use tools: those models need Codex's own code-mode host, which the app now ships.
- **The permission modes are Claude Code's own: Explore is gone, and Plan takes its
  place.** The mode picker matches Claude Desktop's: Auto (Recommended), Manual, Accept
  edits, Plan and Bypass permissions, numbered 1–5 so that a digit picks one while the
  menu is open, with a Default badge on your workspace's default mode; SHIFT+TAB steps
  through the same five, and from a mode outside them it goes to Manual first. Don't ask
  is no longer offered, but it still works for automations and configuration files, and a
  session or automation that uses it shows it by that name (Не спрашивать in Russian). A
  session, automation, workspace default, link or command-line flag that names Explore
  opens in Plan; an automation saved in Explore shows and runs as Plan, and the file says
  Plan the next time any automation is saved. Plan now also writes into the session's
  data folder, as Explore did. Explore's other writes are gone (anything else in the plans
  folder, directories added to the session, `allowedWritePaths` and shell redirects), and
  Settings → Permissions no longer offers `allowedWritePaths`. A former Explore session
  counts as Plan for messages from your other sessions too: where Bypass permissions is
  available, it now holds a message from a session that asks for permissions until you
  approve it. The agent's own session and automation tools offer the six modes, on Pi
  the agent is told what Plan may write, and the hints it gets when a shell command is
  refused name Plan and Don't ask, on existing installs too. A saved session view that
  filtered on Explore (`views.json` in the workspace) now filters on Plan, and the
  built-in one is renamed "Plan mode". A Nestor Cloud session in Don't ask
  shows Plan, which is what it sends. On the iPhone the mode menu matches the desktop: a
  Nestor Cloud session offers only Plan and Act, other sessions offer Auto, Manual, Accept
  edits and Plan, and Bypass permissions is listed but can be turned on only from the
  computer.
- **Codex runs with its own sandbox defaults.** The app no longer adds its own list of
  credential files to Codex's sandbox, so Codex threads open in about a second instead of
  tens of seconds. Codex commands can now read Nessy's credential files and `~/.ssh`, like
  any other file Codex's sandbox allows; a command you approve runs outside Codex's
  sandbox, and **Always Allow** on a command card saves a permanent rule. Denied paths of
  your own (`deniedPaths`) still reach Codex: while any do, an approved command stays
  inside the sandbox and its card says so, Always Allow lasts for the session, and the
  session's diagnostics say that those entries slow thread opening and how to get fast
  opens back. The Bypass permissions warning now says what bounds Codex's writes: Codex's
  own workspace sandbox, which stays on for the protected folders.
- **Web search runs without asking in every permission mode, unless a deny rule turns it
  off.** Such a deny now reaches every search: it removes the app's search tool from every
  Codex session and from Claude Code sessions on the gateway, and switches Codex's own web
  search off on the ChatGPT (Codex) card, from the next turn when you add it during a
  chat. Claude Code's own web search now follows the administrator's domain list
  (`NESSY_WEB_SEARCH_ALLOWED_DOMAINS`) when one is set.
- The `/btw` side-question panel shows the same working indicator as the main chat
  (spinner, status word and elapsed time) while an answer is on its way. Its composer
  folds away while it waits and gets the focus back when the answer arrives.
- A message you queued while the agent was answering now appears after that answer, not
  above it. Background task notifications between turns, and a plugin monitor's message
  delivered into a running turn, appear as a labelled line naming their source that you
  can expand, not as a message that looks like you typed it.
- The context meter and usage panel stop showing old readings as current. After a
  compaction, including one inside a turn, Claude Code sessions show the new, smaller
  size; a reading that a later turn or `/context` contradicts is marked "outdated"; and
  switching runtime clears the previous runtime's numbers. The meter keeps its window size
  when an update arrives without one.
- A run of retries shows one status row that becomes "Retry succeeded" and stops spinning,
  whichever runtime is retrying, instead of one spinner per attempt.
- On Pi, the model is told which tools load on demand (`review`, `web_fetch`, most session
  tools and deferred MCP tools), so it finds them instead of reporting them unavailable.
  `/recap` on a reopened Pi chat answers.
- In Plan mode on Pi, a deferred MCP tool your workspace marks read-only can now be found
  and loaded. Searching for or loading a deferred tool no longer asks for permission in
  Manual, Accept edits or Auto, and on Pi a load is no longer sent to the Auto classifier
  or the Bypass safety judge; the loaded tool is still checked when it is called. The
  built-in Developer Platform servers' read tools (Jira search, GitLab, Allure and the
  rest) no longer ask either.
- **Settings → Codex auto-review** now says what the reviewer can approve that the app
  would otherwise refuse or show you, and that a run of denials interrupts the turn. With
  auto-review on, the reviewer answers only in Auto and Bypass permissions: in Manual,
  Accept edits and Plan the approvals come to you, and Don't ask refuses them. If your
  organisation's Codex policy allows only the reviewer, that policy wins, with auto-review
  on or off: the reviewer answers in Manual, Accept edits and Don't ask too (so in Don't
  ask it may approve what the mode would refuse), Codex refuses Plan turns, and the session
  says so when it starts. The Bypass permissions confirmation says that Codex's reviewer
  still answers what Codex raises in Bypass, and the runtime-switch dialog says exactly
  which permission rules stop applying on Codex.
- `/tasks` and the background-task panel list a plugin's scheduled monitors with their
  schedule, and say plainly that such a monitor reaches the agent only while a turn is
  running: a tick that fires while the session is idle is skipped, not saved for later.
- A built-in Developer Platform server's page tells a user without `dp` why it cannot
  start.
- The composer keeps its line spacing, turns off auto-capitalisation and auto-correction,
  and its placeholder sits on the same line as the cursor. Pinyin and other input methods
  now show what you are typing in an empty composer.
- Spawn Session, Archive Session, Send Agent Message and every other session tool show a
  readable name in the transcript, the activity panel and its title, and in the iOS app.
- More of the interface is translated, with correct Russian plurals: activity cards, copy
  buttons, the code-language picker, diff comments and the diff overlay, the Mermaid
  full-screen label, the permission-mode drawer, the session-list menus and filters,
  sidebar navigation, credential prompts, sharing, marketplace search, and the macOS
  admin-approval card. The Russian warnings about permission rules that were skipped or
  could not be applied now name the settings level (workspace, project and so on) in
  Russian, and the Russian Codex note in the permission-mode menu calls the mode
  «Обход разрешений», as the picker does.
- When the agent uninstalls or disables a plugin, or a plugin or source a turn was using
  is removed, the stopped turn names the plugin and shows one explanation, without the raw
  `capability-snapshot-revoked` error after it, and a tool that was still running shows as
  failed with that reason instead of finished with no result. A session that never loaded
  the plugin keeps its running turn and picks up the change before its next one.
- The automation tools state their permission-mode ceiling where a model reads it, so a
  model no longer tries `auto` or `bypassPermissions` first and gets refused.
- The command-line client no longer glues a failed partial answer to the retried one: text
  output marks it `[incomplete response discarded]`, and `--output-format json` reports
  only the retried answer.
- The app bundle no longer ships an unused MCP bridge server (about 0.6 MB, previously
  packaged twice).
- The Codex Amazon Bedrock connection in Settings → AI shows which AWS region Codex will
  use and where that region came from.
- Documentation: a new page, "Organisation MCP servers", explains how an administrator
  delivers remote MCP servers to every session and what users see. The Environment
  Variables reference documents `NESSY_WEB_SEARCH_ALLOWED_DOMAINS`, including where it
  applies and where it does not; the automations page says a Bash-only `PreToolUse` guard
  does not cover the session's script tools and shows a matcher that does; and the
  headless server page says where Bun loads `.env` files from and how to start the server
  without them. Several section links in the Russian pages, mostly to titles with ё, now
  open the section instead of the top of the page.

## FIXED

**Security and safety**

- **Two Claude Code chats on different Anthropic connections no longer swap credentials.**
  Opening or starting a second chat could restart the first one on the second chat's key and
  endpoint.
  Adding or saving an Anthropic connection with a custom endpoint no longer moves an open
  Claude Code chat on another connection onto that endpoint with its own key, and Pi and
  Codex sessions no longer inherit the default Anthropic connection's key. A Claude sign-in
  renewed during a chat now renews that chat's own connection, so a chat on another
  subscription or on an API key no longer receives the default connection's token.
- **The connection decides where a Claude Code session's requests go.** A Claude
  connection without an endpoint of its own now always talks to Anthropic, even when
  `ANTHROPIC_BASE_URL` is set in the environment the app was started from, and a
  repository's or workspace's Claude settings file can no longer move a session to another
  endpoint or switch it to Bedrock, Vertex or another provider. The chat says which file
  tried, and Settings diagnosis lists each ignored value by file and setting name (the
  environment's endpoint, and a settings file's endpoint, provider switch or first-party
  endpoint flag). A session without an endpoint of its own hands its tools Anthropic's own
  address, never an empty one. Which credential signs the requests stays the project's
  choice, as Claude Code allows: a trusted project's Claude settings file can set its
  sessions' token, API key, `apiKeyHelper` or `CLAUDE_CODE_OAUTH_TOKEN`, and the app now
  names that file in the chat and in Settings diagnosis; the `apiKeyHelper` warning no
  longer claims Claude sessions ignore it. On cards that go through the app's local
  adapter, such as the Nessy Gateway card, that credential is not forwarded. Test
  connection and the diagnostics check on an Anthropic API card no longer read your Claude
  Code settings files (`~/.claude/settings.json`), so they test the endpoint and key you
  entered.
- **The agent can no longer plant Nessy's global hooks, MCP servers, settings or permission
  rules — or another workspace's — by copying, moving or linking a file into their folder**
  (for example `cp x/hooks.json ~/.nessy-agent/`) or with `dd of=`, in any mode, Bypass
  permissions included; a copy into those folders whose file names cannot be read from the
  command (a folder, a wildcard, a variable) is refused too, and so is an archive extracted
  or a file downloaded into those folders (`tar -x -C`, `unzip -d`, `7z x`, `wget -P`,
  `curl -O`, and now `scp` and `aria2c`). Copying a folder's contents or a wildcard into
  the session's own workspace folder can no longer place that workspace's permission rules
  or automations there, and copying a folder into a folder above Nessy's data folder can
  no longer merge files into the data folder (copies that do not reach it still run). The
  agent can no longer move or delete another workspace's folder, the workspaces folder or
  Nessy's data folder either, in any mode.
- **A deny or ask rule you add while a session is running now applies to it.** On Claude
  Code and Pi it applies from the next tool call, even inside the running turn; on Codex
  from the session's next turn, MCP rules included, also for a tool its server marks
  read-only and with auto-review on (before, it held only in sessions started after the
  edit). A rule you remove, and a new allow rule, take effect from the next turn.
- **On Claude Code, an ask-rule card for Read, WebFetch, Grep, Glob or an MCP tool now shows
  what it approves** — the file, the URL or the call's arguments — not just the tool's name,
  and a deny or ask rule on a folder now also holds when the agent reads a large image in
  it (the rule used to be checked against the resized copy, and the image got through).
  A large image you decline is no longer copied into the session's temporary folder
  either: the resized copy is made only after you approve.
- **On Pi, a shell command writing to `$CLAUDE_JOB_DIR/tmp/…` now asks first.** Pi's shell
  has no such variable, so the file went to the system `/tmp` with no approval card. Pi's
  shell commands now get their own session's scratch folder in `NESSY_SESSION_JOB_DIR`, so
  parallel sessions no longer share one, and the agent's Write and Edit into the session's
  scratch folder (`job/tmp`) work without a card, as on Claude Code. A Claude Code session whose scratch
  folder could not be created no longer inherits one from the environment the app was
  started from, and its writes to `$CLAUDE_JOB_DIR` then ask for approval.
- **On Pi, an ask rule now holds in Manual too.** A card raised by one of your ask rules
  no longer offers Always Allow, which switched the rule off for the rest of the session
  or saved a rule the ask rule overrode, so the rule asks every time; such a card now
  shows the command it is asking about next to the rule, and in Don't ask a call the
  rule matches is refused, naming the rule, instead of waiting on a card nobody can
  answer.
- **Your ask rules now hold on Codex.** A shell command or MCP tool call that matches one
  now waits on a card that names the rule and the tool it matched (Bash, or the MCP tool's
  own name, not Codex's internal one), in every mode, Bypass permissions included, and
  that card has no "Always allow"; when nobody is present to answer, the call is refused,
  naming the rule, also in Don't ask, where the refusal used to give a generic reason.
  Before, Bypass permissions ran the call with no card, and "Always allow" in Manual let
  the next identical call run without asking.
- **An ask rule on a privileged install asks every time.** When one of your ask rules
  matches a privileged install (`brew install --cask`, `brew upgrade --cask`), the
  administrator card on Claude Code and Pi names the rule and no longer offers a remember
  switch, which on Claude Code used to switch the rule off.
- **Pi web search no longer sends your connection's credential to OpenAI.** On the Nessy
  Gateway card, and on any connection that uses your own OpenAI-compatible endpoint, Pi's
  web search sent that connection's key to api.openai.com; it searches through DuckDuckGo
  instead now. A key you issued for OpenAI, OpenRouter or Google still gets that
  provider's own search.
- **The agent can no longer rewrite its own permission rules, automations or hooks with a
  shell command.** On Pi and Claude Code, a command writing the permission rules or
  automations that first changes into the workspace folder (`cd …`), writes the path with
  `~` or `$HOME`, or wraps the write in `bash -c "…"` went through with no prompt in
  Bypass permissions, and so did a path split by quotes or backslashes, a `cd -P` or a
  bare `cd`, a path held in a variable set in the same command or written with `$PWD`, or
  a file name in other letter case; all of them are refused now. On Codex,
  those workspace files stay closed to agent commands when the project folder contains the
  workspace, when a folder you added under additional directories contains it (the folder
  stays writable; those files cannot even be read), and in a chat with no project. A shell
  read of the automation record is pointed at the automation list tool instead.
- **Nessy's own data folder stays out of the agent's reach.** On Pi and Claude Code the
  agent can no longer write Nessy's global hooks, MCP server list, app configuration or
  default permission rules, or any workspace's permission rules, automations, automation
  history or hooks, in any mode, Bypass permissions included; before, Bypass permissions
  let it write them and so give itself hooks, servers and rules for every later session.
  The refusal names the file and where to change it; the agent can still read these files
  with its Read tool, and a shell `cat` of them is refused. Other writes into the data
  folder, such as a new skill, still need your approval outside Bypass permissions, also
  when the project folder or an added directory contains the data folder (your home folder
  as the project with a moved `NESSY_CONFIG_DIR`, for example); Accept edits and Auto used
  to write them with no prompt. On Codex, a file patch into the data folder (the global
  hooks, MCP servers, configuration and permission rules, Codex's private session folder,
  or any workspace's records) is refused in every mode, Bypass permissions included, where
  Bypass used to approve it and Codex then wrote the file, and so is a shell command Codex
  asks you to approve when it names one of Nessy's control records, a Codex home or
  `credentials.enc`; an added directory inside the data folder is no longer handed to
  Codex as writable. When the project folder or an
  added directory contains the data folder, or the project is the data folder itself, a
  Codex agent command can no longer rewrite the global hooks, MCP servers and default
  permission rules, skills, or other workspaces' rules and hooks; when the data folder
  sits in a temporary or added directory, agent commands cannot read it either.
- **A project's own settings can no longer loosen the session.** With your home folder as
  the project, a Codex session ran outside its sandbox in every mode, because Codex read
  your own Codex settings (`~/.codex/config.toml`) as the project's; a project's
  `.codex/config.toml` can no longer turn the sandbox or the approval policy off, or hand
  your approvals to Codex's auto-review reviewer while auto-review is off in Settings (nor
  can your own `~/.codex` when your home folder is the project), and the session says so
  if Codex settles on a different approval policy than the app asked for.
  A project you keep restricted (**Keep restricted**) now stays restricted on Codex and
  Claude Code as well: Codex no longer trusts the folder on its own, and until you trust
  the project its `.codex` settings, MCP servers, hooks, rules and `AGENTS.md` (Codex) and
  its `.claude` settings and hooks, `.mcp.json` servers, `CLAUDE.md` and `CLAUDE.local.md`
  (Claude Code) do not load or run. A restricted Codex session says what it left out,
  its skills included.
  On Codex a restricted project no longer offers its own skills to the model either: the
  skills in its `.codex/skills` folder and in every `.agents/skills` folder from the project
  root down to the working folder are switched off each time the chat opens its Codex
  thread, and if the app cannot get that list from Codex it does not open the thread and
  says why (a skill added while a chat is open stays available until the chat reopens).
  A folder whose only project setup is a `.codex/` folder, `.claude/skills` or
  `.claude/rules` now shows the trust prompt when you reopen it, so those layers load
  once you trust it instead of silently staying out. The same holds for a folder inside a
  repository, such as a package in a monorepo, when the repository's root carries that
  setup (a `.codex/` folder, `.claude/skills`, `.claude/agents`, `.claude/commands` or
  `.claude/rules`, a `.mcp.json`, or an `AGENTS.md` or `CLAUDE.md`).
  The same holds for Claude Code setup in the folders above a repository and, for a folder
  that is in no repository, in its parent folders (a `CLAUDE.md`, `CLAUDE.local.md`,
  `.claude/CLAUDE.md`, `.claude/rules` or `.mcp.json`, and outside a repository also
  `.claude/skills`, `.claude/agents` or `.claude/commands`); your home folder's own
  `~/CLAUDE.md` and `~/.claude` setup is not asked about and loads in Claude Code sessions
  only for a trusted project. The trust prompt also lists the language servers your
  enabled code-intelligence plugins would start on Pi, so an ordinary code folder is asked
  about, and code intelligence starts there once you trust it.
- **Codex's "always deny" rules and its unattended-automation check can no longer be
  switched off by the agent.** Codex's private session folder, which holds the always-deny
  rules and the hook settings Codex reads, now lives inside the app's settings folder, out
  of reach of agent commands, also when your project folder contains the settings folder;
  for a few unusual layouts the older temporary location is kept and the session says so.
  The file that tells the automation check the session's mode is kept where no agent
  command can write it either, and where no such place exists the check stays on in every
  mode and the session says so.
- **`sessionAllowedTools` on Claude Code now limits the built-in tools to the ones it
  lists.** Before, it left every tool available and let the listed ones run without
  asking. MCP tools are not governed by it; use `sessionDisallowedTools` with an
  `mcp__<server>__*` entry for those. `nessy-general-agent doctor` names every entry Claude
  Code ignores (a scoped rule, an MCP tool name or a misspelt name) and says why, and the
  runtime-switch warning says that on Claude Code the list narrows only built-in tools,
  while on Pi it covers MCP tools too. The side requests the app makes for the agent on
  Claude Code (`call_llm`, the advisor, `/btw`, title and summary generation) no longer
  get any built-in tools, with or without that setting: they had Claude's full default
  tool set, and those tools skipped the app's permission checks. They also no longer read
  your Claude settings files, `CLAUDE.md` or hooks, or load MCP servers from your Claude
  settings, a project's `.mcp.json` or plugins. `/btw` now matches its documented "no tool
  access", and the notice about skipped permission prompts no longer says the app's own
  permission check is bypassed.
- **MCP tools whose names merely contain a read word no longer run without a card.** In
  Explore (now Plan), Manual and Don't ask, `update_issue_status`, `delete_account`,

  it, so `get_or_create_user` asks too. This covers the built-in rules, a source's own

  the parent's, and the new session says so when it was narrowed.
- **Your deny and ask rules now hold on Claude Code.** A deny rule in a workspace's

  raised a card on Claude Code in Manual, so you could approve what the rule forbids, and

- A `Read`, `Edit` or `WebFetch(domain:…)` allow rule no longer approves an MCP tool call,

  Claude-style allow rule such as `Bash(git status)` now also approves that command on
  Codex, and a rule naming the shell itself no longer approves every Codex command.
- After you chose **Always allow** for a command on Codex, any command containing `;`,
  `>>` or `&&` was refused as "unsafe or unsupported syntax" in every mode, Bypass
  permissions included: the agent's own compound commands on Pi and Codex, and your own
  hooks, so such a prompt hook dropped every message. Such a command is now judged as if
  that rule were not there (Manual asks, Bypass permissions runs it), and a deny rule
  still refuses it. An Always allow on a command Codex cannot split (for example
  `rm -rf ~/folder`) is now honoured by the app's own permission check too, so the

- Commands that print stored credentials now ask first: `kubectl config view --raw`,

- A source's description and a remote MCP server's connection-error text reach the model

  character, before or inside the tag name. The Pi review tool's reviewer no longer loads

- **Administrator settings hold as written.** When managed settings change `HOME`, your

  Permissions. The API endpoints it allows now apply only to that source's own API tool;

  working directories" setting on all three runtimes; with that setting on, a script
  refuses to run and names it. A file attached to a `call_llm` request now passes the same
  read check as the Read tool, on Claude Code and Pi: a denied path, a file a deny
  `Read(…)` rule protects, or a credential file such as `~/.aws/credentials` is refused
  with its reason instead of reaching the side model's prompt, also when only a managed or
  pinned permission layer denies it. A Read, Write, Edit or search of a link that points
  at a protected file or folder (for example a `.env` file or `~/.aws`) is refused the

- **Approving a plan no longer switches the chat to Bypass permissions.** Approving from

- **Changing what or when an unattended automation runs asks you.** Changing, re-enabling,

  does not raise it. On Codex the change is never approved for you when nobody is
  watching: with Codex auto-review on, a session in Auto refuses it before the reviewer
  is asked, while Manual and Accept edits show you the card; if your organisation's
  Codex policy allows only the reviewer, every mode but Bypass permissions refuses it,
  and the refusal names the policy.
- The agent now asks before it edits the workspace's `hooks.json` in Accept edits or Auto.
  On Pi, when a hook adds a session rule for a command the dangerous-command safeguard
  always asks about (such as `git push`), the agent is told the safeguard still asks, not
  that the rule applied.
- On Claude Code, the claude.ai cloud tools (Artifact, Projects, ClaudeDesign,
  RemoteTrigger) are turned off on every card. A file only counts as read when the shell

  always the session's own; it could move next to or into your project, where writes then
  ran without a prompt. The write-blocked hint in read-only modes names the right session.

  involved: a source or skill name must be a single folder name, only folders inside

**Messages, Stop and the queue**

- **A message with files sent while the agent is working is now queued and sent with
  them.** Before, it reached the model as text only while the transcript showed the files
  (Pi, Claude Code and Codex). The send button says **Queue** for such a message, and for
  a message typed behind a queued file or workflow message. Steer and Edit are disabled on
  it with a tooltip, instead of silently dropping the files. A queued message with files
  still waiting at restart is sent with its files, a text message sent after it no longer
  overtakes it, and a queued message with one file no longer reads "Attachments: 2".
- **Claude Code: every message you send while the agent works now reaches it, whole and in
  order.** A second message no longer replaces the first, a message longer than about
  2,000 characters is no longer cut to a preview, and your mid-turn messages are placed
  ahead of long hook and rule context. A message not delivered by Stop or by a plan or
  sign-in card goes back to the queue instead of vanishing, without making the agent
  believe its reply was interrupted. A message sent while a subagent works reaches the
  main agent. A correction typed during planning waits in the paused queue (Steer /
  Resume) instead of running after the plan has been carried out.
- Pressing Stop while a follow-up is queued no longer puts the stopped prompt back in the
  composer or sends it again. A message you type after Stop, while the turn is still
  ending, is queued instead of being pushed into the stopping turn. A message queued
  behind a turn you stopped is no longer sent by itself the next time the app starts: it
  waits under "Queue paused because you interrupted" until you press **Resume**, and
  Steer on such a message sends it exactly once, even across a restart. Steer on a queued
  workflow command no longer sends it as plain text, and says why it is unavailable. A
  message put back in the queue shows as queued again, not as delivered, and on Codex,
  when only the second of two identical messages could not be delivered, that one goes
  back to the queue.
- **A turn that ends late no longer disturbs the next one.** When a stopped response took
  more than 5 seconds to wind down, or a plan or sign-in card ended the turn, the next
  message could be cut off when the old response finished: its reply stopped streaming, a
  steer was replayed as a separate turn, or the reply inherited the old stop reason,
  spending-limit verdict or structured result. The old response's cost is still counted,
  and a goal's token count credits the reply that spent the tokens. Pressing Stop twice on
  consecutive turns no longer cuts the second turn off early, a Stop pressed while the
  next turn is still getting ready stops its model call, a message stopped while the
  previous response was winding down no longer goes on to call the model and run tools,
  and a reply after a Stop pressed just as a plan or sign-in card took over streams as it
  is written.
- **Stop now stops a Claude Code session that is working toward a goal.** A few seconds
  after Stop, such a session used to start a "Continue active goal" turn by itself and go
  on running tools. The goal now stays set and waits for your next message, also when a
  Stop takes more than five seconds to finish.
- After Stop, while a plugin monitor or background notification is waiting, the agent no
  longer starts a new turn on its own; the notification goes with your next message. A
  plugin monitor's report no longer appears as a message from you: on Claude Code, Pi and
  Codex it reaches the agent as a background notification from that monitor.
- Accept & Compact sends the approved plan exactly once, after the compaction you asked
  for; an automatic compaction or a busy session no longer sends it early, on any runtime.
- Accept & Compact on a short Pi session no longer stops with "Nothing to compact": Pi's
  note is shown as a plain message and the plan runs. If a compaction really fails, the
  plan card keeps its Accept so you can approve the plan again. When the agent compacts
  its own context on a Pi session that is too short, it gets Pi's "nothing to compact"
  answer as an ordinary result instead of a failed tool call.
- Stop keeps working in a second window opened while a turn is running. After Stop, a plan
  or a sign-in card, the spinner and Stop button no longer come back for a turn that has
  ended, and a reply that hung can no longer end the next turn.
- Pressing Stop on Claude Code while a tool runs, or just after a steering message, no
  longer adds an Error box and "Stopped: the model provider returned an error"; it reads
  as an ordinary stop. A real provider error still shows its message.

**Approval cards**

- A permission request that a Stop refused no longer stays counted in the background or
  comes back as a live card after a restart; a Claude Code card is re-offered after a

- A Claude Code background agent waiting for your approval no longer raises a second,
  identical approval card about 30 seconds later that did nothing when allowed: you answer
  one card and the command runs. The agent panel now shows the agent's latest tool instead
  of a model-written phrase.
- An unanswered permission card no longer waits forever or ends the tool call after ten
  minutes blaming the host. The card is withdrawn on its own and the agent is told, in

  ended. An automation hook's card also disappears when the hook stops waiting, and on Pi

  appear after its turn has ended. The same happens when the chat's agent restarts and

- A card raised by background work, such as a Claude Code background task asking to watch
  a connection or a Codex subagent, stays until you answer it, and closes when that task
  or subagent ends or is stopped. When a Claude Code background worker ends — you stop it
  inside the app, a plugin it was using is removed, or a limit ends it — its pending

  stayed up to nine minutes.
- **Pi's Guardian judges every risky action in Bypass permissions and Auto.** It judged
  only the first one in a session; every later action raised a permission card, so
  unattended runs stalled until someone answered. Now each action is judged, the Guardian
  can check a file or folder before it answers instead of running out of turns, a verdict
  wrapped in a code block is read, it has up to 90 seconds to answer (up from 15), the same
  as Codex's own reviewer, so a slow start under load no longer turns into a card, and its

  the project: that card showed the planned command, but pressing Deny only refused the
  Guardian's look, not the command. It now decides without that access, and when it

  fails to load is shown on the session too: a rejected edit says the previous automations
  stay in effect, and a file that fails at startup says none of its automations are. Two
  saves of the automations file at the same moment no longer lose one of them.
- On Claude Code, a `UserPromptSubmit` hook that sets `sessionTitle` now renames the
  session, and a prompt such a hook blocks shows the hook's reason instead of a bare
  "Operation stopped by hook". On Codex, a hook whose matcher names an MCP tool
  (`mcp__<source>__.*`) now fires with the same tool name and arguments as on Pi,
  including a `PermissionDenied` hook on an auto-review denial. A hook that refuses an
  action now reads "blocked the action", not "failed", on Claude Code and Codex.

  `hooks` instead of `actions`, now loads and runs instead of being rejected. Its command
  hooks follow Claude Code's exit codes (only exit 2 blocks; exit 1 is reported as a hook
  error and the action goes ahead), and a command with an `args` list runs directly,
  without a shell; an http, MCP-tool, prompt or agent hook in such a file does not run,
  and a warning says so. A hook with no name is labelled by its event in error messages
  (for example "PreToolUse:Bash hook error"), as Claude Code labels it, instead of the
  generic "Automation".
- A plugin's agent hook now runs every time it fires in a Pi session, also after the
  session has started a subagent, and no longer uses up the session's subagent limit, so
  after many hook runs the agent can still start its own. An agent hook's verifier no
  longer shows you permission cards: anything it asks permission for is refused, and it
  decides from what it can read.

**Memory**

- Codex memory now works like the other runtimes. Asking it to remember something for this
  project works, turning "Remember from this chat" back on works straight away, and
  turning memory off stops it even when your config folder has been moved. A moved memory
  folder (`autoMemoryDirectory`) is where your user memories go. Choosing a project folder
  or moving the plans folder partway through a Codex chat takes effect in that chat. A
  memory saved for the session, and the files the session tools write (data transforms,
  templates, `script_sandbox`, the to-do list), now go into the session's own folder on
  Codex, as on Pi and Claude Code: the memory is loaded back into the session, the files
  are removed with it, and switching the chat between runtimes keeps them together. On
  Claude Code, turning memory on or off for a chat reaches the running session at the next
  message.

**Plugins, marketplaces and sources**

- **After you add a marketplace, the Plugins page opens it** (a 1.40.0 known issue). If
  its catalogue is still loading or could not be fetched, the page says so, and "Some
  marketplaces could not be loaded." shows whichever marketplace you are viewing.
- Installing or managing a plugin while a Codex session is open no longer tells the agent
  the install failed when it succeeded, and an install that could not refresh an open
  session says so instead of announcing the plugin as active. If refreshing one open
  session fails, the other sessions still take the change, the answer says which sessions
  need a restart (in your workspace only), and the failed session retries at its next
  message instead of failing every later one. Removing a source from inside a chat reports
  the same way.
- **One MCP tool with a broken schema no longer takes its server down.** A tool whose
  input schema Pi cannot compile, that misuses a date or format limit, that lacks the MCP
  tool shape, or that repeats another tool's name is skipped with its reason; the server's
  other tools keep working on every runtime, `/mcp` names each skipped tool (on Claude
  Code too), the MCP servers panel marks such a server "Some tools skipped" (hover it for
  which and why), and the agent is told. Before, such a tool made every prompt fail on Pi
  or stopped the server connecting; a Pi session whose tools repeat a name now keeps the
  first one and writes the repeat to the debug log. Tool lists cached by earlier versions
  are checked again before use, and testing an MCP source ends with "Validation passed
  with warnings" when some of its tools cannot be loaded (the warning names them) or its
  server answers that it needs authentication. On Claude Code, a tool whose input schema
  has `anyOf`, `oneOf` or `allOf` at its root keeps its parameters and accepts a call in
  each of its alternative shapes, a tool whose argument takes a fixed list of numbers (or
  of numbers and words) shows those choices to the model and can be called, and a tool's
  text result shows as text instead of a JSON list of content blocks.
- A switched-off MCP server's page says it is switched off instead of showing the code
  `source-disabled`, which every built-in `dp` server you had not switched on showed, and
  it no longer keeps showing the server's tools for a few minutes once you reopen it. If
  a source's connection fails during a session, the agent is told, even when the source
  was last saved as connected.
- A Codex plugin whose MCP server allows tool calls longer than a day (for example
  OpenAI's codex-security) now installs with that server instead of deferring it, and a
  very long MCP tool timeout (over about 24 days) no longer makes every tool call fail at
  once.
- A plugin install planned from a repository link now says the repository has not been
  checked yet (it is fetched and checked when you install), so a link to a repository that
  does not exist is no longer presented as verified, and after **Inspect URL** the Plugins
  page no longer shows a check mark.
- **A marketplace entry and a plugin's own `plugin.json` combine as in Claude Code.** An
  entry can no longer add MCP servers, language servers or configuration options to a
  plugin that ships its own `plugin.json`, nor its default agent setting or monitors, and
  the install says which entry fields were ignored; when an entry adds hooks to such a
  plugin, they replace the plugin's hooks only for the events the entry names. An entry
  with `strict: false` (needed for `headersHelper`) now installs a plugin whose
  `plugin.json` lists its components, and such an entry that lists components of its own
  is refused as a conflict. Hooks an entry lists as a file path or an array no longer run;
  the plugin still installs, and its details say those hooks are not loaded. An entry that
  declares only output styles is now recognised as a Claude plugin. For a plugin without a
  `plugin.json`, the entry's default agent setting and monitors now apply, and the
  commands, agents, output styles or workflows it lists now replace the plugin's matching
  default folder instead of loading beside it. **For such a plugin already installed,**
  the default folder's items stop loading at its next install, update or repair, and the
  plugin shows that the default folder is not scanned.
- "Send to workspace" shows its title, buttons and messages in the app's language, counts
  only the items actually sent, and says why something was not sent.

**Runtimes and models**

- Pi: when the model's reply stream breaks off partway (a dropped gateway or endpoint
  connection), the turn now ends with an ordinary error instead of crashing the Pi runtime
  with "Pi subprocess exited unexpectedly".
- **Plan mode can write and submit its plan on Pi and Claude Code.** In Plan the agent's
  plan file was refused ("File modifications are blocked in Plan"), SubmitPlan then
  answered "Plan file not found", and on Pi no mode could write it, so **Accept Plan** and
  **Accept & Compact** were out of reach. The agent now writes its plan into the session's
  own plans folder in Plan and Accept edits with no protected-folder card; in Plan every
  other write stays blocked, apart from the session's data folder. On Pi the agent can
  also read the files you attach to a chat, which were refused as "Managed Nessy
  storage", and a revised plan it submits after your feedback now opens a new plan card
  instead of being refused: submitting a plan or a sign-in request now stops the Pi run
  that made it, so that run no longer carries on into the turn where you answer it.
- **The agent can use its own session folder.** It now writes into the session's own
  folder (plans, data, scratch, downloads, and the files a session without a project
  creates there) without the protected-folder card, on Pi as on Claude Code, and on Codex
  Plan lets it write its plan and data files there without asking. The session's
  transcript and attachments, and the records Nessy and Pi keep there (such as Pi's saved
  conversation and carried history, turn anchors, the workflow journal and rewind
  snapshots), stay protected; on Pi the agent can read a large tool result it saved
  there, as the result preview says, while writes to those saved results stay refused.
  With a moved data folder, a write into the workspace folder now asks, as it already did
  in the default location. A Pi session with no project folder is told the folder its
  tools actually work in, so it no longer tries to write into the protected session
  folder.
- Pi's Find and Grep tools work in the installed app on a computer without its own
  ripgrep: they use the copy that ships with Nessy Desktop, and a ripgrep you installed
  yourself still comes first. Pi's Find now reads patterns the way upstream Pi does: `*`
  stays within one folder, `{ts,tsx}` and `[ab]` work, `lib/*.ts` finds matching folders
  at any depth, a `**/` pattern also finds files at the top of the searched folder (so
  `**/*.md` includes `README.md`), a lower-case pattern ignores case while an upper-case
  letter makes it exact, and a plain name must match the whole file name.
- On Pi, a tool loaded on demand can be called from the model's next step in the same
  request, and it stays loaded in later messages. A loaded built-in such as web search
  answered "not found" however often it was loaded, and a change to the tool list
  unloaded every loaded tool; now only a tool that was removed or whose definition changed
  is unloaded, and a loaded tool stays loaded when the Pi process restarts after a source
  or settings change. The list of tools not yet loaded updates at once within the same
  reply, and a tool loaded mid-request shows its live progress and receives a
  `PreToolUse` hook's added context, like any other tool.
- **Pi and your project's tooling.** Pi now loads subagents from a trusted project's
  `.claude/agents` folder instead of answering "Unknown agent". Post-edit checks, the
  format tool and plugin language servers run in your project folder. A plugin language
  server now sees the file you ask about and later edits to it, a request that names no
  language goes to the server that claims the file's extension, the post-edit check sends
  the edited text and waits briefly for its diagnostics, and a server that only pushes
  diagnostics returns them instead of failing.
- On Claude Code, an agent in a trusted project's `.claude/agents` folder named planner,
  reviewer, scout or worker now replaces Nessy's bundled agent of that name, with its own
  hooks and MCP servers, instead of being hidden by it.
- On the **Claude Code (Nessy Gateway)** card, and any Claude Code card pointed at an
  OpenAI-compatible endpoint, the `call_llm` tool works: it asked the gateway for a Claude
  model the gateway does not serve and failed every time with "There's an issue with the
  selected model". It now runs on the card's fast model when the requested model is not
  one the card serves.
- Editing a connection's endpoint during a chat now re-applies the external-model MCP
  rules straight away: moving outside the perimeter withholds the servers, and moving back
  returns them. The log a packaged build keeps now records which servers were withheld and
  why (the external-model rules, a `dp` sign-in or an administrator's policy) and which
  upstream a model's requests go to.
- **Claude Code and background tasks.** A background subagent started in your first
  message no longer dies when you send the second one; the app had been restarting
  Claude's session at the second message of each app run, also when the chosen effort is
  above what the model supports. When a background subagent
  finishes after its turn has ended, its task shows as finished, Claude's answer appears
  in the chat with its tool calls, the session shows it is working (spinner and Stop), and
  Stop interrupts it. A message you send meanwhile waits its turn and gets its own answer,
  instead of landing inside that answer or shifting the replies by one, also when two
  background tasks finish close together, and messages sent at that moment no longer stay
  stuck in the queue; a message sent while Claude answers a finished task on its own
  keeps the spinner and Stop when it starts. The completion reaches Claude once, and a
  tool call from such an answer no longer shows as running forever if the Claude process
  ends.
- After a chat leaves Claude Code, or any Claude runtime restarts, the permission mode
  shown is the one actually enforced; a chat in Bypass permissions no longer asks as if it
  were in Manual. `NESSY_SUBAGENT_MODEL` applies on Claude Code as a default: a subagent
  that names its own model keeps it, as on Pi. A Claude Code session's utility model no
  longer leaks into Pi or Codex sessions started after it, and a Claude Code chat in an
  app started from a Claude Code terminal no longer inherits that terminal session's
  markers, so it no longer behaves as if it were nested in, or were, Claude Desktop.
- Starting a worktree subagent in a repository that has no commit yet now tells you to
  make a first commit, instead of showing git's "ambiguous argument HEAD" error.
- **Codex.** Under an organisation policy that allows only Codex's reviewer (or only you)
  to answer approvals, Codex turns no longer fail with "invalid thread settings override";
  Plan turns are refused with a sentence naming the policy, and the session says so
  when it starts. Under a policy that allows only the reviewer, the reviewer also answers
  in Manual, Accept edits and Don't ask, and the session's note says so. When the
  unattended-automation check cannot run, the conversation says the change went on to
  Codex's next approval step; when it cannot be confirmed, the session note says the
  hook was not found or could not be trusted, and names a managed-hooks-only policy when
  Codex reports one; and a refusal that cannot tell who turned the reviewer on names both
  possibilities and a remedy that works for either. A
  Codex session whose runtime could not be fully shut down during a plugin refresh retries
  at the next message instead of failing every later one.
- **Codex sessions.** When the app itself refuses a file change, a tool call or a shell
  command, the assistant no longer tells you that you declined it, and it points you to
  Settings → Permissions or the permission mode. Turning Codex auto-review off in Settings
  now takes effect in open Codex sessions from the next message (turning it on still
  applies to sessions started afterwards), and a session started while the app still
  remembered an older organisation policy that kept auto-review out now says the
  unattended-automation check does not hold in it, when the current policy lets the
  reviewer answer. With your home folder (or any folder containing Nessy's settings
  folder) as the project, changes to unattended automations are no longer refused in
  every mode. A workspace under a folder like `~cfg`, or one whose name starts with a
  space, starts normally and keeps its records read-only. A session with an added working
  directory no longer quietly restarts its conversation thread on its first message; a
  turn right after a permission-rule or effort change no longer fails with "codex thread
  re-fork did not answer", and while Codex re-opens its thread for changed settings the
  turn says so instead of showing nothing. A session no longer adds a "Model metadata …
  not found" row on every turn, and its sandbox-mode notice is written in normal sentence
  case and is not repeated when the runtime restarts. Codex runtime folders left behind by
  a closed or crashed app are removed when the next Codex session starts.
  A Codex chat now continues its own conversation after the app restarts or the chat has
  sat idle, instead of starting a fresh thread that has not seen it (if Codex cannot pick
  the conversation up again, the chat says so), and branching a Codex chat gives the
  branch the conversation it was branched from; a chat's conversation files are kept
  until you delete the chat. A Codex session moved to another project folder now uses
  that folder's trust decision.
- **Pi on the Nessy Gateway and OpenAI-compatible endpoints.** A reply the provider made
  the runtime retry now appears in the chat with "Retrying…" instead of the chat ending on
  an error, and the failed attempt's half-written text disappears. When retries run out
  you get one "Connection Error" or "Service Error" with a Retry button, an overloaded
  provider switches to your fallback model, no stale "Retry failed" line follows into the
  next turn, and a retry no longer counts against a turn limit. A reply no longer loses
  its text, tool call or ending when the relay sends them in an unusual shape, a malformed
  `tool_calls` object no longer fails the turn, and Pi no longer sends `store: false`,
  which strict providers rejected. A Nessy Gateway quota error no longer promises an
  automatic retry: it says the quota is used up and suggests switching model or waiting
  before resending. When the gateway rejects a saved sign-in, the chat says the
  credentials were rejected instead of claiming the token expired.
- **Pi sign-ins and Amazon Bedrock.** Stored sign-ins such as ChatGPT Plus (behind its
  build flag) work in the packaged app, not only in development builds. A Bedrock
  connection with IAM keys authenticates again and uses only its own keys: an AWS session
  token, a Bedrock bearer token or `AWS_BEDROCK_SKIP_AUTH=1` exported in the shell that

  AWS setup keeps honouring the flag, and its bearer token is no longer sent when the flag

- **Pi: Stop and background model calls.** After Stop, a `/compact` still waiting behind

  hook. A failed title generation or `call_llm` no longer cancels other background model
  calls, a timed-out one is actually stopped, one still running when the session
  re-initialises or shuts down is cancelled instead of running on under the old
  credentials, and title and summary generation on a busy gateway retry within their time
  limit. A turn that ends on a plan or a sign-in card now adds its tokens and cost to the

  tokens and cost, not only the last one's. A turn you stop, from the chat or the agent

**Network and proxy**

- **Codex and Claude Code follow your proxy.** A proxy set in your environment (on macOS
  including your login shell) or in a managed settings `env` block, with its
  `NODE_EXTRA_CA_CERTS`, now carries Codex and Claude Code model requests; before, only Pi
  sessions followed them. A managed proxy takes precedence over the in-app setting, which
  takes precedence over the environment. The browser pane, update downloads and sign-in
  windows now follow the same choice instead of the in-app setting alone.
- Client certificates set in the environment (`CLAUDE_CODE_CLIENT_CERT` and
  `CLAUDE_CODE_CLIENT_KEY`) or in a managed `env` block now work for Codex and Claude Code
  requests in the desktop app and the headless server: a managed one comes first and a
  certificate set in Settings comes before the environment, and the headless server no
  longer drops a CA set in Settings when they are set. A cancelled request through the
  app's network layer now cancels the upstream request too.

  are sent and received unmodified, as in the desktop app, and `NESSY_CUSTOM_HEADERS` go

## KNOWN

- **In Manual mode a never-granted read-only command still runs without asking.** The
  read-only allowlist is what the mode trusts, on every runtime (Plan runs it too); an
  edit still asks. To be asked about a read-only command as well, add an ask rule for it.
  This is the documented posture, not a defect.
- On Claude Code, after Stop, a steering message you sent can sit both in the paused queue
  and back in the composer, so pressing Enter after **Resume** has sent the queued copy
  sends it a second time. Clear the composer before you press Enter.
- On Pi, a `/compact` you start yourself shows no progress label and no Stop button, so it
  cannot be stopped from the chat; it runs to the end.
- With **Codex auto-review** turned on, every review on the **Codex (Nessy Gateway)** card
  fails, because the gateway does not serve the reviewer's model, so each action the
  reviewer would decide is refused. Leave auto-review off on that card.
- Windows and Linux builds stay parked until those release channels reopen.
