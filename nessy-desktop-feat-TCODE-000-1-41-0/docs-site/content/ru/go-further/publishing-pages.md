# Публикация страниц

Nessy может опубликовать страницу, которую написала сессия, — файл `.html`, `.htm` или `.md` — во внутреннем сервисе артефактов компании (t-artifacts) и выдать ссылку.

## Как это работает

- Попросите агента опубликовать страницу или поделиться ею. Сам агент никогда не публикует — самое большее предлагает.
- Публикация из предпросмотра: у HTML- или Markdown-предпросмотра файла в чате есть кнопка «Опубликовать»; она показывает ту же карточку подтверждения, что и publish_artifact агента, с предпросмотром ровно того, что будет отправлено, и ничего не отправляется до вашего одобрения. Кнопка не предлагается для предпросмотра без файла, а сессия, которая не может показать карточку (режим «Не спрашивать», дочерняя сессия агента, ход, начатый автоматизацией или расписанием), отказывает.
- Каждая публикация и каждое обновление показывают карточку подтверждения — в любом режиме разрешений, включая Bypass. В карточке видно, кто сможет открыть страницу, когда истечёт ссылка, файл, его размер, предпросмотр ровно того, что будет отправлено, число скриптов, внешние хосты, с которых страница что-то загружает, и результат автоматической проверки на токены и номера карт. Одобрение нельзя запомнить; карточка без ответа через 110 секунд считается отказом.
- По умолчанию ссылка живёт 7 дней. Агент может попросить от 1 до 30 дней; более долгий или бессрочный срок задаёте вы в приложении.
- Агент видит страницы, опубликованные его собственной сессией, и может заменить содержимое страницы, сохранив ссылку.
- Одинаково работает в Pi, Claude Code и Codex.

## Что отклоняется

Файлы с учётными данными и `.env`, файлы вне папок сессии, всё, кроме `.html`/`.htm`/`.md`, страницы больше 16 МиБ, страницы с токенами или номерами карт, поля паролей и формы — и любая публикация, которую некому одобрить: режим «Не спрашивать», субагенты, запуски из автоматизаций, расписаний и продолжений цели.

Собственный инструмент Claude Code `Artifact` (публикует на claude.ai) отключён; его вызов уходит в ту же карточку. В Pi и Claude Code команда оболочки, обращающаяся к сервису или к навыку `artifact-publish`, отклоняется с подсказкой использовать инструмент публикации. Навык `artifact-publish` в комплект не входит.

## Что важно знать перед одобрением

1. Карточка — это ваше согласие на этот путь, а не сетевой барьер: агент, которому доступны команды оболочки и сеть, может обратиться к сервису или к любому другому сайту напрямую. В Codex команды оболочки на это вообще не проверяются.
2. Публикация отправляет ваш токен входа dp (dp auth print-token, учётные данные всей платформы) в сервис t-artifacts по адресу https://t-artifacts.t-tech.team, который распознаёт вашу личность через devplatform. Nessy запрашивает у dp токен при каждом запросе и никогда его не хранит. Это никогда не ваш токен Nessy Gateway, ничего из ~/.nessy/dp_auth_creds.json и никогда не ARTIFACT_AUTH_TOKEN / T_ARTIFACTS_TOKEN из окружения. Когда dp сможет выпускать делегированный токен для этого сервиса, Nessy перейдёт на него.
3. Любой в сети компании, у кого есть ссылка, откроет страницу без входа, а её исходник можно скачать по id. Удаление закрывает ссылку, но копии, которые читатели сохранили, и резервные копии сервиса не отзываются.
4. Скрипты страницы выполняются в браузерах ваших читателей.

## Опубликованные страницы

Настройки → Рабочее пространство → Опубликованные страницы показывают все страницы, которые ваш аккаунт dp опубликовал в t-artifacts, — из этого рабочего пространства (с чатом и файлом, откуда они пришли) или откуда-либо ещё. Откройте страницу или скопируйте ссылку, продлите её срок (7, 30, 90 дней, год или без срока — дольше 30 дней можно задать только здесь, но не агенту) или удалите. Удаление закрывает ссылку для всех; копии, которые читатели уже сохранили, и резервные копии сервиса не отзываются. Если удаление не может достучаться до сервиса (например, dp разлогинен), страница остаётся в списке как «Ожидает удаления» и повторяется при следующей загрузке списка после вашего входа.
