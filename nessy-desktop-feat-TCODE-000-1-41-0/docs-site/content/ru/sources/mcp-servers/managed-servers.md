# MCP-серверы организации

Администратор может выдать всем пользователям один и тот же набор удалённых MCP-серверов через
managed policy, ключом `managedMcpServers`. Пользователи эти серверы не добавляют и не настраивают:
они доходят до каждой сессии — на Pi, Claude Code и Codex одинаково, — и пользователь не может
заменить или удалить ни один из них. Имя ключа и форма записи — те же, что у одноимённой настройки
Claude Code.

## Что пишет администратор

### Где лежит policy

`managedMcpServers` — ключ той же host-owned managed policy, что описана в разделе
[Managed Pi policy](../../core-concepts/permissions#managed-pi-policy):

| Платформа | Файл policy |
| --- | --- |
| macOS | `/Library/Application Support/Nessy/managed-policy.json` |
| Linux | `/etc/nessy/managed-policy.json` |
| Windows | `%ProgramFiles%\Nessy\managed-policy.json` |

На Windows policy, оставленная в прежнем месте `%ProgramData%\Nessy`, игнорируется, потому что этот
каталог доступен на запись обычным учётным записям; диагностика называет место, куда её перенести.

Несколько команд могут поставлять каждая свою часть отдельным `.json`-файлом в каталоге
`managed-policy.d/` рядом с файлом policy. Файлы читаются в порядке имён. Серверы с разными именами
складываются; более поздний файл, называющий тот же сервер, заменяет запись этого сервера целиком, а
не поле за полем.

Когда Nessy Gateway доставляет managed policy, несущую хоть одну настройку, вместо файла действует
доставленная policy. `managedMcpServers` она несёт точно так же, и список из файла к ней не
добавляется. Кладите ключ в тот источник, из которого приходят остальные ваши managed-настройки.

Ключ сопоставляет имени сервера форму удалённой записи `.mcp.json`:

```json
{
  "schemaVersion": 1,
  "managedMcpServers": {
    "corp-docs": { "type": "http", "url": "https://mcp.corp.example/docs" },
    "corp-events": {
      "type": "sse",
      "url": "https://mcp.corp.example/events",
      "headers": { "X-Team": "platform" }
    }
  }
}
```

### Правила для записей

Каждая запись проверяется сама по себе, и отклонённая запись отбрасывается, не затрагивая остальные:

- **Только удалённые серверы.** `type` — `"http"` или `"sse"`. Ничто, что называет программу для
  запуска (`"stdio"`, `command`), не принимается.
- **`url`** должен быть URL вида `http://` или `https://`.
- **`headers`**, если есть, сопоставляют именам заголовков строковые значения.
- **Никаких ссылок `${VAR}`** — ни в URL, ни в заголовках.
- **Только `type`, `url` и `headers`.** Запись с любым другим полем отклоняется целиком, а не
  переносится частично.
- **Имена** состоят из букв, цифр, `_` и `-`, не длиннее 64 символов (`__proto__`, `constructor` и
  `prototype` отклоняются). Имя используется в именах инструментов как есть.
- **Не больше 64 серверов.** Значение, которое не является объектом или перечисляет больше 64
  серверов, отбрасывает весь ключ.

### Как проверить, что отклонено

`nessy-general-agent doctor` перечисляет каждую отклонённую запись из файлов policy с её
файлом-источником, полем (`managedMcpServers.<name>`) и причиной и завершается с кодом 1, если нашёл
хоть одну, — см. [doctor](../../reference/cli#doctor-проверка-конфигурации).

## Как их получает каждый runtime

Ни один из трёх runtime не подключается к этим серверам сам. Собственный MCP pool Nessy подключается
к каждому из них и передаёт его инструменты сессии так же, как любой сервер пула: Claude Code — через
отдельный in-process proxy на каждый сервер, Pi — через proxy-инструменты пула, Codex — через один
агрегированный сервер пула, который ему выдаётся (`[mcp_servers.sources]`). Все три читают один и тот
же набор, поэтому смена runtime у сессии не меняет, какие серверы организации у неё есть.

У Claude Code есть собственная настройка `managedMcpServers`, и её попробовали первой. Измерено на
поставляемом Claude Code 2.1.267: сервер, переданный через канал managed settings в Agent SDK —
единственный managed-канал, который есть у встраивающего приложения, — не получил ни одного
подключения, а тот же сервер, переданный как обычный MCP-сервер, подключился. Этот канал сохраняет
только ограничивающие настройки и отбрасывает добавляющие, как эта, поэтому пул хоста — единственный
путь доставки.

## Какие правила к ним применяются

- **Запись организации забирает своё имя.** Если пользовательский, проектный или плагинный сервер
  использует то же имя, в сессии его заменяет сервер организации.
- **`deniedMcpServers` по-прежнему действует.** Managed-запись deny, совпавшая с сервером организации,
  не пускает его ни в одну сессию.
- **`allowedMcpServers` не обязан их называть.** Managed allowlist, в котором их нет, их не блокирует.
- **Внешние модели теряют их, как любой другой сервер.** Сессия, чья модель отвечает вне Nessy
  Gateway, сохраняет только короткий разрешённый список, описанный на странице
  [Внешние модели и MCP-инструменты](./external-models).
- **Имя, совпавшее со встроенным dp-сервером.** Сервер организации с именем
  [встроенного dp-сервера](./overview#встроенные-mcp-servers), который у вас включён, заменяет его и
  работает, даже пока `dp` требует входа, — уступает именно встроенный сервер под этим именем, а с
  требованием входа удерживаются только встроенные серверы, которые организация не назвала.
- **Разрешения работают, как для любого MCP-инструмента.** Инструменты называются
  `mcp__<name>__<toolName>`, и каждым вызовом управляют [режим разрешений](../../core-concepts/permissions)
  сессии и её правила.

## Что видит пользователь

- **Инструменты — в каждой сессии.** Инструменты организации предлагаются рядом с собственными
  инструментами пользователя, на всех трёх runtime.
- **Строка только для чтения в панели MCP-серверов.** У каждого сервера организации одна строка в
  **Sources → MCPs**, и она открывает страницу сервера. Переключателя у строки нет, поэтому её нельзя
  выключить, изменить или удалить из приложения.
- **Нет входа.** Для них нет слота учётных данных и нет OAuth-потока: статические `headers` в policy —
  единственная аутентификация, которую может нести запись.

Для операторов лог приложения записывает каждое решение, которое убирает или заменяет сервер:
`managed_org_mcp.denied: <names>` — для серверов, которые не пустила запись deny, и
`managed_org_mcp.displaced_configured_server: <names>` — для настроенных серверов, которые заменила
запись организации.
