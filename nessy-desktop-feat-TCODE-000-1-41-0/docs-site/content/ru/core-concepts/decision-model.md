# Модель решений

Модель решений — необязательный помощник, который отвечает на короткие типизированные вопросы вероятностями: «это сообщение поправляет текущую работу или это новая просьба?», «какая из этих меток подходит?», «закончил ли этот ответ дело?». Это классификатор, а не чат-модель. Она не пишет текст, не вызывает инструменты и ничего не запускает. Nessy Desktop спрашивает её в нескольких местах, которые выбираете вы, и считает каждый ответ советом.

По умолчанию она **выключена**. Пока она выключена, никуда ничего не отправляется, и каждая функция на этой странице работает ровно так же, как до появления модели решений.

## Как включить

Откройте **Настройки → AI → Модель решений (Jev)**:

1. Включите **Включить модель решений**.
2. Выберите **Провайдер** (см. таблицу ниже). Для облачного провайдера вставьте его API-ключ и нажмите **Сохранить ключ** или выберите **Использовать ключ из …**, чтобы взять ключ уже настроенного подключения OpenRouter или Vercel AI Gateway.
3. Нажмите **Проверить** в блоке **Проверка подключения**. Проверка отправляет один заранее заданный вопрос «да/нет» и показывает модель и задержку или причину ошибки. Она работает и при выключенном переключателе, так что провайдера можно проверить заранее.
4. Откройте **Расширенные настройки** и выберите, для чего использовать модель решений.

Ключ хранится в зашифрованном локальном хранилище учётных данных и никогда не попадает в `config.json`.

## Провайдеры

| Провайдер | Адрес | Ключ | Куда уходит ваш текст |
| --- | --- | --- | --- |
| TypeSafe AI (direct) | `https://api.typesafe.ai` | обязателен | облачный сервис TypeSafe |
| OpenRouter | `https://openrouter.ai/api` | обязателен; можно взять ключ подключения OpenRouter | OpenRouter, затем модель TypeSafe |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/typesafe` | обязателен; можно взять ключ подключения Vercel AI Gateway | Vercel, затем модель TypeSafe |
| Laya (local, open source) | `http://127.0.0.1:8000` | не обязателен | никуда: работает на вашем компьютере |
| Custom (Jev-compatible server) | адрес, который вы укажете | не обязателен | на указанный вами сервер |

- **Laya** — сервер с открытым кодом (Apache 2.0), который вы запускаете сами. Карточка показывает команду установки и запуска `pip install "laya[serve]" && laya-serve`, проверяет, доступен ли сервер, и перечисляет загруженные им чекпоинты. Запустив сервер, нажмите **Проверить**.
- **Custom** принимает базовый адрес любого сервера с тем же протоколом; `/v1/systemone` добавляется сам.
- У каждого провайдера закреплён идентификатор модели, поэтому провайдер не может незаметно сменить отвечающую модель. Модель, о которой сообщил провайдер, записывается рядом с закреплённой.
- **Провайдера Nessy Gateway нет.** Шлюз обслуживает чат-модели, а не такой классификатор. Токен Nessy Gateway никогда не уходит провайдеру решений: запрос несёт только сохранённый вами ключ модели решений или не несёт ключа вовсе.
- При смене провайдера собственный адрес и модель прежнего провайдера сбрасываются, так что ключ никогда не уходит на адрес, настроенный для другого провайдера.

## Для чего она используется

У каждого применения свой переключатель в **Расширенных настройках**. Три включены по умолчанию, потому что срабатывают, только когда их что-то вызывает; остальные меняют поведение приложения сами по себе и поэтому выключены.

| Переключатель | По умолчанию | Что меняет ответ |
| --- | --- | --- |
| **Инструмент агента (decide)** | вкл. | Агент получает инструмент `decide`, чтобы за один вызов классифицировать, распределять или оценивать элементы — например, разложить много писем по папкам. Действует для новых сессий. |
| **Вердикты задач** | вкл. | Если проверяющий шаг задачи забыл строку `VERDICT:`, уверенный «пройдено» или «не пройдено» читается из ответа и показывается как выведенный, с вероятностью. Настоящая строка `VERDICT:` всегда главнее. |
| **Семантические правила меток** | вкл. | Метки, у которых правило — вопрос «да/нет», ставятся по смыслу. См. [Правила автоприменения меток](../labels/auto-rules#семантические-правила). |
| **Итог хода** | выкл. | Открытая сессия, последний ответ которой ждёт вас (вопрос, препятствие), переходит в **Needs Review**, а причина видна под её названием. В запуске задачи шаг, который застрял или задал вопрос, не отмечается выполненным. Статус, который вы поставили сами, и закрытую сессию модель не меняет. |
| **Метки риска** | выкл. | Карточка разрешения показывает, что делает действие: удаляет данные, отправляет данные наружу, публикует, затрагивает секреты, меняет систему, тратит деньги. Кнопки и ваш выбор не меняются. См. [Метки риска](./permissions#метки-риска). |
| **Условия автоматизаций** | выкл. | Автоматизация может нести вопрос «да/нет», ответ на который должен быть «да», прежде чем она создаст сессию. См. [Автоматизации](../automations/overview#семантическое-условие). |
| **Точечные исправления задач** | выкл. | Если упавшая проверка не называет сломанные шаги, исправляются только шаги, на которые она указывает, и зависящие от них. |
| **Умные названия** | выкл. | Светская беседа вроде «привет» не получает автоматического названия, пока вы о чём-то не попросите, а автоматическое название, которое перестало подходить, обновляется. Название, которое вы задали сами, не трогается. |
| **Сообщения во время работы** | выкл. | Сообщение, отправленное во время работы агента, для каждого сообщения отдельно либо вклинивается в текущий ход, либо встаёт в очередь. См. [Отправка во время ответа агента](./interactions#когда-решает-модель-решении). |
| **Подсказки навыков и источников** | выкл. | Перед обработкой сообщения агент может получить подсказку на один ход с названием одного источника, который настроен, но не активен в этой сессии и явно нужен вашему сообщению. Подсказываются только источники: навыки и так перечислены для агента на каждом рантайме. Ничего не включается за вас; решает агент, с вашими обычными разрешениями. |

## Чего она никогда не делает

- **Она ничего не разрешает.** Ответ может добавить сведения, добавить шаг, который ждёт вас, или выбрать между двумя поведениями, которые в приложении уже были. Он никогда не превращает карточку разрешения или отказ в разрешение.
- **Нет ответа — нет изменений.** Тайм-аут, сетевая ошибка, ошибка провайдера или некорректный ответ считаются отсутствием ответа, и приложение делает то, что сделало бы без модели решений.
- **Быстро или никак.** Фоновые проверки по умолчанию ждут 1,5 секунды (провайдер, который давно не отвечал, получает на первый вызов немного больше). Две проверки, связанные с отправляемым сообщением, — подсказка источника и вклинивание сообщения посреди хода — ждут не дольше 3 секунд, а сообщение посреди хода сразу встаёт в очередь, так что отправка не задерживается. Инструмент агента `decide` ждёт до 10 секунд.
- **Метки риска не могут одобрить.** Карточка ждёт свои метки не дольше фонового срока. Если к их приходу на карточку уже нельзя ответить — вы уже ответили, сессия остановлена, — запрос отклоняется, а не разрешается.

## Что отправляется и что хранится

Отправляется только текст, нужный конкретной функции, и только выбранному вами провайдеру:

- Семантические правила меток: каждое ваше сообщение в рабочем пространстве, где есть такое правило, — первые 8000 символов без блоков кода. Сообщения короче 20 символов не проверяются, а про метку, которая у сессии уже есть, модель больше не спрашивают.
- Итог хода: начало запроса и конец ответа.
- Метки риска: имя инструмента, описание с карточки и команда.
- Условия автоматизаций: событие, его поля и последние сообщения пользователя и ассистента в сессии.
- Сообщения во время работы: запрос, над которым идёт работа, и ваше новое сообщение.
- Подсказки: ваше сообщение и названия с описаниями не более 60 неактивных источников.
- Инструмент `decide`: то, что передаёт ему агент.

Каждая проверка записывается в `logs/decisions.jsonl` в каталоге конфигурации: функция, провайдер, модель, вероятности и время. Отправленный текст **не** хранится — только его отпечаток и размер. Текст ошибки провайдера тоже не хранится, потому что он может повторять запрос. Когда журнал превышает 10 МиБ, сохраняется один предыдущий файл.

Под каждым переключателем карточка показывает последние семь дней: сколько было проверок, сколько из них что-то изменили и сколько завершились ошибкой. После 30 проверок с ответом, которые ничего не изменили, карточка так и пишет — функцию, которая вам ничего не даёт, легко заметить и выключить.

## Когда изменения вступают в силу

- Фоновые функции читают переключатели при каждой проверке, поэтому включение или выключение действует со следующей проверки.
- Инструмент **decide** предлагается, когда в сессии запускается агент, поэтому его включение доходит до новых сессий. В Codex список инструментов фиксируется при старте потока. Выключение модели решений действует сразу: сессия, у которой инструмент ещё остался, получает ответ «не включено», и ничего не отправляется.

## На каждом рантайме

Всё описанное работает в приложении, а не в рантайме агента, поэтому сессии Pi, Claude Code и Codex ведут себя одинаково. Инструмент `decide` предлагается на всех трёх; в Codex он доходит до приложения через тот же мост, что и остальные инструменты сессии.

## Удалённые клиенты и headless-сервер

Выбрать, куда уходит ваш текст, — провайдера, базовый адрес, используемое подключение и ключ — может только окно десктопного приложения на этом компьютере. Удалённый клиент, включая [терминальный клиент](../reference/cli), может читать настройки и включать или выключать модель решений и её функции, но запрос на смену адреса или ключа отклоняется.

У headless-сервера нет окна, поэтому провайдера, адрес и ключ задаёт его оператор в `config.json` этого сервера, в разделе `decisionLayer`:

```json
{
  "decisionLayer": {
    "enabled": true,
    "provider": "laya",
    "baseUrl": "http://127.0.0.1:8000",
    "features": { "semanticLabels": true, "turnOutcome": false }
  }
}
```

`provider` — одно из `typesafe`, `openrouter`, `vercel-ai-gateway`, `laya` и `custom`. Переключатель, который вы не указали, сохраняет значение по умолчанию.
