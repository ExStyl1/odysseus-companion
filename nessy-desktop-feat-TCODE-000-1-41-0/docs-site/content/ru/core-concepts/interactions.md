# Взаимодействия

Сообщение в chat input — основной способ говорить с агентом, но не единственный. Nessy Desktop также позволяет inline подключать sources и skills, прикладывать files, steer или queue follow-up messages и управлять sessions из sidebar.

## Mentions

Используйте `@` mentions внутри message, чтобы добавить source или skill в диалог без открытия settings.

### Source Mentions

Введите `@` и имя source, чтобы направить агента к нему:

```text
"Check @linear for my open issues"
"Look in @docs-kb for the deployment runbook"
"Read the latest rows from @analytics-db"
```

Mention source активирует его для диалога, поэтому агент получает tools этого source на текущий turn без ручной настройки. См. [Sources](../sources/overview), чтобы подключить их.

### Skill Mentions

Skills работают так же — сослитесь на один через `@`, чтобы вызвать его:

```text
"Run @daily-standup"
"Use the @code-review skill on this branch"
```

Также можно вызвать skill через bracket syntax (`[skill:code-review]`) в любом месте message.

### Session Mentions

Живые sessions попадают в тот же список `@`, и каждая строка называет runtime,
на котором session работает, — так можно адресовать другой диалог по имени:

```text
"Ask @auth-refactor whether the migration landed"
"Tell @'release sitting' the gate is green"
```

В отличие от source или skill вставляется обычный `@name`, без bracket token.
Имя — это текст, который читает *модель* и передаёт своему cross-session
message tool; поэтому имя с пробелом или любым символом вне букв, цифр, дефиса
и подчёркивания заключается в кавычки автоматически.

Одно однозначное живое имя доставляется по самому имени, без промежуточного
запроса списка sessions. Если на имя отвечает больше одной живой session, агент
спросит, какая имелась в виду, вместо того чтобы выбрать сам; такие строки
говорят об этом в списке ещё до вставки, потому что имена, сгенерированные
приложением, на уникальность не проверяются. Имя, за которым нет живой session,
отклоняется по имени, а не теряется молча.

Переименование session вами — проверяется: если имя занято, оно остаётся у той
session, которая его уже носит, ваше становится вариантом с двухсловным
суффиксом вида `auth-refactor-graceful-unicorn`, и вам об этом сообщают.

::: tip
Когда вы вводите `@`, появляется autocomplete list с доступными sources, skills и живыми sessions. Выберите пункт, чтобы вставить mention.
:::

## Slash Commands

Введите `/` в начале ввода, чтобы вызвать встроенные команды. Две из них важны
для работы с кодом:

- **`/code-review`** запускает выделенный adversarial code review диффа. По
  умолчанию он смотрит коммиты вашей ветки поверх её upstream плюс любые
  незакоммиченные изменения; чтобы проверить что-то другое, передайте target —
  имя ветки, ref range вида `main...my-feature`, один или несколько путей к
  файлам, либо один коммит. Он спавнит read-only reviewer с рубрикой и
  возвращает структурированные findings, отсортированные от самых серьёзных
  (P0–P3), каждое со ссылкой `file:line` и категорией: `correctness` или
  `test-coverage` для бага, `reuse`, `simplification` или `efficiency` для
  cleanup. Добавьте `--fix`, чтобы применить findings к рабочему дереву после
  review. Двух вещей эта сборка не умеет: номер pull request не является
  допустимым target, а `--comment` не может публиковать inline-комментарии в PR —
  GitHub-интеграции здесь нет. Алиаса `/review` нет — используйте полное имя.
- **`/init`** инспектирует репозиторий и пишет стартовый гайд проекта `AGENTS.md`
  (команды build/test, структура, соглашения) в корне проекта. Если `AGENTS.md`
  уже существует, он сохраняется — агент предлагает дополнить или улучшить его на
  месте, а не перезаписывать, и файл пишется через обычный permission-gated tool
  path.

Четыре session-команды управляют самим диалогом:

- **`/btw <вопрос>`** задаёт быстрый side question о текущей работе, не
  добавляя его в историю диалога. Ответ появляется в закрываемом overlay над
  composer и никогда не попадает в transcript, так что можно уточнить деталь,
  не расходуя context. Side questions видят весь диалог, но не имеют доступа к
  tools и работают даже пока агент занят turn'ом. Они работают и на чате,
  который ещё не начат: side question запускает агента чата так же, как это
  сделало бы обычное сообщение, а вопрос и ответ по-прежнему не попадают в
  transcript. У панели есть собственный composer, так что спрашивать можно не
  выходя из неё: набранный внутри `/btw` — это просто следующий вопрос (префикс
  отбрасывается), а `/recap` и `/heapdump` там остаются текстом, потому что оба
  действуют на настоящий диалог, а панель — намеренно нет. Панель — это
  переписка: каждый вопрос и его ответ остаются в ней по порядку, самые свежие
  внизу, ровно как в обычном чате — ранние ответы больше не собираются тусклым
  списком над текущим, и переключаться между ними не нужно. Запустите `/btw`
  без вопроса, чтобы снова открыть панель. Внутри `c` копирует последний ответ
  как raw Markdown, `x` очищает переписку, а `Escape` закрывает панель. `Space`
  и `Enter` тоже закрывают, но только из тела панели — при открытии фокус
  уходит в composer, так что ввод никогда не съедается.
- **`/recap`** генерирует однострочное summary того, что произошло в session —
  показывается в том же overlay; удобно, когда возвращаетесь после перерыва.
- **`/clear`** сбрасывает диалог до пустого context: следующий prompt начинает
  свежий диалог без прежней истории. Предыдущий диалог остаётся на диске в
  session storage. В Nestor Cloud session он также сбрасывает remote-диалог,
  так что следующий prompt начинается с чистого листа и на стороне cloud.
- **`/quota`** показывает остаток бюджета на gateway этого подключения: по
  каждому лимиту — сколько осталось в процентах, собственное сообщение gateway
  о состоянии лимита и время сброса, когда сервер его отдаёт. Команда доступна
  на всех подключениях, которые сообщают quota: в Nestor Cloud sessions и на всех
  трёх карточках Nessy Gateway (Pi, Claude Code и Codex). Бюджет у них общий,
  персональный, поэтому все три карточки показывают одни и те же цифры, а Stop
  отменяет чтение. На подключении к собственному endpoint такого бюджета нет,
  поэтому команда скрыта из slash menu. На карточке
  [ChatGPT (Codex)](../reference/config/llm-connections#chatgpt-codex), которая
  входит в Codex через ваш аккаунт ChatGPT, `/quota` доступна и спрашивает сам
  Codex: показываются окна использования этой подписки (доля израсходованного,
  длина окна, время сброса, план и кредиты), а когда Codex runtime не запущен —
  окна, которые Codex сообщил последними, с пометкой об этом. На подключении
  Codex к собственному endpoint набранная вручную `/quota` объясняет, почему окна
  недоступны.

`/compact` (см. [Длинные диалоги](/ru/core-concepts/conversations#длинные-диалоги))
и meter'ы `/usage` и `/context` дополняют набор. `/usage` и `/context` больше не
только для Pi: сессия Claude Code или Codex теперь может сказать, какие
`CLAUDE.md`, `CLAUDE.local.md` и файлы правил действительно загрузились, а там,
где рантайм не публикует разбивку по категориям, оверлей об этом пишет, а не
показывает пустоту. Число выходных токенов в `/usage` появляется, когда ответ
завершён: на каждом рантайме оно сообщается один раз, в конце ответа, а не
растёт по мере стриминга текста, поэтому неподвижная строка **Выход** посреди
ответа — это ожидаемое состояние, а не зависшая сессия.

С этим релизом появилось ещё несколько команд, на всех рантаймах, если не указано
иное:

- **`/branch`** форкает диалог на месте и переключает вас в ветку — см.
  [Диалоги](/ru/core-concepts/conversations#ветвление-диалога).
- **`/diff`** сводит рабочее дерево и открывает патч в просмотрщике. Дифф можно
  комментировать: комментарии, привязанные к строкам, доходят до следующего хода
  одной пачкой.
- **`/hooks`** перечисляет hooks, которые эта сессия действительно запустит, с
  группировкой по событию, с matcher'ом, типом обработчика и файлом-источником у
  каждого, на любом рантайме. История запусков показывает каждый hook, сработавший
  в этой сессии: prompt, agent, MCP-tool и HTTP hooks наравне с command hooks, hooks,
  выполненные внутри сессии Claude, и hooks, которые запускает само приложение
  (например, `MessageDisplay`). Hook, который не смог запуститься, показан с
  причиной. Если все hooks выключены (`disableAllHooks`), ответ — "No hooks will
  run in this session."
- **`/config`** читает и меняет настройку прямо из промпта, по объявленному
  списку разрешённых ключей. Раньше её предлагало меню и не обрабатывал никто,
  так что набранный `/config` доходил до модели как текст.
- **`/status`** говорит, к чему сессия подключена на самом деле: base URL,
  источник credential, провайдер и прокси.
- **`/simplify`** и **`/security-review`** едут рядом с `/code-review`, а
  уровень усилий, на котором идёт ревью, запоминается между сессиями, а не
  сбрасывается каждый раз.
- **`/mcp`**, `/help`, `/config` и `/diff` теперь отвечают в несколько строк, и
  строку с ответом можно выделить и скопировать — раньше они схлопывались в один
  абзац.
- **`/tasks`** перечисляет фоновую работу этого чата — запланированные
  автоматизации, наблюдения и задачи, которые идут прямо сейчас, — и оставляет
  ответ в транскрипте, так что к нему можно вернуться через несколько ходов.
- **`/workflows`** открывает вид прогресса workflow, а **`/workflows stop`**
  останавливает все фоновые агенты, запущенные этим чатом. Обе формы разбирает
  само приложение, поэтому они означают одно и то же на Pi, Claude Code и Codex —
  до 1.40.0 ни один из этих токенов не разбирался нигде, и оба доходили до модели
  как обычный текст.

## File Attachments

Передать файлы агенту можно тремя способами:

- **Drag and drop** — перетащите files прямо на chat input
- **Paste** — вставьте image или file из clipboard
- **File picker** — нажмите attachment button и выберите file

Агент обрабатывает большинство распространённых форматов:

| Type | Examples | Что может сделать агент |
| ---- | -------- | ----------------------- |
| **Code** | .py, .ts, .js, .go, .rs | Прочитать, review, refactor, explain |
| **Documents** | .pdf, .docx, .xlsx, .pptx | Extract text, summarise, convert |
| **Images** | .png, .jpg, .svg, .webp | View, describe, resize, convert |
| **Data** | .json, .csv, .xml, .yaml | Parse, analyse, transform |
| **Notebooks** | .ipynb | Read cells, outputs и figures |

Image attachments отправляются только когда active model поддерживает image input.

### Ограничения размера

Вложения уходят на сервер приложения одним сообщением, поэтому поле ввода проверяет их размер до отправки:

- **Один файл** больше предела отклоняется сразу при добавлении, ещё до чтения, с уведомлением, где названы файл и его размер.
- **Набор файлов**, слишком большой вместе, отклоняется при нажатии «отправить»; сообщение и вложения остаются в поле ввода, так что можно убрать часть или отправить их отдельными сообщениями.
- Предел — **`73.4 MB`** в десктопном приложении и **`11.7 MB`** при подключении к [headless-серверу](/ru/server/headless), который принимает сообщения меньшего размера. Сервер сообщает приложению свой предел при подключении; для старого сервера, который этого не делает, принимается меньший.
- Изображение засчитывается в общий размер не больше чем 5 MB, потому что большие изображения перед отправкой уменьшаются.

До этой проверки вложение сверх предела обрывало соединение, и все запросы в работе завершались ошибкой «Connection lost».

**PDF в Claude Code.** PDF размером до 10 MB передаётся модели как документ, когда подключение обращается к API Anthropic напрямую. PDF большего размера и любой PDF на подключении, чей адрес не говорит на API Anthropic напрямую, — в том числе на карточке **Claude Code (Nessy Gateway)**, — передаётся путём, по которому приложение его сохранило, и агенту предлагается прочитать его инструментом Read, а большой файл — по диапазонам страниц. Сессии Pi всегда получают PDF по пути.

## Отправка во время ответа агента

Follow-up можно отправить в любой момент — даже mid-turn, пока агент streaming reply или выполняет tool. Как будет обработано это message, решается per **AI connection**; есть два behaviours:

| Mode | Что происходит | Когда использовать |
| ---- | -------------- | ------------------ |
| **Steer** | Ваше message доставляется в running turn, чтобы агент заметил его до завершения | Нужно перенаправить задачу на лету ("actually, do it in Python") |
| **Queue** | Текущий turn завершается без изменений; ваше message проигрывается как следующий turn | Нужно добавить follow-up, не нарушая уже идущую работу |

### Defaults

Default зависит от backend, который использует connection:

- **Nessy Gateway и другие Pi-backed providers** по умолчанию используют **steer**. Pi steers natively without discarding work — ваша заметка попадёт после завершения текущего tool call, и уже вычисленная работа не теряется.
- **Codex connections** по умолчанию используют **steer**. У Codex runtime есть свой steer, и он строже — а это в вашу пользу: запрос называет ход, для которого предназначен, поэтому поправка, адресованная уже сменившемуся ходу, будет отклонена, а не применена к чужой работе. Два вида хода steering не принимают — review и compaction, — и отклонённое по этой причине сообщение уходит в очередь, а не теряется.
- **Claude connections** по умолчанию тоже используют **steer**. Здесь steering эмулируется: ваше сообщение доходит до модели при её следующем вызове инструмента. Если до конца хода вызова инструмента больше нет, ход сначала завершается, а ваше сообщение выполняется следующим ходом — ничего не теряется, цена — токены этого хода.
- **Nestor Cloud connections** по умолчанию используют **queue**: удалённый агент не умеет принимать сообщение посреди хода.

**Сообщение с вложениями всегда ставится в очередь, какой бы режим ни был у connection.** Steer переносит только текст, поэтому файлы уходят вместе с сообщением в следующем ходе. Кнопка отправки для такого сообщения подписана **Queue** («В очередь»). В строке очереди Steer и Edit для него выключены (с подсказкой): иначе файлы потерялись бы. Когда ход заканчивается, сообщение отправляется вместе с файлами — даже после перезапуска приложения. Текстовое сообщение, отправленное после него, тоже ждёт за ним, так что порядок остаётся тем, в каком вы писали.

### Переопределение на одно сообщение

**Alt/Option + Enter** отправляет набранное сообщение *другим* способом —
вклиниванием на подключении, которое ставит в очередь, и в очередь на том,
которое вклинивает, — не меняя настройку подключения. Композер подписывает, что
именно сделает аккорд. Это обычное переназначаемое действие, так что его можно
изменить или отключить на странице Shortcuts. Сообщение с вложениями аккорд
вклинить не может — оно всегда ставится в очередь.

### Когда решает модель решений

Если включён параметр **Сообщения во время работы** (Настройки → AI → **Модель решений (Jev)** → **Расширенные настройки**; см. [Модель решений](./decision-model)), текстовое сообщение, отправленное посреди хода, сразу ставится в очередь, так что отправка никогда не задерживается. Затем модель решений определяет, поправляет ли оно идущую работу. Поправка переходит из очереди в текущий ход так же, как при вклинивании, если идёт всё тот же ход и рантайм может принять её в этот момент. Отдельный follow-up остаётся в очереди. Если уверенного ответа нет, действует режим подключения.

Два сообщения в очереди, которые модель считает одной просьбой (например, «когда будешь создавать событие позже,» и «назови его Team day»), отправляются вместе одним ходом. Ни одна из половин не вклинивается отдельно. Модель никогда не пересматривает сообщение с вложениями, команду workflow, сообщение, отправленное с переопределением **Alt/Option + Enter**, и сообщение, отправленное после Stop.

### Изменение режима

**Умолчание достаётся только новым подключениям.** Режим записывается на подключение при его создании, поэтому уже существующее сохраняет то, с чем было создано, даже если умолчание для этого бэкенда позже изменилось. Так сделано намеренно: приложение не может отличить сохранённое значение, пришедшее из умолчания, от выбранного вами — и молчаливая перезапись отменила бы настоящее решение. Если в релизе объявлено новое умолчание и оно вам нужно, выставьте его здесь один раз.

Эта настройка хранится на самом connection, поэтому каждая session, использующая connection, наследует её. Переключайте когда нужно — switch применится при следующей mid-stream отправке. Underlying config field описан в [LLM Connections](../reference/config/llm-connections).

::: tip
Если сомневаетесь, оставьте default. Для спокойного follow-up оба режима приходят к одному результату — разница важна только когда вы активно перенаправляете всё ещё running task.
:::

## Остановка работы

Используйте stop control, когда turn нужно завершить сразу. В CLI отправка `SIGINT` (Ctrl+C) команде `run` просит server отменить session и завершает процесс с code `130`; `SIGTERM` завершает процесс с code `143` и сразу останавливает turn, но не записывает для него результат, так что возобновление продолжает его. См. [CLI reference](../reference/cli) для полного lifecycle.

Если при нажатии Stop в очереди ждёт следующее сообщение, очередь приостанавливается: баннер «Очередь приостановлена: вы прервали ответ» с кнопкой **Возобновить**, и ничего не отправляется, пока вы не решите. Остановленный запрос в поле ввода не возвращается. Сообщение, отправленное после Stop, пока ход ещё завершается, ставится в очередь и никогда не вклинивается в останавливаемый ход.

Если поле ввода пустое, `Up` во время хода действует как Stop и возвращает остановленный запрос в поле ввода. Если вы очистили черновик двойным `Esc`, `Up` вернёт этот черновик, а ход продолжится.

**Stop завершает ответ, а не фоновую работу.** Задачи, которые уже выполняются в фоне, продолжают работать и сообщают о завершении: в Pi долгий вызов MCP, переведённый в фон до нажатия Stop, доставляет результат позже; в Claude Code и Codex фоновые агенты и команды продолжают работать так, как их ведёт рантайм. Чтобы завершить одну из них, используйте её чип — см. [Фоновые задачи](#фоновые-задачи).

## Фоновые задачи

Работа, которую агент перевёл в фон, — долгая команда, фоновый агент, workflow — видна как чип над полем ввода: со спиннером, пока она идёт, и с отметкой, когда она завершилась.

Нажмите на чип, чтобы открыть его карточку:

- **Команда** показывает конец своего вывода, который обновляется, пока она работает («Показан конец вывода», если вывод обрезан).
- **Агент** показывает число шагов, последние шаги и последнее сообщение.
- **Открыть** показывает весь вывод в отдельном окне, **Копировать** копирует его, **Скрыть** убирает чип, а **Остановить** завершает только эту задачу — пока она не завершится, на чипе написано **Остановка…**.

Что карточка может показать, пока задача идёт, зависит от рантайма: управляемые команды Pi и фоновые команды и агенты Claude Code читаются вживую; фоновый терминал Codex во время работы прочитать нельзя, поэтому его чип показывает только состояние. Завершённую задачу, оставившую вывод, по-прежнему можно открыть. `/tasks` тоже перечисляет эту работу в переписке.

## Управление сессиями

Имя, которое вы дали сессии, сохраняется: с 1.38.0 переименование при создании доходит до диска, как и любое другое изменение, а переключение рантайма имя не теряет.

Каждый диалог — session, и вы управляете ими из sidebar.

### Flagging

Отмечайте sessions, к которым хотите вернуться. Flagged sessions показывают marker flag и доступны через filter.

### Archiving

Архивируйте finished или dormant sessions, чтобы sidebar оставался аккуратным. Archived sessions исчезают из default view, но остаются доступными через filter.

### Read / Unread

Session помечается unread, когда агент создаёт новый output, пока вы на неё не смотрите. Открытие session помечает её read.

### Batch Operations

Выберите несколько sessions, чтобы одним действием изменить их status, toggle labels, flag or unflag, archive или delete. См. [Conversations](../core-concepts/conversations#batch-operations) для полного списка.

### Уведомления о фоновых сессиях

Включите **Настройки → Внешний вид → Уведомления о фоновых сессиях**, чтобы видеть в углу поля ввода значок, когда сессия, которую вы сейчас не смотрите, завершает ход. Нажмите на него, чтобы открыть эту сессию. По умолчанию выключено и запоминается только на этом компьютере.

## Панель Agent Runtime

Выбор модели называет, откуда взят список — каталог Nessy Gateway или собственный эндпоинт подключения, — чтобы два похожих списка не путались.

Диалоги на встроенном Pi runtime (включая подключение Nessy Gateway) показывают runtime-панель в правом sidebar. Она отражает живое состояние агента во время работы:

- **Задачи и план** — список задач агента, ожидающие вопросы и элементы утверждения плана
- **Цель** — активный контракт завершения, жёсткие лимиты ходов/tokens/cost/time и состояние settled, blocked или completed
- **Субагенты** — фоновые дочерние агенты со статусом, расходом токенов и управлением steer/stop
- **Процессы** — supervised фоновые команды с выводом и остановкой
- **Checkpoints** — файловые checkpoint'ы перед правками с откатом в один клик
- **Receipts** — ограниченные и очищенные результаты execution с корреляциями process, workflow, checkpoint, child и goal
- **Контекст и безопасность** — использование контекста, состояние compaction, ожидающие permissions и активный isolation profile

Панель — это read-only проекция плюс явные элементы управления; она никогда не обходит permission mode диалога.

Cross-session **Agent View** показывает Pi sessions workspace, включая состояния
working/needs-input и runtime-residency hot, cold, recovering, updating или lost.
Из него можно открыть session либо отправить owner-checked stop/resume; Nessy
показывает невозобновляемую работу как lost и не перезапускает её молча.

## Keyboard Shortcuts

Escape закрывает любой открытый диалог панели чата — меню rewind, панели агентов, контекста и использования — и прерывает идущий ход только когда ни один диалог не открыт.

Nessy Desktop поставляется с shortcuts для частых actions. Откройте shortcuts reference из app menu (**Keyboard Shortcuts**). Часто используемые bindings:

| Action | Notes |
| ------ | ----- |
| New Chat | Открывает свежий conversation |
| Cycle Permission Mode | **Shift + Tab** проходит по режимам |
| Send message | Настраивается в **Settings → Input** |
| Stop | Завершает текущий turn агента |
| Keyboard Shortcuts | Открывает этот reference |
| Отправить другим способом | **Alt/Option + Enter** — один раз вклиниться на подключении с очередью или один раз поставить в очередь на вклинивающем |
| Убрать текущую задачу в фон | **Ctrl/Cmd + Shift + B** — дать ходу продолжиться, не дожидаясь вызова инструмента, на котором он застрял |

::: note
Send shortcut настраивается в **Settings → Input**, а набор режимов, по которым проходит **Shift + Tab**, можно сузить в **Workspace Settings**.
:::

Любое сочетание в списке переназначаемо, и переназначение, которое не может быть
принято — конфликт или непонятное приложению написание, — теперь сообщает об
этом, а не уходит в лог. Правка `preferences.json` руками вступает в силу без
перезапуска.

**Страницу Shortcuts можно спросить в обе стороны.** Строка поиска фильтрует
список по названию команды на языке интерфейса, а обратный поиск записывает одно
нажатие и называет все команды, привязанные к нему, — включая честное «к этому
сочетанию ничего не привязано». Обратный поиск и уведомление о конфликте при
переназначении — одна и та же проверка, поэтому они не могут разойтись в ответе
на вопрос, кому принадлежит аккорд.

**Уход в фон для застрявшего хода** работает там, где рантайму есть куда деть
задачу: на Claude Code аккорд переносит вызов инструмента в фон, ход
продолжается, а результат приходит в диалог, когда задача завершится. На Codex
нажатие отклоняется по имени, а не проходит впустую. На Pi `/code-review` и так
возвращает композер сам.
