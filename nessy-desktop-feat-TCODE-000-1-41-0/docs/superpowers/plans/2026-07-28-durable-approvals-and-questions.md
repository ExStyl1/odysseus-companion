> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (a) Batched `AskUserQuestion` (1–4 questions × 2–4 options) with the documented answer envelope and `askUserQuestionTimeout` semantics replacing our fixed 5-minute expiry-as-error; (b) durable approvals — a pending permission prompt survives restart and resume re-fires it; (c) `defer` as a `PreToolUse` hook decision for the headless surface, terminating the run with `tool_deferred` and re-firing on resume. Order (a)→(b)→(c): the spec says implement the interactive pending-forever approval first, defer second.

## Global Constraints

- One commit per task; no `Co-Authored-By`; no MR/tags; never reset/rebase/amend; pathspec-limited commits; do not touch `docs/superpowers/specs/`, the audit, or the CDP checklist; you may edit this plan file. Implementation-First Verification Budget. Tests from the repo root (CONFIG_DIR guard).
- **Questions never expire by default.** `askUserQuestionTimeout` default `"never"`, values `"60s"|"5m"|"10m"|"never"`; read from **USER settings only — explicitly never project or local** (a checked-in repo must not be able to auto-answer questions); on expiry **auto-continue with whatever is already selected + an away note — never a tool error**. Our current 5-minute expiry-as-error is the documented-opposite divergence (§5e-1 item 4) — this plan removes it.
- **Permission prompts, including plan approval, NEVER auto-resolve on idle.** The timeout applies to AskUserQuestion only.
- Settings key goes through the strict envelope: add to `StoredConfigKnownFields` (validators.ts) + disk round-trip test through `loadStoredConfig` (the R4 brick class).
- **Answer envelope, exactly**: result echoes `questions` verbatim + `answers` keyed by question TEXT → selected `label` (multi-select: array or ", "-joined string) + optional free-text `response` which replaces the per-question list with "The user responded: …" neutral wording.
- `AskUserQuestion` reaches the approval callback even when an allow rule matches; **denied outright without the callback in `dontAsk` mode**; unavailable in subagents.
- **`defer` (headless only)**: interactive sessions log a warning and ignore it; only when the turn contains a single tool call (else warn + normal flow); on defer the tool does not execute, run terminates success with `stop_reason: "tool_deferred"` + `deferred_tool_use: {id,name,input}`; `reason`/`updatedInput`/`additionalContext` ignored for defer; precedence `deny > defer > ask > allow`; no timeout/retry limit; resume re-fires PreToolUse for the same call, answer delivered as `updatedInput` on allow; tool gone on resume → `stop_reason: "tool_deferred_unavailable"` + `is_error: true`; resume restores the deferred-time permission mode except `plan`/`bypassPermissions` (never) and `auto` (only if still qualified).
- Back-compat: existing single-question `ask_user` calls keep working (the batched shape is a superset); `PiPendingAskUserV1` gains a versioned superset or a v2 beside it — old persisted pendings must still hydrate.
- Renderer strings i18n'd in ALL locales; new card states added to the playground registry (playground-design-surface rule).
- The recurring defect count is TWELVE. Every surface here spans subprocess ↔ host ↔ renderer. Assert through production seams; the last three units each shipped one of these (consent template selection, snapshot emission, listing-vs-load). Live re-drive is the planner's pass 11 — leave the checklist alone but list your uncovered live cases.
