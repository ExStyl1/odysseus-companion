## Shared rules

Identical to `docs/superpowers/plans/2026-09-02-wave-1-brief.md` §"Shared rules" — every lane reads
that section and `AGENTS.md` first. Three lessons wave 1 added, binding here:

- **A section of a file is not a zone.** Two lanes splitting `config-writer.ts` by section could read
  it and could not commit it (P3.273). Zones are whole files; stage 0 splits the one file that needed it.
- **Locale files are shared by every lane that touches i18n.** A lane's pathspec commit of `en`/`ru`
  takes every other lane's uncommitted keys. Before committing a locale file, `git diff` it against
  HEAD and commit only your keys; say in the body which foreign keys you saw. Duplicate keys pass both
  lints.
- **A row that names a file outside the lane's zone is a zone change, and it is declared before the edit, not after.** W2-f's `/help` arm landed in `pi-agent.ts`, W2-k's declared exclusive file, mid-wave; nothing was swept, by luck. When a row turns out to need a file another lane holds, STOP and report — the controller re-zones or sequences.
- **Run mutation harnesses as a background script with the restore inside it**, never as a foreground
  tool call — a 120 s tool timeout after the forward write leaves the tree holding the mutant. Assert
  the baseline hash before reading any verdict. **And (W2-a, stage 1): take a lock so two harness runs
  cannot overlap (a killed mutant read as a survivor when they did), start it detached (`nohup`) so the
  10-minute tool timeout cannot kill it mid-mutation (it did), and check restoration post hoc against
  the baseline hash — the killed run never printed its "restored" line.**

Every lane: Opus 5 (`model: "opus"`, verified in the transcript), report to the session scratchpad,
return status / shas / test file-count / in-place fixes / new findings with the scope filter applied.
