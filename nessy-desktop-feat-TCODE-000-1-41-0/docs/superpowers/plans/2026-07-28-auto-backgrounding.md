**Goal:** A timed-out Bash command and a slow main-conversation MCP call move to the background-task registry with a task id + output-file handle instead of losing the work — against the documented contract (doc-verification § R10), not "a handle".

- One commit per task; no `Co-Authored-By`; no MR/tags; never reset/rebase/amend; pathspec-limited commits; no edits to `docs/superpowers/specs/`, the audit, or the CDP checklist; you may edit this plan file. Implementation-First Verification Budget. Tests from the repo root (CONFIG_DIR guard).
- **The Bash timeout message, verbatim shape** (seconds must equal the applied timeout): `Command did not complete within its <N>s timeout and was moved to the background` + the task id + **the output file path** + `Session cwd remains <dir>; directory changes made by the backgrounded command do not apply to subsequent commands.`
- **A command starting with `sleep` is never auto-backgrounded** (it times out exactly as today).
- **MCP**: threshold `NESSY_MCP_AUTO_BACKGROUND_MS` default 120000, `0` = off; on detach the model gets the task id IMMEDIATELY (the tool result), the real result arrives as a **task notification** when the call settles; wall-clock (`timeout`/`MCP_TOOL_TIMEOUT`-equivalents) and idle limits keep applying to the detached call.
- **Never background**: subagent calls; headless runs unless `NESSY_AUTO_BACKGROUND_TASKS=1`; a call blocked on an open elicitation dialog is out of scope until R24 — record it as a named TODO comment at the detach site, do not build elicitation detection. (Claude's "IDE servers" exclusion has no Nessy counterpart — record N/A in the plan.)
- **`NESSY_DISABLE_BACKGROUND_TASKS=1` switches off ALL of it**: auto-background (both kinds), `run_in_background`, and the `bash_background` tool (removed from the manifest through the production filter, the R4 off-switch precedent).
- Backgrounded tasks do not survive session exit; never restored on resume (R3's monitor precedent — reuse, don't duplicate).
- The handle contract: task id + output-file path readable with the ordinary `Read`/`BashOutput` surface + `ProcessStop` to stop + the existing listing. No new dedicated output tool (that is the deprecated Claude shape).
- The recurring defect count is THIRTEEN (R7 added the settled-approval-never-resumes instance). The detach spans subprocess tool ↔ supervisor(host) ↔ registry ↔ notification. Assert through production seams: a detach that a unit performs on a mock supervisor but the real SIGTERM path still kills is THE defect. The live re-drive is the planner's pass 12.
- i18n for any renderer-visible strings; the timeout message itself is a WIRE/tool-result string — keep it English verbatim (contract text), consistent with R4's warning precedent.
