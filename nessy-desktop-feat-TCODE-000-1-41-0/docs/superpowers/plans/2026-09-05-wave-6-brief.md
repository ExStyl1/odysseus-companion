## Standing rules (restated from `docs/superpowers/plans/2026-09-04-wave-5-brief.md` §"Shared rules")

The wave-5 brief's shared rules apply in full, and they carry every earlier wave's rules. Restated
because each has already cost a real measurement:

1. **One commit per lane**, subject in the plan's voice (`<type>(<scope>): <sentence>`). The
   **tracker row is updated in the SAME commit that lands it** — glyph `✅`, the commit sha, and a
   note that says what was measured.
2. **No `Co-Authored-By` trailers.** Ever, in any project.
3. **Commit message via a file and `-F`.** `git commit -m "…"` with backticks in the message is
   command-substituted by zsh — house style quotes identifiers in backticks, and one lane's message
   swallowed a `` git ls-files `` span into a 5 921-line commit (measured 2026-09-03). Write the
   message to a file and pass `-F <file>`; never nest a backtick inside `-m`.
4. **`git commit <pathspec>` takes the file's WORKING-TREE state, not your hunks.** This is the whole
   reason the zones below are file-exclusive: two lanes touching one file commit each other's work.
   If you need a file another lane owns, **hand the patch to that lane** (patch text in your report),
   do not edit it. Declare any zone change before editing; `git status` beside every working-tree
   measurement.
5. **Implementation-first verification budget.** During the loop: focused tests for the changed
   behaviour, the affected package's typecheck, the directly affected contract tests, scope checks,
   `git diff --check`. Nothing else. The full gate runs once at the wave boundary, on the final tree.
   Read the **FILE COUNT** of every `bun test` run, never the pass count — `bun test` given a path
   that does not exist runs the rest and says nothing. Check the known-failing register
   (`docs/superpowers/specs/2026-07-29-known-failing-tests.md`) before recording a new red.
6. **Findings become plan rows AT CONFIRMATION** (owner rule, global 2026-08-23, amended
   2026-08-31): a defect, premise correction or refuted claim surfaced mid-lane goes into the plan
   the moment it is confirmed. A lane MAY fix a residue **in place** if it is **in-zone, under ~30
   lines and changes no contract** — and must report every such fix.
7. **A new row is inserted IN SORTED POSITION, never appended.** Run
   `python3 scripts/sort-plan-tracker.py docs/superpowers/plans/2026-08-22-runtime-parity-closure.md`
   after any row addition; `--check` reports drift without writing.
8. **Read, do not invent** (owner rule 2026-08-28). Nearest documented solution → reference
   implementation → ask the owner → invent, in that order. *"I could not find it documented"* is a
   finding to record, not a licence to invent — write what you searched. For **codex the SOURCE
   outranks the page** (`github.com/openai/codex`, tag `rust-v0.148.0` is what the shipped binary is
   built from); for **claude the documentation IS the contract** and a codex-style caution about
   pages must not be imported there.
9. **Native-first, and the host is the smooth seam** (owner rule 2026-08-28). Every lane records,
   per row, the answer to: *does the runtime already have its own mechanism?* — (1) enable and
   configure it, (2) else can the host supply it uniformly for all three, (3) else build per runtime
   and write down why 1 and 2 failed. **A native mechanism adopted without a switch verdict is a new
   silent divergence, not a closed gap.** Almost every row already carries a *"Native mechanism,
   asked and answered"* clause: the lane **confirms or corrects it at HEAD** and records the verdict
   in its report; it does not re-derive it from scratch, and it does not skip it because the row
   looks like plumbing.
10. **Re-measure at HEAD before building.** Every row here was born from a sweep measurement; a row
    that turns out closed at HEAD is a result to pin, not a reason to build.
11. **Report file: `scratchpad/lane-W6-<x>-report.md`.** One per lane, carrying: the row-by-row
    verdict; the native-mechanism answer per row; every in-zone residue fix (rule 6); every hand-off
    patch for a file another lane owns; and every new plan row proposed, with the reason.

### How the zones work in this wave, and why there are four groups

128 rows over four hot files makes strict, wave-wide file exclusivity impossible:
`SessionManager.ts` is written by **24** rows, `codex-agent.ts` by **24**,
`runtime-switch-costs.ts` by **12**, `claude-agent.ts` by **11**. One lane cannot hold 24 rows and
stay inside the 6–14 band.

So exclusivity is enforced **per parallel group**: the lanes inside a group have **pairwise disjoint
write sets**, verified mechanically (the check is at the bottom of this brief and prints `NONE` for
every group). A hot file may be re-owned by a lane in a **later** group, which is safe because the
groups run in sequence — the earlier owner has committed and released it. The dispatch table names,
for every lane after group 1, which lane released the file it now takes.

The last two groups are small on purpose. Six rows write **both** hot files (or three zones at once):
P6.101, P6.102, P6.106, P6.110, P6.151 and P6.184 each need `SessionManager.ts` *and*
`codex-agent.ts`. They cannot sit beside anything, so they are queued into two tail lanes rather
than allowed to freeze a wide group.

Two rows keep their lane but hand ONE file's hunk to the lane that owns it — both are tiny and both
are named at the row:

| Row | Lives in | Hands off | To |
| --- | --- | --- | --- |
| P6.100 | W6-b | the two comment lines at `codex-agent.ts:2278-2280` | W6-a |
| P6.69 | W6-d | the ≤30-line stale-comment sweep at `SessionManager.ts:15954-15960` (the row's own "in-zone residue") | W6-h |

Row-stated ordering constraints, honoured by the grouping: **P6.134 → P6.137** (the non-Pi producer
of the worktree gate context is a hard prerequisite); **P6.139 → P6.147** (settled by the same live
run, so P6.147 must not precede it); **P6.154 + P6.155 → P6.156** (the tier drop can only be
