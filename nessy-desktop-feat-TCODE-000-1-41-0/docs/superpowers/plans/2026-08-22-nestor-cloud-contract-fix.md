> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the `nessy_cloud` remote-agent integration directly on the backend's A2A **v1.0 wire** (`/api/v2/code-agent/a2a` — owner decision 2026-08-22: "планируем сразу на v2"), implement the backend's ACTUAL tool/extension contract, survive its failure modes (rate limits, stale tasks, dropped streams), and add a user-invocable `/quota` command — fixing the 5 confirmed blockers and the confirmed should/nice findings from `docs/superpowers/specs/2026-08-22-nestor-remote-agent-gap-analysis.md`.

**Architecture:** The v2 wire change is confined to the transport/codec layer (client request builder + stream event decoder): **the entire extension layer is shared between v1 and v2 on the backend** — both endpoints wrap the identical `requestHandler()` / `AgentExecutor`, and every metadata key, `data_type` value, error code, and card extension is byte-identical (`usecase_nessy.go:85-96, 196-207`; verified 2026-08-22, workflow `wf_c5e5dff5-fb7`). So the tool-contract, MCP, skills, suspension, retry, and budget tasks are wire-agnostic and sit on top of the v2 codec. Everything except the six-file `/quota` wiring and one URL-constants file lives in `packages/shared/src/agent/backend/nestor-cloud/**` + `packages/shared/src/agent/nestor-cloud-agent.ts`.

**Verification note:** contract facts below were extracted and adversarially verified against the backend/connector/a2a-go sources by two workflow rounds (`wf_0b24f1fb-271`, `wf_c5e5dff5-fb7`). Facts marked "settled" carry path:line and must not be re-litigated. ⚠️ One provenance gap: a2a-go citations are from `v2@v2.1.0` (the version in the local Go module cache) while the backend's go.mod pins `v2.3.1`; v2.1.0's own CHANGELOG shows the JSON discriminator keys churned within 2.1.0. Treat stream-envelope details as v2.1.0-verified — the codec must log-and-skip unknown envelope keys instead of throwing, and the close-out live day re-verifies the frames.

**Tech Stack:** TypeScript (Bun), bun test, existing nestor-cloud test harness (`__tests__/client.test.ts` et al., fixtures in `__tests__/fixtures/`).

## The v2 wire (normative, verified)

Both endpoints serve the same executor; the differences are ONLY these (a2a-go v2.1.0 + backend @ df526b7):

| Aspect | v1 (0.3-compat) — what we speak today | v2 (A2A 1.0) — what this plan builds |
| --- | --- | --- |
| POST URL | `/api/v1/code-agent/a2a` | `/api/v2/code-agent/a2a` (`handler.go:444-449`) |
| Card URL | `…/api/v1/code-agent/a2a/.well-known/agent-card.json` | `…/api/v2/code-agent/a2a/.well-known/agent-card.json` (`a2asrv/agentcard.go:27`); **requires `Nestor-Token`** like every route (`handler.go:335-343`) |
| Stream method | `"message/stream"` | `"SendStreamingMessage"` (`internal/jsonrpc/jsonrpc.go:34`) |
| Cancel | `"tasks/cancel"` params `{id}` | `"CancelTask"` params `{id}` (`jsonrpc.go:37`; `a2a/core.go:871-881`) |
| Extras | — | `"SubscribeToTask"` `{id}`, `"GetTask"` `{id, historyLength?}`, `"ListTasks"` (v2-only) — available, not used by this plan |
| `role` | `"user"` | **`"ROLE_USER"`** — a bare `"user"` passes validation and silently degrades to assistant (`mapping/message.go:93-101`) |
| Parts | `{kind:'text', text}` / `{kind:'data', data}` | flattened, discriminated by key presence: `{text}` / `{data}` / `{raw}` / `{url}`; **no `kind`, no `file`** (`a2a/core.go:672-716`) |
| Stream events | `{kind:'task'\|'message'\|'status-update'\|'artifact-update', …}` | oneof envelope inside `result`: `{"task":…}` / `{"message":…}` / `{"statusUpdate":…}` / `{"artifactUpdate":…}` (`a2a/core.go:93-109`) |
| Task states | lowercase `submitted`/`working`/… | `TASK_STATE_SUBMITTED` / `TASK_STATE_WORKING` / `TASK_STATE_INPUT_REQUIRED` / `TASK_STATE_COMPLETED` / `TASK_STATE_CANCELED` / `TASK_STATE_FAILED` / `TASK_STATE_REJECTED` / `TASK_STATE_AUTH_REQUIRED` / `TASK_STATE_UNSPECIFIED` (`a2a/core.go:272-292`; backend emits the first five — `a2a_environment.go:157-178`, `usecase_nessy_execution.go:73-100`) |
| `final` flag | present on status-update | **absent** — client computes `final = state ∈ {COMPLETED, CANCELED, FAILED, REJECTED, INPUT_REQUIRED}` (compat reference: `a2acompat/a2av0/conversions.go:485`; `Terminal()` at `a2a/core.go:327-332`) |
| Card fields | top-level `protocolVersion:"0.3"`, `url`, `preferredTransport` | **none of those** — validate via `supportedInterfaces:[{url, protocolBinding:"JSONRPC", protocolVersion:"1.0"}]` (`usecase_nessy.go:181-188`, `a2a/agent.go:124-136`) |
| Everything else | — | **identical**: auth header, SSE framing (`data:` = full JSON-RPC response, errors as `{error:{…}}` frames then stream end, HTTP always 200), all metadata keys and `data_type` parts, all ten card extension URIs incl. the `agent-settings` modes schema (byte-identical), `ToJSONRPCError` codes, in-band `-32029` retryable part + INPUT_REQUIRED, terminal-task rejection `-32602`/`data.error` |

Message shape (v2): `params.message = { messageId, role:"ROLE_USER", contextId?, taskId?, parts:[…], metadata:{…} }` — contextId/taskId/metadata all ON the message object (`a2a/core.go:196-224`); extensions go on MESSAGE metadata, not params-root metadata (`usecase_nessy_execution.go:181-206`).
