## How far to trust this map: it has been wrong in BOTH directions

The date in the header is not decoration, and this section exists because two audits (P5.2 on 2026-08-28, P2.307/P2.308/P2.310 on
2026-08-29) measured **three different classes of error** in a document built seven days earlier. They want different responses:

1. **Drift — a cell that was true and stopped being true.** Fourteen rows described a tree that no longer exists; Phase 3 landed
   almost entirely between the writing and the reading. This is what a dated measurement DOES, it is not a defect, and the repair
   is a dated `**HEAD <date>:**` clause appended to the cell rather than a rewrite — the 2026-08-22 measurement is still a fact
   about 2026-08-22 and deleting it would destroy the only evidence of when a thing landed.
2. **False when written — a cell that was never true.** TWO of them, rows 33 and 37, and both understated what we already ship:
   `config-writer.ts` was called the only `config.toml` writer while `pi-harness/isolation/windows.ts` had been writing one for
   31 days, and `.agents/skills` was called unread while both layers of the page's own table had been read for seven weeks.
   No amount of re-probing a cell's own numbers finds this class; only reading the claim against the tree does.
3. **The corpus moved under the map.** Nine pages had no row at all — see the header. A map's stopping rule is coverage of its
   denominator, so a denominator nobody re-fetches turns "every page gets a row" into a claim about the past.

**The governing fact for a reader: the errors ran in both directions.** Rows have been too red (a gap that was closed) AND too
green-adjacent (a claim of absence that was false). So a cell here is evidence, not authority — the same standing rule
`AGENTS.md` applies to every external reference now applies to this document. Re-probe before dispatching work off a cell.

**A corollary that has already cost a measurement: the line numbers in these cells are dead.** Row 33 cited
`packages/codex-responses-adapter/src/config-writer.ts` symbol `buildCodexConfigToml` for `buildCodexConfigToml`; on HEAD that function is at `:1322`, a drift of ~580 lines in seven days.
Cite the SYMBOL. A quoted sentence survives; a line number has a measured half-life of about two days.

**And five page SUBJECTS were rewritten upstream in the same seven days**, which no probe of our tree can see: `mcp-server` is now

## What each column is, and how far to trust it

Built by a 13-agent pass (10 mappers, 3 adversarial verifiers, all Opus 5): every page fetched and read, every claim probed
against HEAD with `rg -a` + a positive control on the same rig, citations counted over `docs/` and `AGENTS.md` for both URL hosts.
84 gap/not-our-surface verdicts were adversarially re-checked; 2 were refuted and corrected in place (`administration`,
`reference/troubleshooting` — noted in their cells). Probes exclude `apps/electron/resources/*` and `codex-protocol/{schema,generated}`:
bundled third-party artifacts and generated bindings poison grep results (measured in this pass and the w30/w32 pass alike).

The продукт context every verdict is judged against: our codex runtime is the bundled **app-server** driven over stdio JSON-RPC
(`packages/codex-agent-server`), config written by `packages/codex-responses-adapter/src/config-writer.ts`, wire through the
loopback responses-adapter to the Nessy gateway, session tools via the standalone `session-mcp-server`. Pages about the ChatGPT
app/web product, ChatGPT sign-in features, or Codex cloud are ⛔ only when the page itself pins the feature to those surfaces.

## Почему здесь НЕТ оси рантаймов

P5.0 разложил колонку `У нас` в Claude-карте на три (Pi / claude / codex), потому что там один глиф отвечал «реализовано
ГДЕ-ТО в продукте» и не мог сказать, кто снял контракт. **Здесь ось была бы вырожденной, и это следует из абзаца выше:**
колонка `У нас` этой карты уже односкоупная по построению — каждая клетка судит наш **codex-рантайм** (бандленный
app-server, `config-writer.ts`, loopback responses-адаптер, standalone `session-mcp-server`), потому что продуктовый
контекст всех вердиктов зафиксирован именно там. Добавить колонку Pi значило бы спросить «реализует ли Pi
`rules/*.rules` из Codex-доки» — вопрос, которого заявленная цель владельца не ставит: для codex она звучит как «рантайм
codex полностью покрыт НАШИМ хостом», и ровно на него эта колонка и отвечает, страница за страницей.

Поэтому здесь другое: колонка читается как **codex-колонка**, а не как хостовый вердикт, и `⛔` играет роль, которую в
Claude-карте играет `⬜`. Классы доказательств тоже сильнее и потому не выведены в маркеры клетки: этот файл собран
проходом, где **каждая страница прочитана целиком и каждое утверждение проверено пробой по HEAD с позитивным контролем**
(13 агентов, 84 вердикта пере-проверены адверсарно) — тогда как в Claude-карте ни одна страница для того прохода не
читалась, и именно поэтому там маркер `ᵗ`/`ᵏ`/`ʰ`/`ˢ` обязателен, а здесь избыточен. Per-runtime разбор ОБЩИХ хостовых
швов (хуки, гейт разрешений, managed-политика, песочница, скиллы, плагины, MCP, сессии, телеметрия) живёт в Claude-карте
— смотреть её колонку `codex` там, а не искать её здесь.
