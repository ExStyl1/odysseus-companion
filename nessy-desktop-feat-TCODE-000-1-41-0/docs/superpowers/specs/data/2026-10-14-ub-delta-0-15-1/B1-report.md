# B1 — upstream "decisions" delta v0.14.0 → v0.15.1, triaged against Nessy and the 1.43.0 draft

Read-only triage, 2026-10-14. Upstream is `.references/craft-agents-oss`, read by tag. Our tree is `feat/TCODE-000-1-41-0` @ `f495cf311`. The draft is `work/wi16/plan-1.43.0/plan-upstream-adoption-0-14-0.md`, which ports v0.14.0.

v0.14.0..v0.14.1 is one commit (`332533f3`, 67 files). Every one of those files is in my list, plus three files from v0.15.0: `decision-tone.ts` and `semantic-labels.ts` with its test. In v0.15.0 and v0.15.1, the decision layer itself changed only in `semantic-labels.ts`, `SessionManager.ts` (one hunk, the explicit thinking level) and the renderer `DecisionCard`/`decision-tone`.

Three facts frame the triage:

1. **Our fork has no decision layer.**
   - `ls packages/server-core/src/decisions packages/shared/src/decisions` returns "No such file or directory". Positive control: `packages/server-core/src/tasks` is listed by the same `ls`.
   - `git grep -E 'openDecisionPoint|decisionLayer|DecisionPoint' -- packages apps` returns 0 hits. Positive control: `git grep guardLargeResult` hits 10 or more files.
2. **The decision keys did not change after v0.14.1.**
   - en.json has 85 `settings.ai.decisions.*` keys at v0.14.1 and 85 at v0.15.1. v0.14.0 had 82; v0.14.1 added the three usage keys.
   - `git diff v0.14.1 v0.15.1 -- en.json` changes no `settings.ai.decisions` line.
   - The 13 feature toggles are identical at both tags.
3. **No shipped Nessy defect was found, so nothing is CRITICAL.**
   - Guarded mode's new fail-closed behaviour already holds in our `auto` guardian (B1-06).
   - The `_intent` regression (#1086) needs code we never shipped (B1-03).

Owner decisions taken as given:
- The decision layer is identical to craft v0.14.0. The answer to OQ-43.2/43.2b keeps all five presets, the master switch off by default, and upstream's gate order.
- OQ-43.4 (a) drops Guarded mode and DEC-10 drops adaptive thinking. Both come from manifest E and spec §6, and I did not re-open them.
