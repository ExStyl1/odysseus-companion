# Out-of-scope register

**Why this file exists.** On 2026-08-28 the owner narrowed the goal to the agent loop, and lanes were
told: a finding that fails the scope filter is **still recorded** — never silently dropped, because an
unrecorded finding is worse than an out-of-scope one. But "recorded" meant *in the lane's report*, and
lane reports live in a **session scratchpad under `/private/tmp`**, which does not survive the session.
So the instruction as issued would have lost exactly what it promised to keep. This file is the durable
home. Anything a lane files under `## Out of scope` in its report belongs here as well.

**The filter it is the other side of.** A finding becomes a plan row if ANY holds: (1) a tool call
passes through it; (2) it changes what the model is told, sees, or may do; (3) it differs between
runtimes at a switch. Two things are always in scope regardless of category: a control that **silently
stops controlling**, and any switch-visible difference.

**This is not a graveyard.** The goal can widen; a scoped-out finding is a measurement already paid
for. Anything here can be promoted to a plan row with no re-measurement. State what was measured, not
just what was suspected — a vague entry cannot be promoted and will be re-found at full cost.

**Mark what you promote, in the `Promote when` cell, naming the plan row that took it.** An entry
whose trigger has already fired reads exactly like one whose trigger is still waiting, so an
unmarked promotion gets promoted a second time — at the cost of re-measuring what was already paid
for, which is the one thing this file exists to prevent. A promoted entry STAYS here with its
measurement intact; it is the trigger that is spent, not the evidence.

**What does NOT belong here:** anything with a plan row (put it there), test failures caused by lane
contention (`docs/superpowers/specs/2026-07-29-known-failing-tests.md`), and owner-deferred work — that
is `DEFERRED-LAST` on its own row, because the finding stands and only the priority was ruled on.
