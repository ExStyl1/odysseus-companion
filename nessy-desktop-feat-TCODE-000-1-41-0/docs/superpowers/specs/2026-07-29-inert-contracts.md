## 5. What this says about the codebase

This is systemic, not scattered: the common cause is that Claude's documented schemas were implemented parse-first — declare the field, validate it strictly, carry it through the manifest and the composed policy — with the consumer deferred to a later slice that never landed, and the repo's own plan files say so in at least four places ("documented, not implemented"). The mechanical chokepoint is projection: `projectHook`, `RuntimeHookRegistration`, `RuntimeSkillHandle` and the wire types are all hand-written field-by-field copies, so any field added upstream stops there silently. The aggravating factor is that strictness was implemented alongside the parse — a typo in `color` is fatal, an unbalanced paren in `disallowed-tools` is a hard error, `skill_validate` allowlists four unimplemented keys — so the product's loudest signal of support is attached to precisely the fields that do nothing.
