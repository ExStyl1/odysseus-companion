# CDP live-audit checklist

**This file is ONE table: every runnable case, its latest run, its verdict**
(owner rule 2026-08-20, AGENTS.md close-out step 4). It is replenished with
every feature: a plan that adds or changes a case adds/updates its row here at
close-out, and records that close-out's run in the `Last run` / `Verdict`
columns. **Run narratives never live here** — each run appends its own file
under `docs/testing/cdp-runs/`, and the row's `Note` points at it. History up
to 2026-08-17 is archived verbatim in
`cdp-runs/2026-07-30--2026-08-17-run-narratives.md` ("archive" below).

- **Driver:** `scripts/cdp/` — see its README for starting the app
  (`NESSY_CDP_PORT=9223 bun run electron:dev`, rebuild bundles first) and
  running (`bun run scripts/cdp/run.ts [CASE-ID …]`).
- **Verdicts:** `PASS` / `FAIL` / `BLOCKED` (a precondition the harness
  deliberately does not create — a fixture, a policy, an operator login; not a
  pass and not a failure) / `owed` (case exists, no run recorded yet). A File cell of `— (case owed)` is one state further back: the driver case itself is not yet written — the row records an obligation, not something the harness can run today. `owed to the packaged sitting` is that same state with its OWNER named: the twelve rows the 1.35.0 close-out added (W9-ca, 2026-09-10) record obligations from wave 9 that could not be driven at close-out time — the close-out lane has no running app, no credentials and no rig — so they are owed to the next sitting that has a packaged build in front of it rather than being silently absent.
- **Mode:** every case runs in `bypassPermissions` (owner rule 2026-09-18, F1.86,
  `ab15eb7ce`). The only exceptions are the named opt-outs whose subject is the
  card; they run in the mode they measure, and RS-108 sets `default` itself and
  reads it back. A run's `Note` records the mode it ran in, read back from
  `FreshSession.permissionMode` and never assumed. A `not-applied: …` reading is a
  finding about the app, not about the rig.
- **No `#p13-*` anchors here any more.** The pre-2026-07-30 P13 desktop smokes
  had per-case sections in this file; the one-table rule retired them and their
  narratives were never carried into `cdp-runs/`. The two plugin fixtures that
  cited them now record that as `historical://` rather than linking a section
  that does not exist (`claude-desktop-host-evidence.json`).
- A source change is invisible until bundles are rebuilt and the app
  relaunched; a case's detector is the thing most likely to be wrong — both
  traps are documented in the archive and in AGENTS.md.
