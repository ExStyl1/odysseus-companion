## RTS-15 — PASS 11/11 (new case)

The shape RTS-14 structurally cannot cover: a session that has **never** been on
Pi switching onto it. Claude → Pi.

```
  ok   the session starts on Claude, never having been on Pi — claude-gateway
  · tool rows before the switch: {"tools":1,"carriesTag":true}
  ok   a tool row holding the build tag exists before the switch — 1 tool row(s)
  · previewRuntimeSwitch claude → pi: {"kind":"connection-cross-runtime","hasHistory":true,"historyCarry":"native"}
  ok   the server plans a NATIVE carry into Pi
  ok   the switch is cross-runtime and arms a handoff — connection-cross-runtime / handoff
  · runtime switch marker: runtime_switched:anthropic:pi:{"carry":"native"}
  ok   the durable notice records a NATIVE carry
  · answer on pi:
    1. Build tag for stage 1: `FB6B7-091AC-AA20B-9D157`
    2. Alpha label: `9DCE8-B6DAA-EFB94-EA08E`
  ok   Pi knows the tool-only build tag — the text tier drops every tool row
  ok   Pi knows the prose label too
  ok   the build tag did not leak into a memory file
```

The build tag is written to a file **by the case** and never named in a prompt,
so the only path from the file to Pi's answer is a carried tool result — which
the text tier drops on the floor.

The whole mechanism is visible in the host log, in order:

```
[pi-rebuild] session 82a592eb… wrote 6 entr(ies) (3018 bytes) from 5 projected item(s)
             at …/82a592eb…/.pi-carry/handoff.jsonl
[pi] [runtime-handoff] carry session in force at …/.pi-carry/handoff.jsonl;
             suppressing the text handoff for this turn
[pi-server] Forking Pi session from the runtime-handoff carry file: …/.pi-carry/handoff.jsonl
[pi] [runtime-handoff] the Pi subprocess forked the carry session
Runtime handoff context applied for 82a592eb… (context=native-transcript)
```

**First attempt FAILED, correctly, and it is worth keeping.** With RTS-14's
wording verbatim ("Run the shell command … and to keep the transcript short
reply with just the word DONE") the model replied `DONE` **without running
anything** — zero tool rows. The case refused to score a carry that had nothing
to carry, which is exactly what its required check exists for. The prompt is now
emphatic that the command must actually be executed, and the reply is still
pinned to one word so the tag cannot leak into prose.

## RTS-14 — PASS 35/35 (regression, tiers unchanged)

**`EXPECTED_TIER` needed no edit, and reasoning it out beforehand is why.** The
circuit is `pi → claude → codex → pi → codex → claude → pi`: Pi **hosts first**,
so `sdkSessionAnchors.pi` is set before any later entry into Pi, `'pi'` is in
`ANCHORED_PROVIDERS`, and `planHistoryCarry` answers `anchor` at the tier above
the capability map. T7 flips that map for Pi and changes nothing about a return
leg. Measured, per leg:

| leg | into | expected | observed |
| --- | --- | --- | --- |
| 2 | claude | native | native |
| 3 | codex | native | native |
| 4 | pi | anchor | anchor |
| 5 | codex | native | native |
| 6 | claude | anchor | anchor |
| 7 | pi | anchor | anchor |

First attempt was 34/35: leg 2 (Claude) answered the alpha label
`DEE88-01AC7-2496-59E42` where the case planted `DEE88-01AC7-B2496-59E42` — one
dropped character. The same label came back byte-exact on legs 4 and 7, so the
carry delivered it and the reply mistyped it. The second attempt is clean, which
is the measurement; the first is recorded rather than discarded because a
transcription slip on a codeword recall is a class this suite will meet again.
