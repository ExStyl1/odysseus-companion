### The rig defect that cost the first twenty minutes, and it is a real one

The first three attempts at BYO-CATALOG failed `electron-api-incomplete`. The
cause is in the app, not the harness:

```
[main] Restoring window: workspaceId=…, focused=false,
  url=file:///Users/i.i.gavrikov/Desktop/work/nessy-desktop/release/mac-arm64/Nessy%20Desktop.app/Contents/Resources/app/dist/renderer/index.html?workspaceId=…
```

`window-state.json` still held the URL of the **packaged** W-pkg build, whose
`release/` tree was deleted after that wave. `window-manager.ts:350` maps a
restore onto the dev server by keeping the SAVED PATHNAME
(`devUrl.pathname = savedUrl.pathname`), so the dev app loaded
`http://localhost:5173/Users/…/release/…/index.html` — Vite's SPA fallback
answers 200 with a document titled "Nessy Desktop" and no app bundle, so
`did-fail-load` never fires and there is no error anywhere; the window simply has
no `window.electronAPI`.

**This contradicts the contract written on the field itself.**
`window-state.ts:19-23` says the saved URL is safe to store because
"createWindow() never loads this URL directly. It extracts query params … and
rebuilds the URL from `__dirname` (prod) or the current dev server (dev)." The
PROD branch does exactly that. The DEV branch does not — it copies the pathname.
A packaged run followed by a dev run is enough to reproduce.

Recovered by navigating the same window to `http://localhost:5173/` + the saved
query (`Page.navigate`), which is also what repaired the stored state: the URL
saved at quit is now the dev origin.

Not fixed here — it is `apps/electron/**`, outside a docs-only row. Suggested as
its own tracker row.
