**Artefact:** `release/NessyDesktop-1.34.0-mac-arm64.dmg`, built from
`d289a781f`, unsigned (`CSC_IDENTITY_AUTO_DISCOVERY=false`). The `afterPack`
hook printed the match the close-out owes:

> `claude-agent-sdk 0.3.233 (claudeCodeVersion 2.1.233), native binary
> @anthropic-ai/claude-agent-sdk-darwin-arm64@0.3.233 — matches the lockfile pin.`

`app-under-test.kind = packaged` on every case below, derived by the driver from
the CDP page target url — not asserted by hand.

**Rig.** The `runtime-switch` fixture, rooted in this session's scratch tree
rather than the operator's home (`NESSY_CDP_RTS_ROOT`), booted twice: once so the
app writes its own `config.json`, then again after the fixture merged the three
gateway cards (`pi-api-key`, `claude-gateway`, `codex-gateway`), which the
fixture asserts secret-free before writing. The operator's own `~/.nessy-agent`
was never written; `~/.nessy/dp_auth_creds.json` stayed read-only and shared.
Dark theme forced by the harness on every case (`theme: already-dark`).

**A rig fault caught before it was believed, and it is the one worth carrying
forward.** PKG-1's first run reported `FAIL 9/10` on *"the Pi runtime wrote this
turn into its own session file"*. It had not: the CASE PROCESS does not inherit
the app's `NESSY_CONFIG_DIR`, so `configDir()` resolved to the operator's real
`~/.nessy-agent` and the detector looked for a sidecar in a config dir the app was
not using. The README already warns of exactly this for `SKL-P1`. Re-run with
`NESSY_CONFIG_DIR` on the case process too: **PASS 10/10**. A detector is the
thing most likely to be wrong, and this one would have filed a product defect
against a path the app never touched.
