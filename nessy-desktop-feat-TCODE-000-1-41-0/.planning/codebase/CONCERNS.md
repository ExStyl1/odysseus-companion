## Security Considerations

**Seatbelt write containment is a wildcard, on purpose, until GA:**
- Risk: `packages/shared/src/agent/core/bash-seatbelt.ts:87` —
  `export const SEATBELT_TESTING_WILDCARD: boolean = true;` The macOS seatbelt
  profile permits writes anywhere while it is on.
- Current mitigation: dated owner decision (2026-07-21) recorded at
  `bash-seatbelt.ts:54-62`; the containment tests key off the constant and
  re-arm automatically (`__tests__/bash-seatbelt.test.ts:24-25,29-30`).
- Recommendation: flip to `false` before GA. This is a scheduled flip, **not** a
  defect to "fix" ad hoc.

**Sandbox / isolation is OFF by standing owner decision (2026-08-12/13):**
- Risk: no process isolation on the Pi runtime by default.
- Consequence measured elsewhere: with sandbox off,
  `packages/codex-responses-adapter/src/config-writer.ts` emits
  `danger-full-access` for **every** permission mode, so the approval card was
  the only thing carrying a read-only mode's intent to codex (fixed under plan
  row R6, but the shape is the warning).
- Recommendation: any change here must go through the owner; bypass + no-sandbox
  is containers-only territory.

**A sandbox-escaping command is approved with no indication it escapes:**
- Risk: `PromptInfo.impact` — the string "Runs outside the sandbox: matched the
  administrator's excludedCommands pattern …" is built, wired and persisted
  (`packages/shared/src/agent/core/pre-tool-use.ts:1511`/`:1880`, emitted at
  `packages/shared/src/agent/claude-agent.ts:1511` and
  `packages/shared/src/agent/pi-agent.ts:4386`, persisted at
  `packages/server-core/src/sessions/SessionManager.ts:5688`) and the approval UI
  never renders it: `apps/electron/src/renderer/components/app-shell/ChatDisplay.tsx:1717-1729`
  reads `impact` only under `type === 'admin_approval'`; `PermissionRequest.tsx`
  has zero `impact` references.
- Recommendation: render `impact` on the bash prompt path. Classified **small**.

**A persisted approval prompt has no TTL:**
- Risk: `PiPendingApprovalV1.requestedAt` (`packages/shared/src/sessions/types.ts:173`)
  is written once (`SessionManager.ts:5696`) and read nowhere;
  `reprojectPendingApproval` (`SessionManager.ts:5721-5751`) forwards
  `approvalTtlSeconds` while comparing nothing. The only TTL arithmetic lives in
  the in-memory `privileged-execution-broker.ts:51,63`, lost on restart.
- Impact: a week-old prompt is re-presented as live and settled. `admin_approval`
  is excluded by a dated, honoured decision (`SessionManager.ts:5794`,`:5807`).

**An enforced permission rule can match no tool at all:**
- Risk: `ParseClaudeRuleOptions.knownToolNames`
  (`packages/shared/src/agent/pi-harness/claude-permission-rules.ts:41`) is never
  supplied by any of six production call sites, and the unknown-tool branch
  (`:188-198`) attaches `warning` *alongside* a rule while both warning consumers
  gate on `!parsed.rule`. Probe: `parseClaudeRuleString('StopTask','deny')`
  installs an enforced rule matching nothing, silently. Classified **medium**.

**A skill's `disallowed-tools` is not enforced (the sibling subagent field is):**

  freezes `{tools, model, agent, effort}` and there is no subtraction path

**A source-anchored plugin hook `if` filter fails open:**

## Performance Bottlenecks

**Base session context is ~46 000 tokens before any user turn:**
- Problem: system prompt plus capabilities set a floor a session can never go
  below. Measured while proving auto-compaction.
- Impact: a compaction threshold sized against zero sits below the floor and the
  session compacts after every turn forever — which reads exactly like
  "compaction is broken". Size any narrowing knob (`NESSY_AUTO_COMPACT_WINDOW`)
  against the resting state.
- Improvement path: `docs/superpowers/plans/2026-08-15-base-context-diet.md`.

**Full-suite runs are load-sensitive and self-interfering:**
- Problem: several session suites mutate `process.env.NESSY_CONFIG_DIR` at module
  scope, so two concurrent `bun test` processes manufacture failures
  (`durable-approvals`, `permission-remember`, `fuzzy-file-search`, `queue-ops`).
- Improvement path: check nothing else is running before recording a failure;
  move config-dir mutation out of module scope.

**`bun test` from the repo root collects packaged renderer copies:**
- Problem: after a dmg/AppImage build, `release/**/Resources/app/src/**` adds 182
  files whose path aliases no longer resolve. Measured 2026-08-05: 12 928 tests
  collected with `release/` present, 11 464 without; 14 phantom failures.
- Improvement path: `rm -rf release` before any test wave.

**A source file carrying a NUL byte is skipped SILENTLY by `rg`/`grep`:**
- Files: **do not read a list from here — run `bun scripts/check-nul-bytes.ts`.** It reads
  every byte of every tracked `.ts`/`.tsx` and prints the live set with each file's first
  NUL offset. This bullet used to name eight files; the committed scan later measured
  fourteen, and after those were escaped it measures zero. Every one of those numbers was
  correct on the day it was written, which is exactly why the pointer replaced the list.
- Why fragile: any "identifier X has no callers" claim over such a neighbourhood
  is a false negative, and the failure is invisible (a single-file target says
  "binary file matches"; a multi-file search says nothing).
- Why the clever instrument is worse than none: `comm -23 <(git ls-files) <(git grep -lI '')`
  reads only the ~8000-byte prefix git inspects, so at the fourteen-file reading it found
  four — plus one zero-byte file carrying no NUL at all — and looked complete both times.
- Safe modification: use `grep -a` / `rg --text` for every absence claim; when you own the
  file, escape the byte as `\u0000` instead (identical runtime value, source stays
  greppable — see the script's header for the byte-identity proof).

## Scaling Limits

**Long-lived feature branches accumulate breakage invisibly:**
- Current capacity: the per-base "pre-existing" check works for a short branch.
- Limit: at ~200 commits the known-failing register had grown to 15 rows that
  `master` did not have, each verified correctly against its own base.
- Scaling path: compare against the **target branch** before any merge, not
  against your base.

**Single active turn per Claude session:**
- Current: a fresh `query()` per user message; the session dies with the answer.
- Limit: background tasks, workflows and long-running modes are unreachable
  because nothing is alive to call the levers.
- Scaling path: plan row R7 (designed, gated on one live day; **unowned**).

## Dependencies at Risk

**`@earendil-works/pi-*` pinned to exactly `0.80.3`:**
- Risk: `SUPPORTED_PI_RUNTIME_VERSION` is compared with a strict `!==` before a
  session is constructed — any other version refuses loudly. Declared in
  `package.json:141-142` and `packages/shared/package.json:169-171`.
- Impact: a bump is a qualification exercise, not a dependency update. The
  `0.81.1` upgrade was assessed and skipped; its scorecard was deleted in
  `97f7e7af` (recover with `git show 97f7e7af^:docs/architecture/pi-extension-adoption-scorecard.md`).
- Migration plan: `docs/architecture/extension-first-pi-agent-runtime.md` — read
  before any Pi SDK bump. Its line ledger is a qualification-time snapshot, not a
  current measurement.

**`@anthropic-ai/claude-agent-sdk` `0.3.218` — behaviour lives in a native binary:**
- Risk: the SDK interprets `permissionMode` and hook payloads inside a ~255 MB
  per-platform binary, so **no unit test can execute it**. Every permission
  change here is proven only under the *documented* reading.
- Mitigation in place: R1/R2/R8 added run-time guards that re-parse the union out
  of the installed `sdk.d.ts`, so a rename or a new message type fails by name
  rather than arriving and being dropped.
- Migration plan: treat Claude Code's docs as the contract; cite the snapshot
  `scripts/claude-doc-pages.tsv`, refresh with `scripts/refresh-claude-doc-pages.py`.

**Known CI-infra failures are reviewer-owned, not ours:** electron postinstall,
semgrep registry image. Protected-ref secrets are unavailable on feature
branches, so signed release and S3 publish checks are reviewer-only.
