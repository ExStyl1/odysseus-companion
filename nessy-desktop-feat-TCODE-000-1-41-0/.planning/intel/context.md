## Topic: CLI client (`nessy-general-agent`)
- source: docs/cli.md
- Terminal client for the Nessy Desktop server; connects over WebSocket (`ws://` or `wss://`) to a running headless server.
- Prerequisites split three ways: `run` and `--validate-server` need an API key (`--api-key`, `$LLM_API_KEY`, or a provider-specific env var such as `$ANTHROPIC_API_KEY`) and both spawn their own server; `doctor`, `plugin validate|list|details` and `--version` need **nothing** and run offline against local configuration; every other command needs a running headless server with URL and token.
- Install paths: `bun run apps/cli/src/index.ts <command>` from the repo root, or `cd apps/cli && bun link` to put `nessy-general-agent` on PATH.
- Connection surface: `--url`/`NESSY_SERVER_URL`, `--token`/`NESSY_SERVER_TOKEN`, `--workspace` (auto-detects the first available workspace when omitted), `--timeout` (default 10000), `--tls-ca`/`NESSY_TLS_CA`, `--json`, `--send-timeout` (default 300000), `--safe-mode`/`NESSY_SAFE_MODE=1`, `--verbose`/`-v`, `--no-spinner`/`--disable-spinner`, `--help`/`-h`, `--version`. Flags take precedence over environment variables.
- Safety note carried by the reference: `--safe-mode` starts with no CLAUDE.md, skills, plugins, hooks, MCP servers, commands or agents loaded, "for troubleshooting a broken configuration. **Managed policy still applies** — safe mode is a diagnostic, not a way out of org policy."

## Topic: Mobile remote (iOS/iPadOS)
- source: docs/nessy-mobile.md
- A phone client for an agent that runs elsewhere. "There is no agent runtime on the device: it is a thin client to the same WebSocket RPC server the desktop renderer and `apps/cli` already speak." Its stated reason to exist is answering permission approvals while the agent keeps working on the desktop.
- Source lives in `apps/ios/` as `NessyAgentKit` (protocol, transport, models) and `NessyMobile` (the app). It began as a vendored upstream pull request at a pinned SHA; **the owner decided on 2026-08-09 to fork and own it**, so upstream is no longer tracked and the modules carry Nessy names. Provenance, license and every deviation are in `apps/ios/UPSTREAM.md`; the wire comparison is in `apps/ios/PROTOCOL-CONFORMANCE.md`.
- Measured on an iPhone 17 Pro simulator against a real `nessy-server`, not a mock: pairing (server URL + token in the device Keychain), browsing workspaces/session list/history, live streamed turns, approvals that unblock the waiting turn, control (stop a turn, switch permission mode, switch model), offline cached session list behind an explicit banner with sending and approvals disabled, background reconnect, two simultaneous devices without eviction, iPad split view, and localized error sentences carrying the wire code in small print.
- Permission modes on the device are "this fork's seven, not upstream's three, and the pre-migration spellings still decode." Interface is Russian and English.
- Deployment constraint: `nessy-server` bound to `127.0.0.1` is reachable only from the host Mac, and pointing it at a network address **is refused by design** — "Refusing to bind to a network address without TLS. Authentication tokens would be sent in cleartext." The server logs that, calls `stop()` and exits one millisecond after reporting "listening", "which reads exactly like a crash if you skim the log."
