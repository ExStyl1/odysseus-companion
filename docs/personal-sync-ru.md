# Общий профиль Nessy CLI и Desktop

Запускайте приложения файлами **«Запустить Odysseus Desktop.command»** и **«Запустить Odysseus CLI.command»** из папки Odysseus. В Desktop появятся две кнопки внизу боковой панели: **«Открыть в CLI»** и **«Синхронизировать CLI ↔ Desktop»**.

«Открыть в CLI» явно запускает системный **«Терминал» macOS** в папке текущего чата и продолжает его связанную историю. Кнопка ждёт подтверждения запуска процесса CLI; если оно не получено, покажет ошибку, а подробности будут видны в окне «Терминала». Сначала остановите работающий ответ. Для пустого чата открывается новая CLI-сессия. Приложения остаются отдельными: CLI запускает собственный движок и использует свои разрешения.

## Что синхронизируется

- Текст чатов, названия, порядок сообщений и рабочая папка. Изменения появляются автоматически примерно через пять секунд. Сканирование и запись выполняются в отдельном фоновом процессе, чтобы не задерживать переключение разделов Desktop. История инструментов отображается как информационный текст. Оригинальные записи обоих приложений и файлы вложений Desktop сохраняются в архиве.
- API-подключения OpenAI и Anthropic, совместимые шлюзовые подключения Nessy: адрес, модели, названия, описание, известные возможности изображений, размер контекста и выбранная модель. Неизвестный размер контекста нового подключения Desktop получает консервативный предел 32 000 токенов, его можно уточнить в настройках.
- API-ключи из штатного менеджера Desktop и явно заданных пользовательских `settings.env` CLI. Другие переменные окружения и OAuth-подписки не извлекаются. При изменении ключей перезапустите уже работающий CLI, чтобы он получил новое окружение.
- Язык интерфейса `ru`, `en`, `zh-CN`; светлая и тёмная тема. Режим «системная» сохраняется в Desktop: у CLI нет точного аналога.
- MCP, навыки, агенты и общие правила синхронизируются общим профилем проектов при запуске и в том же автоматическом цикле. Для ручного запуска профиля используйте `node tools/odysseus.mjs sync`.

## Границы переноса

OAuth-подписки ChatGPT/Claude, IAM, специализированные провайдеры и произвольные подключения без API-ключа остаются в исходном приложении, если у второго нет доказанного аналога. Настройки интерфейса, специфичные для одного приложения, также сохраняются на месте. Сеансы SDK, активные инструменты, доверие к папкам и разрешения не переносятся.

Вложения сохранены в архиве, но в чате другого приложения представлены подписями: для повторной отправки модели приложите файл заново. При переходе в Desktop текст истории также передаётся через штатный механизм контекста переноса; для очень длинных разговоров этот контекст сокращается до начала и последних сообщений, полная история сохраняется.

Входящие изменения чата с выделенным агентом Desktop ждут освобождения сессии или перезапуска приложения. Исходящий экспорт стабильного чата разрешён. Если продолжить один чат одновременно в обеих программах, появится конфликт: автоматического объединения двух веток нет, обе версии остаются. Удаление чата или подключения не удаляет его копию в другой программе.

## Где данные

Приватные данные находятся в `~/.odysseus/`, вне проекта:

- `state.json` — соответствия чатов, моделей и состояние сравнения;
- `conversations/` и `objects/` — история, исходные записи и файлы;
- `backups/` — копии перед изменениями; `pending.json` — журнал восстановления после прерывания;
- `status.json` — последнее состояние без ключей; `credential-state.json` содержит только отпечатки ключей;
- `secrets.enc` — API-ключи, зашифрованные AES-256-GCM; `bridge.key` — локальный ключ с правами 0600. Каталог закрыт правами 0700. Это защита от случайного раскрытия, а не от программ с доступом к вашему пользовательскому профилю.

В репозиторий секреты не записываются. Не публикуйте приватную папку вместе с её ключом. Резервные копии оригинальных настроек могут содержать уже имевшиеся в них секреты и имеют те же закрытые права.

Можно переназначить папку переменной `ODYSSEUS_DATA_DIR`. Нативные `NESSY_HOME`, `NESSY_RUNTIME_DIR`, `NESSY_CONFIG_DIR` поддерживаются. Для разных пар профилей используйте разные `ODYSSEUS_DATA_DIR`.

Предпросмотр: `node tools/odysseus.mjs personal-sync --check`.
Применение вручную: `node tools/odysseus.mjs personal-sync`.
При ошибке незавершённой транзакции обычный запуск попытается восстановить её. Если файл успело изменить само приложение, восстановление остановится и сохранит обе версии для ручной проверки. Не удаляйте `pending.json`, не разобравшись с резервной копией.

## Раздельные обновления

Общие данные не находятся в папках приложений и переживают их замену. CLI можно обновлять и пересобирать отдельно, сохраняя путь из `odysseus.json`.

Кнопки Desktop входят в эту локальную сборку. Штатное обновление установленного Desktop не добавляет их в чужую готовую сборку автоматически. После замены **исходников** Desktop укажите новый путь в `odysseus.json`, выполните `node tools/install-desktop-bridge.mjs --check`, затем без `--check` и пересоберите Desktop. Установщик делает копии изменяемых файлов и откажется применять интеграцию, если нужные участки новой версии несовместимы. Проверки адаптеров следует повторить при изменении нативных форматов.

Самостоятельно запущенные приложения без запуска через Odysseus не поднимают этот мост. Одновременно с Desktop синхронизацией управляет его процесс; CLI принимает эту блокировку и не запускает второго писателя. Когда открыт только CLI через общий запуск, синхронизацию выполняет его оболочка.
