# База знаний проектов

Odysseus сохраняет контекст проектов на диске, чтобы CLI и Desktop могли обращаться к нему через общий MCP Graphify. Это локальный разбор кода и ссылок, без дополнительных AI API и ключей. Движок Graphify 0.9.92 устанавливается в отдельное окружение; обновления CLI и Desktop остаются раздельными.

## Первое включение на новом компьютере

Из корня Odysseus выполните `npm run knowledge:setup`. Нужны Node.js 22+, uv (поставляется с Desktop) и Python 3.12. При необходимости uv загрузит Python; первый запуск требует интернета для зависимостей. После установки запускайте CLI/Desktop штатными командами Odysseus. Установщик добавит источник «Graphify · база знаний» в рабочие пространства Desktop и общий MCP для CLI. Источник подчиняется обычным настройкам разрешений приложения.

Хранилище ищется в локальном реестре Obsidian: сначала открытое, затем последнее использованное существующее. Если ничего не найдено, создаётся `workspace/Obsidian`. Реестр Obsidian не переписывается. Для явного выбора задайте `ODYSSEUS_OBSIDIAN_VAULT` или поле `vault` в `.odysseus/graphify/config.json`. Неверный явно указанный путь вызывает ошибку. На этом компьютере Obsidian не установлен; создание и проверка Markdown/Canvas выполняются без его GUI.

## Во время работы

CLI регистрирует свою рабочую папку, Desktop подхватывает папки сохранённых Projects. Подключение через attach также регистрирует проект. Дополнительный проект: `node tools/graphify.mjs register /path/to/project "Название"`.

При запуске приложения отдельный фоновый процесс проверяет изменения примерно раз в 30 секунд после завершения предыдущего прохода. Он не разбирает код внутри процесса UI. Первое индексирование крупного проекта занимает минуты; неизменённые снимки используются повторно. Проверка состояния: `npm run knowledge:status`. Обновление вручную: `npm run knowledge:refresh`.

Сохраняются дерево папок/файлов, кодовые связи Graphify, документы, зависимости и решения. После значимого этапа агенту следует сохранить устойчивое решение вместе с основанием: `node tools/graphify.mjs record /path/to/project "Решение и ссылка на источник"`. Весь разговор автоматически не копируется. Обновление дерева автоматическое; запись решений выполняется по команде или инструкции навыка Graphify.

## Какие связи находятся

- Прямая зависимость от пакета другого зарегистрированного проекта, если поставщик пакета однозначен.
- Общие npm-зависимости: это общий стек, а не доказательство вызова одного проекта другим.
- Совпадающие исходники/контракты по SHA-256.
- Прямые ссылки из Markdown на файлы другого проекта и упоминания полного пути проекта в заметках.
- Явные связи заметок Obsidian через wikilinks и Markdown-ссылки.

У связей сохраняются источник и уровень достоверности EXTRACTED/INFERRED. Семантические сходства, не подтверждённые исходниками, требуют проверки агентом. Одинаковые имена функций разных проектов разделены. При ошибке обновления предыдущий граф сохраняется и помечается как устаревший.

## Как читать и спрашивать

Откройте `Graphify/Проекты.canvas` в выбранном Obsidian: проекты соединены через общие зависимости и фрагменты кода. `Graphify/Проекты.md` содержит обзор, `Graphify/Проекты/` — отдельные карточки, `Graphify/Карта.canvas` — связи обычных заметок. Исходные заметки не изменяются. Отредактированный пользователем отчёт не перезаписывается; сообщение об этом видно в диагностике.

В Odysseus подключите источник Graphify и спросите, например: «Что связывает эти проекты? Покажи файлы-основания» или «Какие проекты используют этот контракт?». Инструменты MCP: query_graph, get_node, get_neighbors, shortest_path, graph_stats. Общий граф содержит файлы, документы, зависимости и проекты. Для поиска функций/классов найдите узел проекта и передайте его `graphify_project_path` параметром `project_path` инструментам MCP.

Состояние лежит в `.odysseus/graphify/knowledge`, подробные графы — в `projects/<id>/engine/graphify-out/graph.json`. Сохраняется до 20 предыдущих снимков проекта. Личные пути, графы и окружение находятся в локальном runtime, а общая конфигурация не содержит путей этого компьютера.

Сканирование ограничено 50 000 исходников на проект и 10 000 заметок, по 2 МБ на файл. Скрытые каталоги, symlinks, сборочные зависимости и файлы с именами credential/secret/token/lock исключаются. Эти фильтры не заменяют проверку содержимого: граф может включать фрагменты исходников. Запросы к MCP доступны подключённому агенту, поэтому его дальнейшая работа с данными подчиняется настройкам модели приложения.

## Карта и чат в Desktop

В боковом меню есть «База знаний» и «Чат с базой знаний». На карте сначала показаны проекты и общие элементы. Двойной клик раскрывает окружение узла; выбор проекта, глобальный поиск, список узлов и страницы позволяют добраться до всей базы. На одной странице до 160 узлов и 1200 связей, ограничения указаны в интерфейсе. Масштаб меняется колесом, фон можно перетаскивать. Карточка узла показывает основания видимых связей.

Кнопки «Заметка» и «Добавить связь» создают ручные записи. Они хранятся в отдельном overlay.json, версии — в overlay-history. Индексация их не стирает. У ручных связей уровень USER_RECORDED: это записанное утверждение пользователя. Их можно обновлять и удалять; автоматически найденные связи исправляются в исходниках.

Вкладка чата открывает сохраняемую беседу встроенного агента для текущего рабочего пространства. Используются выбранная модель и обычные разрешения приложения. Первый запрос содержит инструкцию по Graphify; допишите задачу и отправьте. Например: «Свяжи проекты A и B через общий API-контракт, найди основание и добавь пояснение». Агент может пользоваться MCP для поиска и локальным помощником для изменений:

`node tools/knowledge-ui.mjs snapshot '{"query":"контракт"}'`

`node tools/knowledge-ui.mjs edit '{"type":"add-note","label":"Решение","description":"Основание: ADR-1"}'`

Операции edit: add-note (label, description), add-link (source, target, relation, evidence), update-manual (id, label/description/relation), remove-manual (id). Идентификаторы берутся из snapshot/MCP. Передавайте JSON отдельным аргументом, без eval. Изменение сразу видно на карте, общий MCP подхватывает его после фонового прохода. Если автосвязь устарела, исправьте исходный документ/код. Напрямую graph.json редактировать не нужно.

## Каталоги и чтение источников

Начальный вид показывает проекты. В режиме «Каталоги» нажатие на проект или папку открывает только её непосредственное содержимое. Путь над картой позволяет вернуться на любой уровень. Режим «Связи» показывает окружение выбранного узла, включая зависимости между проектами. Поиск внутри проекта ограничен этим проектом; для поиска по всей базе вернитесь к «Все проекты». Новая ручная заметка сохраняется в текущем проекте/папке.

У узла и его связей есть «Читать источник». Клик по линии с источником тоже открывает файл. Markdown отображается как документ, код и текст — как текст. Неподдерживаемый формат или крупный файл можно открыть системным приложением. Читатель разрешает только файлы, указанные в графе у выбранного узла или его связей, а не произвольные пути из интерфейса.

Постоянный процесс держит граф в кэше и перечитывает его при изменении. Открытый вид проверяет обновления последовательно примерно раз в 2,5 секунды, не сбрасывая масштаб и положение при неизменённых данных. Полная перезагрузка приложения для обновления графа не нужна. Индексация исходников сохраняет свой фоновый интервал; обновление UI не означает немедленную переиндексацию кода.

## Отдельные каталоги знаний

Каталог знаний объединяет выбранные проекты и отделяет их контекст от остальных. Он не меняет расположение исходников. «Мои проекты» — каталог по умолчанию для рабочих проектов. Исходники CLI/Desktop Odysseus и его демонстрационная рабочая папка автоматически относятся к «Odysseus», а самостоятельные заметки хранилища — к «Заметки Obsidian».

Выберите каталог над картой. В «Управление каталогами» можно создать свой каталог и назначить ему проекты. В выбранном каталоге доступны только его проекты, файлы и относящиеся к ним связи; общие зависимости не втягивают соседние проекты из другого каталога. Новые рабочие проекты появляются через штатный раздел «Проекты» и фоновое обнаружение. Настройки назначения хранятся локально в `.odysseus/graphify/knowledge/collections.json`.

«Папки проекта» — отдельный уровень навигации: каталоги исходников внутри уже выбранного проекта. «Связи» показывает окружение узла в пределах текущего каталога знаний.

Для каждой пары «рабочее пространство Desktop + каталог знаний» открывается отдельная беседа агента и отдельный MCP-источник. Истории разных каталогов не объединяются. Общий MCP по умолчанию читает «Мои проекты»; CLI launcher выбирает каталог своей рабочей папки. Явный запуск: `node tools/graphify.mjs serve --collection ID`. Самостоятельные графы каталогов находятся в `knowledge/collections/ID/graphify-out/graph.json` и обновляются вместе с индексом. Исходный общий индекс остаётся внутренним хранилищем для организации каталогов. Это разделение контекста, а не разграничение прав доступа файловой системы.

## Синхронизация всех каталогов с Obsidian

Вверху карты и чата базы знаний нажмите **«Синхронизировать всё с Obsidian»**. Кнопка обрабатывает все каталоги, включая пустые, а не только выбранный. Уже запущенная операция используется повторно; переходы между вкладками не прерывают её. Большой граф обрабатывается отдельным процессом. Первая выгрузка создаёт Markdown-файл для каждого узла и все его исходящие связи. Повторная синхронизация не переписывает неизменённые файлы.

Хранилище находится автоматически по настройкам Obsidian; если его нет, создаётся `workspace/Obsidian`. Файлы обмена находятся в `Graphify/Каталоги/<id каталога>/`. У файлов читаемые названия со стабильным идентификатором; связи — обычные `[[wiki-ссылки]]`, доступные в графе Obsidian. Для отдельного каталога используйте фильтр пути в графе Obsidian, для одной заметки — локальный граф. Служебный `odysseus_id` в начале файла сохраняйте.

- В Odysseus можно создавать заметки и ручные связи: следующая синхронизация запишет их в Obsidian.
- В Obsidian можно менять заголовок, текст между заголовком и разделом «Связи», добавлять или убирать строки связей вида `- [[имя файла]] — название связи`. Следующее нажатие кнопки перенесёт правки в граф. Переименование и перемещение заметки внутри её каталога сохраняют ID.
- Новый обычный Markdown-файл внутри папки каталога становится ручной заметкой. Его wiki-ссылки на известные заметки того же каталога становятся ручными связями.
- Описания узлов из кода изменяются как пользовательские пояснения; исходные файлы не переписываются. Связи, извлечённые из кода, исправляются в исходниках: удаление такой строки в Obsidian не удаляет подтверждённую кодом связь.
- Одновременные разные изменения одного поля с двух сторон дают конфликт. Обе версии сохраняются. Согласуйте содержимое в заметке и графе и нажмите кнопку ещё раз. Предыдущие версии файлов и ручных записей хранятся в `knowledge/obsidian-history` и `knowledge/overlay-history`.
- Удаление Markdown-файла не удаляет знания: файл будет восстановлен из графа. Удалённые из графа узлы не приводят к удалению заметок пользователя; синхронизация сообщает об оставшемся файле.

Синхронизация папки обмена выполняется по кнопке, а не непрерывно. Обычные заметки Obsidian за пределами `Graphify` продолжает читать фоновый индексатор. Без UI: `npm run knowledge:sync`. Последний результат и полный список конфликтов: `.odysseus/graphify/knowledge/obsidian-sync-result.json`.
