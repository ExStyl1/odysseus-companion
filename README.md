# Odysseus

Общий профиль для Nessy CLI и Nessy Desktop с сохранением их отдельных
установок и штатных обновлений. Исходные проекты лежат в своих папках;
Интеграция Desktop накладывается отдельным воспроизводимым мостом; штатный updater и инфраструктура выпуска сохраняются.

Требуется Node.js 22+. У оболочки нет внешних зависимостей, `npm install` для
неё не нужен. CLI и Desktop устанавливаются/собираются отдельно.

## Быстрый старт

Все команды выполняются из этой папки.

```bash
node tools/odysseus.mjs status

# Подключить свой рабочий проект; сначала можно посмотреть изменения:
node tools/odysseus.mjs attach /absolute/path/to/project --check
node tools/odysseus.mjs attach /absolute/path/to/project

# Либо включить существующие проектные ресурсы в общий профиль:
node tools/odysseus.mjs attach /absolute/path/to/project --import

# Синхронизация вручную или в отдельном терминале постоянно:
node tools/odysseus.mjs sync
node tools/odysseus.mjs watch

# Запустить установленный CLI в этом же проекте:
node tools/odysseus.mjs run cli --project /absolute/path/to/project

# Открыть установленный Desktop; в приложении выбрать этот же проект:
node tools/odysseus.mjs run desktop --project /absolute/path/to/project
```

Демонстрационный проект `workspace/` уже подключён. В нём есть общий skill
`odysseus-workspace`; общий MCP Graphify включается после `npm run knowledge:setup`. Это реальная
проверка раскладки файлов, но не проверка запуска агентных движков.

Для других ОС или имени установленного приложения поменяйте массив
`components.desktop.command` в `odysseus.json`. По умолчанию используется
macOS-команда `open -a "Nessy Desktop"`. CLI запускается командой `nessy` из
PATH. Аргументы передаются без shell; дополнительные аргументы — после `--`.

## Что общее

В общем каталоге **220 самостоятельных навыков**: объединены 28 повторов и исключены 53 рекламных и маркетинговых навыка. У всех активных навыков русские
описания; у 132 включён выбор моделью по подходящей задаче, 88 вызываются явно.
В Desktop каталог с дополнительными навыками агента содержит 247 позиций и открывается в «Источники → Навыки». Раздел «Плагины» предназначен для управления плагинами.
Исходные варианты, ресурсы и сведения об авторах сохранены. Корпоративные
подключения разрешены для явно добавленных пользователем сценариев;
локальные ограничения других режимов сохраняются.

Полный справочник с назначением, примерами, зависимостями и режимом выбора:
[docs/skills-catalog-ru.md](docs/skills-catalog-ru.md).
Для ежедневного использования: [каталог с поиском и карточками](workspace/Каталог%20навыков%20Nessy.html)
и [версия для чтения в Nessy Desktop](workspace/Каталог%20навыков%20Nessy.md).
У каждого навыка есть переход в новый чат с готовым запросом;
запрос отправляется после нажатия Enter в Desktop.
История импорта: [docs/shared-skills.md](docs/shared-skills.md).
Русские описания и настройки редактируются в `shared/skills-catalog.json`;
`npm run catalog:build` обновляет метаданные, справочник и контрольные суммы.

- `shared/mcp.json` — объект `mcpServers`, проектная копия — `.mcp.json`.
- `shared/skills/<slug>/SKILL.md` и вспомогательные файлы — `.agents/skills`.
- `shared/agents/<slug>.md` — `.nessy/agents` и `.nessy-agent/agents`.
- `shared/rules/**/*.md` — `.nessy/rules` и `.nessy-agent/rules`.

Агенты должны использовать базовый формат с `name`, `description` и Markdown
инструкцией. Модель, инструменты и дополнительные поля трактуются конкретным
движком; одинаковые файлы не означают одинаковые возможности рантаймов.

Хуки, плагины, OAuth/API credentials, настройки моделей, разрешения и чаты
остаются отдельными. Навыки могут заменить переносимые slash-команды;
форматы команд/хуков двух продуктов автоматически не конвертируются.

MCP поддерживает переносимые `stdio` (поле `command`), `http` и `sse`.
Для HTTP в проектном файле добавляется `httpUrl`: CLI выбирает транспорт
по нему, а Desktop — по `type: "http"` и `url`. При импорте CLI-конфигурации
`httpUrl` нормализуется обратно в общий формат. Разные `url` и `httpUrl`
считаются конфликтом и требуют явного исправления.
Используйте абсолютные пути к серверным скриптам, если они не находятся в
каждом подключённом проекте. Строки `${TOKEN}` сохраняются без раскрытия;
переменные должны быть доступны процессу приложения. GUI, запущенный через
macOS `open`, не обязательно наследует окружение терминала. OAuth-вход при
необходимости проходит отдельно в каждом приложении. Не коммитьте токены.

В Desktop нужно открыть тот же каталог проекта и разрешить доверие проекту;
в CLI подтвердить MCP. Менеджер не выдаёт эти разрешения. Организационные
политики приложений продолжают действовать. После изменения ресурсов может
потребоваться новая сессия или обновление списка ресурсов в приложении.

## Правки, импорт и конфликты

Меняйте общий каталог или уже управляемую проектную копию и запускайте `sync`.
В режиме `watch` изменения проверяются раз в две секунды. Новые файлы в общем
каталоге добавляются автоматически, новые локальные ресурсы — через
`attach PROJECT --import`. Перед импортом синхронизируйте правки существующих
ресурсов. Импорт объединяет MCP и каталоги, а не выбирает одну сторону при
разногласии.

Обычные локальные ресурсы с другими именами сохраняются. Если одинаковый
ресурс одновременно изменили по-разному, операция ничего не перезаписывает и
показывает конфликтующий путь. Сохраните нужные варианты, приведите
конфликтующие копии к одному содержимому и повторите `sync`. Нет `--force`.

Удаление управляемого ресурса распространяется на все подключённые проекты.
Для удаления целого skill удаляйте его каталог вместе с ресурсами. Чтобы
прекратить синхронизацию проекта и оставить текущие файлы:

```bash
node tools/odysseus.mjs detach /absolute/path/to/project
```

Состояние и хеши лежат в `.odysseus/state.json`. Блокировка защищает от двух
одновременных sync; не редактируйте управляемые файлы во время записи. При
ошибке записи выполняется откат; аварийное отключение питания не покрывается
транзакцией. Для профиля и важных проектов нужен обычный резервный backup.
Файлы должны быть strict JSON там, где ожидается JSON; ссылки в управляемых
каталогах отклоняются. Удалённый/недоступный проект следует отключить `detach`.

## Независимые обновления

CLI обновляется своим штатным npm/pnpm/standalone-механизмом. Desktop — своим
`Settings → About → Check for updates`. Обновление одного не требует сборки
или обновления второго. Odysseus не связывает их номера версий.

```bash
node tools/odysseus.mjs updates cli
node tools/odysseus.mjs updates desktop
```

Эти команды показывают способ обновления; они не скачивают и не устанавливают
новую версию. После обновления достаточно снова запустить приложение.
Общий каталог и проектные копии находятся вне установок и сохраняются.
Если будущий upstream изменит форматы или прекратит читать перечисленные
проектные каталоги, адаптер Odysseus придётся обновить отдельно.

Можно заменить исходники только одного компонента и поменять его `source` в
`odysseus.json`. `status` показывает версии этих исходников, не установленных
приложений. Для запуска из исходников:

```bash
# В папке CLI: npm ci, npm run build, npm run bundle.
node tools/odysseus.mjs run cli --source --project /absolute/path/to/project

# В папке Desktop: bun install --frozen-lockfile, bun run electron:build.
node tools/odysseus.mjs run desktop --source --project /absolute/path/to/project
```

### Чаты, модели и запуск CLI из Desktop

Личная синхронизация и кнопки доступны в локальной сборке Desktop при запуске через `Запустить Nessy Desktop.command`. CLI запускается через `Запустить Nessy CLI.command`. Совместимые данные обновляются каждые пять секунд; резервные копии и секреты хранятся вне проекта. Подробности, ограничения и порядок раздельного обновления — в [инструкции](docs/personal-sync-ru.md).

Предпросмотр: `npm run sync:personal -- --check`. После замены исходников Desktop: `npm run desktop:integration -- --check`, затем применение без `--check` и пересборка Desktop.

## База знаний проектов и Obsidian

`npm run knowledge:setup` устанавливает Graphify и находит хранилище Obsidian либо создаёт новое. При работе через launcher Odysseus деревья проектов обновляются в фоне; общая карта связывает проекты по зависимостям, одинаковым исходникам и явным ссылкам. Проверка: `npm run knowledge:status`. [Настройка, ограничения и команды](docs/knowledge-obsidian-ru.md).

В Desktop откройте **«База знаний»** для карты или **«Чат с базой знаний»** для работы со встроенным агентом. Ручные записи и связи сохраняются отдельно от автоматического индекса.
