# Code Documentation Generator

Skill для автоматической генерации технической документации по коду микросервисов на Java/Kotlin + Spring Boot.

## Назначение

Этот skill анализирует кодовую базу микросервиса (Java или Kotlin) и генерирует подробную документацию в формате Markdown, включающую:

- Общее описание сервиса
- Архитектуру с диаграммой компонентов
- API endpoint'ы с примерами запросов/ответов
- Алгоритмы работы
- Схему данных (PlantUML)
- Интеграции и зависимости

## Активация

### Через триггерные фразы
- "сгенерируй документацию по коду"
- "опиши архитектуру сервиса"
- "создай документацию API"
- "обнови документацию по микросервису"

### Через команды
```
/ai-doc-generator           # полная документация
/ai-doc-generator --full    # полная документация
/ai-doc-generator --api-only # только API
/ai-doc-generator --architecture # только архитектура
```

## Как это работает

### 1. Анализ проекта

Skill сканирует директорию проекта и находит:

- **Контроллеры** (`@RestController`) — для определения API endpoint'ов (Java/Kotlin)
- **Сервисы** (`@Service`) — для понимания бизнес-логики
- **Репозитории** (`@Repository`, `JpaRepository`) — для схемы данных
- **Entity-классы** (`@Entity`) — для структуры таблиц
- **Конфигурации** (`application.yml`) — для портов и настроек
- **Зависимости** (`pom.xml`, `build.gradle(.kts)`) — для списка библиотек

### 2. Генерация документации

На основе анализа создаётся Markdown-файл со структурой:

```markdown
# Service Name API — Описание

## Краткое описание
## Основные возможности
## Архитектура
### Компоненты сервиса
### Базы данных
## Спецификация
### API Endpoint
#### POST /api/v1/...
## Алгоритм работы
## Схема данных
## Интеграция
### Вызывающие системы
### Зависимости
### Порты
```

### 3. Сохранение результата

Документация сохраняется в папке `ai-docs/` в корне проекта:

```
ai-docs/
├── README.md
├── architecture.md
├── api/<ControllerName>/<methodName>.md
├── jobs/<JobClassName>/<methodName>.md
└── data/schema.md
```

## Пример использования

```
Пользователь: сгенерируй документацию для payment-control-app

Skill:
1. Анализирует структуру проекта...
2. Находит контроллеры: PaymentController
3. Находит сервисы: PayoffBonusService, BonusesUsageService...
4. Находит репозитории: EventRulesRepository, ActionRepository...
5. Находит entity: EventRuleEntity, ActionEntity...
6. Читает конфигурацию: порты 8080, 8081
7. Генерирует документацию...
8. Сохраняет в ai-docs/
```

## Формат выходного файла

Документация следует шаблону из `template.md` и включает:

- **ASCII-диаграммы** для архитектуры
- **PlantUML** для схем данных и последовательности
- **Таблицы** для параметров API
- **Примеры JSON** для запросов/ответов
- **Пошаговые алгоритмы** с визуальными блоками

## Настройка

### Изменение пути сохранения

По умолчанию документация сохраняется в `ai-docs/` в корне проекта.
Для изменения отредактируй `ai/task.md` в разделе "Создание директорий".

### Добавление разделов

Для добавления дополнительных разделов отредактируй `template.md`.

## Best Practices

1. **Перед генерацией**
   - Убедись, что код соответствует naming conventions
   - Проверь, что все классы имеют корректные аннотации Spring

2. **После генерации**
   - Проверь точность описаний
   - Добавь недостающие детали вручную
   - Обнови примеры запросов/ответов

3. **Поддержка актуальности**
   - Перезапускай skill при изменении API
   - Сравнивай документацию с кодом при рефакторинге
   - Веди историю изменений документации

## Ограничения

- Требуется наличие аннотаций Spring для корректного анализа
- PlantUML-диаграммы требуют рендерера для отображения
- Не анализирует динамическую конфигурацию во время выполнения

## Зависимости skill'а

- Доступ к файловой системе проекта
- Возможность чтения Java/Kotlin файлов
- Возможность записи Markdown файлов
