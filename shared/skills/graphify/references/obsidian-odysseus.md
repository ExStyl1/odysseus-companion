# База знаний Odysseus: Graphify и Obsidian

## Когда использовать

Когда нужно понять дерево проекта, найти зависимости и общие части нескольких
проектов, ответить по накопленному контексту или связать проектные знания с Obsidian.
Обычная правка текста без задачи по графу не требует полного разбора всех проектов.

## Где работает интеграция

Корень Odysseus берётся из ODYSSEUS_ROOT либо определяется по odysseus.json.
Команды ниже выполняются из этого корня, пути и текст передаются отдельными
аргументами, без подстановки через eval. Исполняемый движок устанавливается
командой `node tools/graphify.mjs setup` в отдельное окружение .odysseus/graphify.
Нужен Node.js 22+, uv (есть в Desktop) и Python 3.12; uv может установить Python.
Вендорский `graphify install` не нужен: общий навык уже установлен.

## Автоматический выбор Obsidian

Порядок: ODYSSEUS_OBSIDIAN_VAULT → локальный config.json с vault → зарегистрированное
открытое хранилище → самая свежая зарегистрированная папка. Несуществующие пути
пропускаются при автообнаружении; неверный явно заданный путь вызывает ошибку.
Если ничего нет, создаётся workspace/Obsidian с минимальной папкой .obsidian.
Реестры Obsidian читаются, но не переписываются. Выбор виден в doctor и
.odysseus/graphify/vault-selection.json. Файлового формата Obsidian достаточно для
создания заметок; приложение Obsidian нужно для его собственного графического UI.

## Работа с проектом

1. `node tools/graphify.mjs register /path/to/project "Имя проекта"` добавляет проект.
   CLI через штатный launcher регистрирует рабочую папку автоматически; Desktop
   подхватывает папки из сохранённых Projects. При attach проекта регистрация
   выполняется автоматически, если движок установлен.
2. `node tools/graphify.mjs refresh` обновляет графы и Obsidian. Фоновый worker
   запускается вместе с Odysseus и проверяет изменения раз в 30 секунд. Он работает
   отдельно от UI и использует кэш; первый большой разбор может занимать минуты.
3. Для вопросов сначала используй источник MCP Graphify: query_graph, get_node,
   get_neighbors, shortest_path и graph_stats. MCP обслуживает выбранный каталог знаний; другие каталоги не подмешиваются.
   Общая карта содержит дерево папок, файлов и зависимости. Для функций и классов
   сначала найди узел проекта и возьми его graphify_project_path; передавай этот
   путь параметром project_path в инструменты MCP. Подробные графы независимы,
   поэтому крупный проект не требует загрузки всех символов остальных проектов.
4. После значимого этапа зафиксируй полезное для будущей работы решение и ссылки
   на файлы/задачи командой `node tools/graphify.mjs record /path/to/project "Текст решения и источник"`.
   Записывай устойчивые факты и принятые решения, а не весь разговор. Гипотезы
   называй гипотезами. Сохранённая запись подтверждает, что решение записано,
   но сама по себе не доказывает истинность его содержания.

## Как читать связи

- Внутри проекта: папки, файлы и символы из локального AST Graphify. Сохраняй
  исходные уровни EXTRACTED/INFERRED; не превращай вывод парсера в доказанный факт.
- Между проектами: явные зависимости package.json, общий стек npm, идентичные
  исходники по SHA-256 и прямые ссылки на файлы/пути другого проекта в документах.
  Общая библиотека означает общий стек, а не вызов одного приложения из другого.
- Одинаковые имена функций в разных проектах имеют разные идентификаторы.
  Если один пакет определён в нескольких проектах, совпадения имени недостаточно
  для прямой зависимости на один из них.
- Уточняй источник каждого вывода (source_file, source_line/source_location).
  При stale/pending используй снимок как сохранённый контекст и сообщай его состояние.
  Семантические связи, не подтверждённые кодом или документом, проверяй текущим
  агентом по источникам; фоновый процесс не вызывает внешние AI API.

## Результаты

.odysseus/graphify/knowledge/projects хранит отдельные графы, решения и до 20
предыдущих снимков на проект. Общий graph.json обслуживает MCP. В Obsidian:
Graphify/Обзор.md, Graphify/Карта.canvas, Graphify/Проекты.md, Graphify/Проекты.canvas
и заметки проектов. Canvas проектов показывает до 100 общих промежуточных элементов;
полный граф доступен через MCP. Исходные заметки не меняются; если пользователь
отредактировал созданный отчёт, экспорт останавливается с сообщением и сохраняет
его правки. Перед заменой сгенерированного файла предыдущая версия сохраняется
в previous-export рядом с графом.

## Редактирование общей карты

В Desktop раздел «База знаний» показывает общую карту, а «Чат с базой знаний» открывает сохранённого агента. Для ручных записей используй `node tools/knowledge-ui.mjs snapshot` и `edit` с отдельным JSON-аргументом. Операции: add-note (label,description), add-link (source,target,relation,evidence), update-manual (id,label/description/relation), remove-manual (id). Находи точные id в графе, указывай основание. Ручные связи имеют USER_RECORDED и хранятся в overlay.json; автоматическая индексация их не стирает. Автосвязи исправляй в исходниках. graph.json напрямую не редактируй.

## Каталоги знаний и отдельный контекст

Уточни текущий каталог знаний до запросов и изменений. «Мои проекты» исключает исходники самого Odysseus. Каталог «Odysseus» содержит CLI, Desktop и демонстрационную папку. Для разных каталогов Desktop открывает разные чаты и MCP-источники. Не переноси контекст между каталогами без прямой просьбы пользователя. В snapshot/edit передавай JSON-поле collection с id выбранного каталога. Каталоги создаются и проекты перемещаются через UI «Управление каталогами»; назначение не меняет исходные папки проекта. Для отдельного MCP: graphify.mjs serve --collection ID. CLI launcher выбирает каталог своей рабочей папки.
