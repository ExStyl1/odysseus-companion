# Time to Jira

Скилл для автоматического создания задач в Jira на основе обсуждения в Time messenger.

## Когда использовать

**Обязательно применяй этот скилл когда:**
- Пользователь присылает ссылку на тред в Time (например, `https://time.tbank.ru/tinkoff/pl/abc123`)
- Пользователь просит "создай задачу по этому треду", "заведи баг из обсуждения"
- Нужно превратить обсуждение в чате в структурированную Jira-задачу
- Пользователь хочет задокументировать проблему из переписки

**Не используй этот скилл для:**
- Создания задач без ссылки на тред (нет контекста для анализа)
- Обновления существующих задач (для этого `dp jira update`)
- Поиска задач в Jira (для этого `dp jira jql-search`)

## Рабочий процесс

### Шаг 1: Извлечение ID треда из ссылки

Ссылка на тред имеет формат: `https://time.tbank.ru/tinkoff/pl/{root_id}`

Извлеки `root_id` из URL. Пример:
- Ссылка: `https://time.tbank.ru/tinkoff/pl/abc123def456`
- `root_id`: `abc123def456`

### Шаг 2: Получение треда из Time API

**Вариант A: Прямой HTTP запрос (рекомендуется)**

Используй MCP `mcp__rtd__dp_runtime-diagnostic_request` или `run_shell_command` с curl:

```bash
curl -H "Authorization: Bearer <token>" \
  "https://api-time.tinkoff.ru/api/v4/posts/{root_id}/thread"
```

**Вариант B: Через канал**

Если прямой запрос недоступен, спроси у пользователя:
```
В каком канале находится тред? (например, ~ins-sre-support)
```

Затем используй MCP `time_mcp__read_channel`:
```
peer: ~channel-name
limit: 50
include_reactions: false
```

Отфильтруй сообщения по `root_id`.

> **Важно:** Time MCP не поддерживает чтение тредов напрямую по root_id. Если ни один вариант не работает — попроси пользователя скопировать текст обсуждения из треда.

### Шаг 3: Подготовка контекста для LLM

Собери сообщения в единый текст, отсортированный по времени:

```
[Сообщение 1 от user1]: текст сообщения
---
[Сообщение 2 от user2]: текст сообщения
---
...
```

Отфильтруй:
- Пустые сообщения
- Сообщения от ботов (если они не несут контекста)
- Служебные сообщения (реакции, системные)

### Шаг 4: Анализ через LLM

Передай контекст LLM с системным промптом:

```
Ты - ассистент для заведения задач в Jira. Твоя задача: из данного тебе диалога понять, в чем проблема, и описать её.

ВАЖНО! Ответ должен быть в формате JSON (без форматирования) и строго соответствовать шаблону:
{
  "title": "Заголовок задачи",
  "description": "Общее описание проблемы",
  "as_is": "Шаги воспроизведения",
  "to_be": "Как должно быть",
  "workaround": "Есть ли обходной путь (если есть то какой)",
  "mass": "Массовость проблемы (кол-во запросов, ошибок и т.д)",
  "first_appearance": "Дата появления ошибки на проде"
}

Если входных данных для заполнения какого-либо поля не достаточно - поставь прочерк ("-"), все поля обязательные!
```

### Шаг 5: Валидация JSON

Проверь, что LLM вернул валидный JSON со всеми полями:
- Все 7 полей присутствуют
- Поля не пустые (допускается "-" если данных нет)
- JSON парсится без ошибок

Если валидация не прошла — попроси LLM исправить.

### Шаг 5: Уточнение проекта

**Перед созданием задачи обязательно спроси пользователя:**

```
В каком проекте создать задачу?
- INSSRE (по умолчанию) — инфраструктура, мониторинг, SRE
- TIGD — Guidewire, полисы, биллинг
- TICA — Claims API
- Другой проект (укажите ключ)
```

Если пользователь не указал проект — используй **INSSRE** по умолчанию.

### Шаг 6: Создание задачи в Jira

Используй MCP `dp_jira__dp_jira_create` с параметрами:

```
project-key: {INSSRE по умолчанию или указанный пользователем}
issue-type: Bug
summary: {title из JSON}
description: {форматированное описание}
labels: time-auto,bug-hunter
```

**Форматирование описания для Jira** (Jira wiki markup, не Markdown!):

```
{panel:title=Общее описание проблемы|titleBGColor=#f29b27}
{description}
{panel}

{panel:title=Шаги воспроизведения|titleBGColor=#f29b27}
{as_is}
{panel}

{panel:title=Как должно быть|titleBGColor=#f29b27}
{to_be}
{panel}

{panel:title=Есть ли обходной путь|titleBGColor=#f29b27}
{workaround}
{panel}

{panel:title=Дата появления ошибки на проде|titleBGColor=#9cbb5d}
{first_appearance}
{panel}

{panel:title=Массовость|titleBGColor=#9cbb5d}
{mass}
{panel}

{panel:title=Дополнительная информация|titleBGColor=#add8e6}
Тред: {ссылка на тред}
{panel}
```

### Шаг 7: Обновление пользователя

После успешного создания задачи:

1. Верни пользователю ссылку на задачу: `https://jira.tcsbank.ru/browse/{key}`
2. Кратко опиши, что было сделано:
   - Проанализировано сообщений: N
   - Создана задача: {key}
   - Заголовок: {title}

## Чек-лист создания задачи

**Перед созданием задачи:**
- [ ] Ссылка на тред извлечена (root_id из URL)
- [ ] Тред получен (через API или от пользователя)
- [ ] LLM вернул валидный JSON со всеми 7 полями
- [ ] Проект уточнён у пользователя (INSSRE по умолчанию)
- [ ] Тип задачи определён (Bug по умолчанию)

**Валидация JSON от LLM:**
- [ ] Все поля присутствуют: title, description, as_is, to_be, workaround, mass, first_appearance
- [ ] Поля не пустые (допускается "-" если данных нет)
- [ ] JSON парсится без ошибок

**Форматирование описания:**
- [ ] Использован Jira wiki markup (не Markdown!)
- [ ] {panel} блоки для каждого раздела
- [ ] Ссылка на тред добавлена в "Дополнительная информация"
- [ ] Labels: time-auto, bug-hunter

**После создания:**
- [ ] Задача создана (получен key из Jira)
- [ ] Ссылка возвращена пользователю
- [ ] Краткое резюме предоставлено

## Выходной формат

Всегда предоставляй результат в этом порядке:

1. **Краткое резюме** — что было сделано
2. **Ссылка на задачу** — кликабельная ссылка
3. **Детали** — заголовок, проект, тип задачи
4. **Исходный тред** — ссылка для контекста

## Типы задач

| Тип | Когда использовать |
|-----|-------------------|
| **Bug** | Проблема, ошибка, дефект (по умолчанию) |
| **Task** | Работа по улучшению, не связанная с багом |
| **Story** | Функциональность для пользователя |

По умолчанию создавай **Bug**, если пользователь не указал иное.

## Проекты Jira

| Проект | Ключ | Когда использовать |
|--------|------|-------------------|
| **SRE** | INSSRE | Инфраструктура, мониторинг (по умолчанию) |
| **TI: GW development** | TIGD | Guidewire, полисы, биллинг |
| **TICA** | TICA | Claims API |

**По умолчанию используй INSSRE**, если пользователь не указал иной проект.

## Типичные ошибки

| Ошибка | Проблема | Исправление |
|--------|----------|-------------|
| Markdown в описании | Jira не рендерит | Используй Jira wiki markup (`{panel}`, `*bold*`) |
| Нет ссылки на тред | Потеря контекста | Всегда добавляй ссылку в "Дополнительная информация" |
| Пустые поля | LLM не заполнил | Проверяй валидацию, запрашивай исправление |
| Неправильный проект | Задача не там | Уточняй проект у пользователя |
