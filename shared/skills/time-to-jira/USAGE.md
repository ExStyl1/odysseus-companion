## Быстрый старт

```
Пользователь: Создай задачу по этому треду: https://time.tbank.ru/tinkoff/pl/abc123
Nessy: [Анализирует тред] → [Создаёт задачу в Jira] → Возвращает ссылку
```

## Примеры использования

### Пример 1: Стандартное создание задачи

**Вход:**
```
Создай задачу по этому треду: https://time.tbank.ru/tinkoff/pl/XyZ123AbC
```

**Процесс:**
1. Извлечение `root_id = XyZ123AbC`
2. Получение треда через Time MCP
3. Анализ диалога через LLM
4. **Уточнение проекта** (по умолчанию INSSRE)
5. Создание задачи в Jira (проект INSSRE, тип Bug)

**Выход:**
```
✅ Задача создана!

📋 **INSSRE-123** — Ошибка расчёта премии при продлении полиса ОСАГО

📎 Ссылка: https://jira.tcsbank.ru/browse/INSSRE-123
📝 Проанализировано сообщений: 8
🔗 Исходный тред: https://time.tbank.ru/tinkoff/pl/XyZ123AbC
```

### Пример 2: Задача с явным указанием проекта

**Вход:**
```
Заведи баг в проект TIGD: https://time.tbank.ru/tinkoff/pl/monitoring-alert
```

**Выход:**
```
✅ Задача создана!

📋 **TIGD-456** — Ошибка при расчёте КМ бонуса

📎 Ссылка: https://jira.tcsbank.ru/browse/TIGD-456
📝 Проанализировано сообщений: 12
🔗 Исходный тред: https://time.tbank.ru/tinkoff/pl/monitoring-alert
```

### Пример 3: Недостаточно данных в треде

**Вход:**
```
Создай задачу: https://time.tbank.ru/tinkoff/pl/short-thread
```

**Выход:**
```
✅ Задача создана!

📋 **TIGD-12346** — Проблема с API

⚠️ Некоторые поля заполнены прочерком (недостаточно данных в треде):
- first_appearance: -
- mass: -

📎 Ссылка: https://jira.tcsbank.ru/browse/TIGD-12346
```

## Форматы ссылок Time

Поддерживаемые форматы:

| Формат | Пример | root_id |
|--------|--------|---------|
| Стандартный | `https://time.tbank.ru/tinkoff/pl/abc123` | `abc123` |
| С якорем | `https://time.tbank.ru/tinkoff/pl/abc123#message-xyz` | `abc123` |
| Короткий | `time.tbank.ru/pl/abc123` | `abc123` |

## Поля Jira

### Заполняемые поля

| Поле | Описание | Источник |
|------|----------|----------|
| **title** | Заголовок задачи | Извлекается LLM из диалога |
| **description** | Общее описание проблемы | Саммаризация диалога |
| **as_is** | Шаги воспроизведения | Если описаны в треде |
| **to_be** | Ожидаемое поведение | Если описано в треде |
| **workaround** | Обходной путь | Если предложен в треде |
| **mass** | Массовость (кол-во ошибок, запросов) | Если упомянута в треде |
| **first_appearance** | Дата появления на проде | Если известна из треда |

### Форматирование описания

Описание в Jira использует **Jira wiki markup**:

```jira
{panel:title=Общее описание проблемы|titleBGColor=#f29b27}
Текст описания проблемы
{panel}

{panel:title=Шаги воспроизведения|titleBGColor=#f29b27}
1. Шаг 1
2. Шаг 2
{panel}
```

**Не используй Markdown** (`##`, `**bold**`, ```code```) — Jira его не рендерит!

## Edge Cases

### 1. Тред не найден

Если Time MCP возвращает ошибку:

```
❌ Не удалось получить тред

Возможные причины:
- Ссылка невалидна
- У вас нет доступа к этому треду
- Тред был удалён

Проверьте ссылку и попробуйте снова.
```

### 2. LLM не вернул валидный JSON

Если анализ не удался:

```
⚠️ Не удалось распарсить ответ LLM

Попытка повторного анализа...
[Повторный запрос]
```

После 3 неудач — запроси у пользователя ручное заполнение полей.

### 3. Пустой тред

Если в треде нет сообщений:

```
⚠️ Тред пуст или не содержит сообщений

Невозможно создать задачу без контекста.
Убедитесь, что в треде есть обсуждение проблемы.
```

### 4. Пользователь без прав в Jira

Если создание задачи не удалось:

```
❌ Ошибка создания задачи в Jira

Возможно, у вас нет прав на создание задач в проекте TIGD.
Обратитесь к владельцу проекта для предоставления доступа.
```

## Кастомизация

### Изменение проекта по умолчанию

В SKILL.md измени секцию "Проекты Jira":

```markdown
По умолчанию используй **INSRE**, если пользователь не указал иной проект.
```

### Добавление custom fields

Для добавления кастомных полей используй MCP `dp_jira__dp_jira_create` с параметром `custom-field`:

```
custom-field: customfield_162600=Все продукты
```

### Изменение типа задачи по умолчанию

По умолчанию создаётся **Bug**. Для изменения:

```markdown
По умолчанию создавай **Task**, если пользователь не указал иное.
```

## Интеграция с другими скиллами

### sage-metrics-analyst

Если в треде обсуждаются метрики Sage:

1. Сначала используй `sage-metrics-analyst` для анализа метрик
2. Затем `time-to-jira` для создания задачи с результатами анализа

### alert-investigator

Если в треде обсуждается алерт:

1. Используй `alert-investigator` для расследования
2. Затем `time-to-jira` для заведения задачи по итогам

## Troubleshooting

### Проблема: Time MCP не возвращает тред

**Причина:** Time MCP не поддерживает чтение тредов напрямую по root_id.

**Решение 1: Прямой HTTP запрос**

Используй curl с токеном DevPlatform:

```bash
curl -H "Authorization: Bearer $(dp auth print-token)" \
  "https://api-time.tinkoff.ru/api/v4/posts/{root_id}/thread"
```

**Решение 2: Указать канал**

Спроси пользователя, в каком канале находится тред, и прочитай канал:
```
В каком канале находится тред? (например, ~ins-sre-support)
```

**Решение 3: Ручное копирование**

Если тред недоступен, попроси пользователя скопировать текст обсуждения:
```
К сожалению, не удалось получить тред автоматически.
Пожалуйста, скопируйте основные сообщения из обсуждения:
- Описание проблемы
- Шаги воспроизведения
- Ожидаемое поведение
```

### Проблема: Задача создаётся не в тот проект

**Решение:** Явно указывай проект в запросе:
```
Создай задачу в проект TIGD по треду: ...
```

### Проблема: Поля заполнены прочерками

**Решение:** Это ожидаемое поведение если данных нет. Для улучшения:
- Попроси пользователя дополнить тред информацией
- Добавь ручное заполнение после анализа LLM
